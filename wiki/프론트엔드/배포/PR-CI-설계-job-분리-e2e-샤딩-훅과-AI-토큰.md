# PR CI 설계 — job 분리, e2e 샤딩, 로컬 훅과 AI 토큰

Cloudflare 빌드만 있고 머지를 막는 검사가 없는 저장소에 CI를 처음 넣을 때의 설계 판단 모음. 핵심은 (1) 지금 통과하는 검사와 아직 못 켜는 검사를 job으로 분리하고, (2) 무거운 e2e는 샤딩하며, (3) AI 에이전트가 커밋·푸시하는 환경에서는 로컬 훅이 토큰을 먹으므로 훅은 빠르고 조용한 것만 둔다는 것. 적용 사례는 [[ToyVillage-Admin-FE/하네스-점검-결과와-개선-방향]].

## GitHub Actions 용어
- **workflow** = `.github/workflows/*.yml` 파일 하나(지시서). **job** = 안의 작업 단위로, job마다 **깨끗한 새 러너(컴퓨터 1대)**를 빌린다. **step** = job 안에서 순서대로 실행되는 명령.
- job끼리는 기본 **동시 실행**, job마다 체크아웃·`yarn install`을 처음부터 다시 한다. 순서가 필요하면 `needs: verify`. PR 검사 목록에 job이 한 줄씩 뜨고 **그 줄 단위로 필수 검사를 지정**한다.

## job을 합치지 않고 나누는 이유
- e2e가 아직 실패 중이면 같은 job의 lint·타입 검사까지 빨간불이라 **필수 검사로 지정할 수 없다**(지금 통과하는 1단계가 e2e 정리에 묶임).
- 한 job(러너 1대)에서는 **샤딩이 불가**하다. `strategy.matrix: shard: [1,2,3,4]` + `npx playwright test --shard=N/4 --workers=4`로 4대에 나눠야 한다.
- 실패 지점이 PR 목록에서 "verify ✅ / e2e ❌"로 바로 구분된다. 합쳐서 얻는 건 설치 1회뿐인데 공개 저장소라 비용이 없고 job당 1분 이내.
- `e2e: needs: verify`는 lint·타입 오류 PR에 e2e를 돌리는 낭비를 막지만 총 시간이 약 1분 늘어난다(시간이 중요하면 `needs` 생략).
- 빌드를 Cloudflare Workers Builds가 이미 PR마다 하면 verify에서 빼도 된다(개별 측정: lint 14.1s·typecheck 4.6s·style-policy 0.3s·build 5.5s라 절감은 5초 정도). **조건: Workers Builds를 필수 검사로 지정**해야 빌드 깨진 PR이 막힌다. **typecheck는 남기는 편이 좋다** — Cloudflare 실패 로그는 대시보드에 있어 계정 없는 팀원은 원인을 못 본다. 단 `yarn verify` 스크립트에는 빌드가 들어 있으니 공지할 때 스크립트 이름 대신 실제 명령을 적어야 오해가 없다.

## e2e 시간: 로컬 14분 → CI에서는 오히려 더 걸린다
- 로컬 8코어에서 Playwright 워커 4개로 14분. **GitHub 러너는 4코어라 기본 워커가 2개**여서 설정 없이 올리면 약 28분(추정).
- 샤딩 4개 × 워커 4개면 테스트 3~4분 + 설치·브라우저 준비 1~2분 ≈ **5분**(추정, 첫 CI 실행에서 확인 필요). 실패 테스트가 30초 타임아웃을 각각 기다리는 시간도 고치면 줄어든다.
- PR에서 e2e를 빼고 머지 후·야간에만 돌리는 대안은 PR이 빨라지지만 깨진 걸 머지한 뒤에야 알게 되어 4주 방치형 드리프트를 못 막는다(→ [[Playwright-e2e-실패-유형-분류와-취약-선택자-패턴]]).
- **e2e는 Cloudflare preview URL이 아니라 CI 안에서 띄운 서버에 돌린다.** preview는 실제 스테이징 API에 붙는 빌드라 mock에서 빠진 요청이 실서버로 나간다([[Playwright-mock-오리진-미검증]], [[Playwright-reuseExistingServer-실서버-유출]]). preview는 사람이 눈으로 확인하는 용도.

## 비용과 "토큰"은 두 가지로 나뉜다
- **AI 토큰**: CI는 GitHub 서버가 명령만 실행하고 AI가 출력을 읽지 않으므로 0. AI 단계(자동 PR 리뷰 job 등)를 넣을 때만 API 비용이 생긴다. 비밀값(Secrets)도 불필요할 수 있다 — e2e는 가짜 서버 주소(`api.e2e.invalid`)+mock이라 로그인 정보가 필요 없고, Sentry 소스맵 업로드는 `SENTRY_AUTH_TOKEN`이 없으면 건너뛰게 되어 있으며 `GITHUB_TOKEN`은 자동 제공.
- **Actions 사용량**: 공개 저장소는 기본 러너 무료·무제한, 무료 조직은 동시 job 20개. **비공개로 바뀌면** 무료 한도는 월 2,000분이라 (PR 85개 × 푸시 3회 × (e2e 4×5분 + 기타 2분)) ≈ 월 5,600분으로 초과 → 그때는 e2e를 "리뷰 요청 전환 시"나 "머지 후"로 조건을 건다.

## 로컬 훅(husky 등)과 AI 토큰
- AI 에이전트가 `git commit`/`git push`를 실행하면 **훅 출력이 전부 모델 입력으로 들어가 커밋마다 토큰이 든다**. 실패하면 읽고 고치고 재커밋하는 비용이 더 든다. 오래 걸리는 훅은 명령 시간 상한(최대 10분)에 걸려 푸시가 끊기고 세션이 멈춘다(e2e 14분을 pre-push에 넣으면 불가).
- 기준: **빠르고 조용한 검사는 훅, 무거운 검사는 CI.** 훅은 `--no-verify`로 우회 가능하므로 마지막 방어선은 CI. 통과 시 출력이 없게 만들고(성공 출력 억제, 폐기 경고는 근본 제거), AI가 `--no-verify`로 건너뛰지 못하게 팀 규칙·설정으로 금지한다.
- **PR 머지 커밋 방식(`Merge pull request #N`)이면 개별 커밋이 그대로 develop에 남는다.** 그래서 커밋 메시지 형식 오류를 PR CI에서 발견하면 고치려면 강제 푸시(팀 규칙 위반)가 필요 → **커밋 메시지 형식만 commit-msg 훅**으로 두고, PR 제목은 푸시 없이 GitHub에서 고칠 수 있으니 CI에서 검사한다.
- 훅 구현 선택지: husky 대신 저장소에 `.githooks/commit-msg`를 두고 `git config core.hooksPath .githooks`(의존성 1개 감소). husky를 쓰면 Yarn 4에서는 `prepare`가 아니라 `postinstall`로 연결해야 하고 동료 PC에도 훅이 걸리니 공지 필요.
- 커밋 본문을 금지하면 Claude가 기본으로 붙이는 `Co-Authored-By` 줄도 걸리므로 형식 합의 시 허용 여부를 같이 정한다. "명사형으로 끝나기" 같은 규칙은 기계 판정이 어려워 검사에서 뺀다.

## CI에 넣지 않는 것의 기준
- 포맷 검사(Prettier)를 강제하면 해시 기반 승인 파일을 건드려 전부 재승인이 필요한 저장소에서는 해시 방식을 바꾼 뒤로 미룬다.
- 상태가 외부 서버에 좌우되는 실서버 API 테스트, 이미 일정 비율이 깨진 검사를 전체 범위로 켜는 것(켜는 순간 모든 PR 실패) → **PR에서 바뀐 범위만 검사**하도록 줄인다.
- 브랜치 보호: 필수 상태 검사가 0개면 PR이 있어도 아무것도 막지 않는다. 관리자 우회를 막을지는 팀 규칙("PR 없는 머지 금지")과 엮인 합의 사항.
