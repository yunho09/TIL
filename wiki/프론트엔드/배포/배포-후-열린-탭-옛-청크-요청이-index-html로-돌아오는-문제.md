# 배포 후 열린 탭의 옛 청크 요청이 `index.html`로 돌아오는 문제

화면별 코드 스플리팅을 하면 "배포 전에 열어 둔 탭에서 아직 안 연 화면을 처음 누르는" 순간 옛 해시의 청크 파일을 요청하는데, 새 배포에는 그 파일이 없다. Cloudflare Workers의 SPA fallback이 404 대신 `index.html`(200 `text/html`)을 돌려줘서 동적 `import()`가 실패하고 에러 화면이 뜬다. `vite:preloadError`에서 한 번 새로고침하는 게 표준 대응이지만, 이 프로젝트에서는 2026-10-28 기준 **미구현**이다.

## 왜 생기나
- 빌드하면 JS 파일명 뒤에 내용 해시가 붙는다(`TaskListPage-abc123.js`). 내용이 바뀌면 해시도 바뀐다 → 해시 캐시 원리는 [[Vite-청크-그룹으로-라이브러리-분리와-해시-캐시]].
- 화면 46개가 각각 청크라서 메뉴를 **처음 누를 때** 그 청크를 받는다(`lazyPage()` = `React.lazy` + `Suspense`).

발생 순서:
1. 관리자가 아침에 어드민을 열어 둔다. 이 탭의 JS는 "업무 목록 청크는 `abc123`"이라고 알고 있다.
2. 점심에 새 버전이 배포된다. 새 빌드에서는 `TaskListPage-def456.js`가 되고, Cloudflare에는 새 배포의 파일만 있다.
3. 열어 둔 탭에서 업무 목록을 처음 누르면 `abc123`을 요청한다 → 없는 파일.
4. `wrangler.jsonc`의 `not_found_handling: "single-page-application"`(주소로 바로 들어와도 화면이 뜨게 하는 설정, [[Cloudflare-Workers-SPA-fallback-404]]) 때문에 404가 아니라 **`index.html` 200 `text/html`**이 온다. 스테이징에서 존재하지 않는 `/assets/TaskListPage-OLDHASH.js`를 요청해 직접 확인.
5. 브라우저는 JS를 기대했는데 HTML이 와서 모듈 로드 실패 → 라우터 `errorElement`(`RouteErrorPage`)가 "화면을 불러오지 못했습니다"를 띄우고 `Sentry.captureException`으로 에러가 기록된다.

## 범위
- **이미 한 번 연 화면은 괜찮다**(브라우저가 받은 청크를 재사용). 아직 안 연 화면만 실패.
- 스플리팅 전에는 없던 문제(처음에 JS 한 파일에 전부 들어 있었다). **첫 main 배포는 안전** — 당시 main은 분할 전 버전이라 한 파일. 문제는 분할 버전이 올라간 뒤의 **두 번째 배포부터 매번**.
- 에러 화면의 "홈으로 이동"(`reloadDocument`)을 누르면 풀리지만 사용자가 직접 복구해야 하고 보던 위치를 잃는다.

## 고치는 방법: 한 번만 새로고침
Vite는 동적 import의 프리로드 헬퍼(`__vitePreload`)에서 실패하면 취소 가능한 `vite:preloadError` 이벤트를 `window`에 낸다. **화면 청크 자체를 못 받을 때도 이 이벤트가 난다는 걸 Vite 8.1.3 코드와 실제 빌드 결과(헬퍼가 `react-*.js` 청크에 포함)로 확인.** 이 신호(또는 `lazyPage`의 실패 처리)에서 새로고침하면 새 `index.html`을 받아 새 청크 이름을 알게 되고, 주소는 이미 누른 화면이라 그 화면이 바로 뜬다(사용자에겐 화면이 한 번 깜빡임).

안전장치:

| 경우 | 처리 |
|---|---|
| 방금(예: 10초 안) 새로고침했는데 또 실패 | 재새로고침하지 않고 에러 화면 + Sentry 기록(진짜 문제라 남겨야 함) → 무한 새로고침 방지 |
| 오프라인 | 새로고침 안 함(하면 브라우저 오프라인 화면이 떠서 더 나쁨) |
| 새로고침으로 해결된 경우 | Sentry로 에러를 보내지 않음 |
| 세션 녹화(replay) 청크 실패 | 대상에서 제외 — `initSentry.ts`의 `loadReplay()`가 이미 `.catch`로 조용히 넘김 |

테스트: e2e에서 화면 청크 요청에 일부러 HTML을 돌려줘 ① 새로고침 뒤 화면이 뜨는지 ② 두 번째도 실패하면 에러 화면이 뜨는지 확인. 규모는 코드 20~30줄 + e2e 2개(반나절).

## 도입 시점의 함정
새로고침 처리는 **열려 있는 탭 안의 JS**가 실행한다. 그래서 이 처리가 들어간 버전을 배포해도, 그 배포 **전에** 열려 있던 탭은 옛 코드라 보호받지 못한다.
- 첫 main 배포에 포함하면 한 번도 안 생긴다.
- main 먼저 배포하고 다음 배포에 포함하면 그 다음 배포 때 **한 번**(그때 열려 있던 탭만) 생기고 이후엔 없다.

## 정정 기록
처음에 "이 에러가 Sentry 8일 측정값에 섞인다"고 판단했으나 틀렸다. 측정 대상 3개(강제 로그아웃·버튼 라벨·응답 형식 오류)는 각각 따로 세는 항목이라 청크 로드 에러가 생겨도 그 숫자는 안 변하고, Sentry에 별도 에러 하나로 보일 뿐이다. 남는 이유는 관리자 화면 불편 하나 → 급하지 않다는 결론. 그래서 이슈는 만들지 않고, main PR(#270) 본문에 리뷰어 주의로만 남겼다.
