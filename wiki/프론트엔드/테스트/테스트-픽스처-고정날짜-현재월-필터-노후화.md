화면이 "이번 달" 데이터만 필터링해 보여주는 구조일 때, e2e 테스트 픽스처에 특정 연·월을 고정값으로 박아두면 작성 시점엔 통과하지만 **실제 달력의 달이 바뀌는 순간부터 아무도 코드를 건드리지 않아도 자동으로 실패**하기 시작한다.

## 증상

- 목록/카드가 렌더되길 기다리는 요소 대기(`getByRole` 등)가 항상 타임아웃으로 죽는다.
- 진입 단계에서 멈추므로 그 뒤로 이어지는 수정·삭제 등 후속 플로우 테스트도 전부 실패한다.
- `git stash`로 최근 변경을 통째로 치워도 동일하게 실패한다 — 범인은 코드 변경이 아니라는 뜻.

## 원인

화면이 다음과 같은 구조일 때 발생한다.

```tsx
const [month, setMonth] = useState(() => startOfMonth(new Date()))   // 항상 "오늘"
const monthSchedules = useMemo(() => filterSchedulesByMonth(schedules, month), ...)
```

테스트 픽스처는 작성 당시의 "이번 달" 날짜를 그대로 하드코딩한다(예: 7월에 작성하며 `2026-07-28`). 시간이 흘러 실제 오늘이 다른 달이 되면 화면의 월 필터가 그 픽스처를 걸러내 카드 자체가 렌더되지 않는다.

## 판별법

1. 픽스처의 날짜와 오늘 날짜가 다른 달/연도인지 먼저 확인한다.
2. 해당 스펙의 마지막 관련 커밋 날짜를 확인한다 — 그 시점엔 "이번 달"이 픽스처와 일치해 통과했을 가능성이 높다.
3. 픽스처 날짜만 바꾼 임시 probe로 같은 응답을 재현해, 날짜가 현재 달일 때만 카드가 그려지는지 실측 확인한다.

## 해결책

1. **픽스처를 상대 날짜로**: 하드코딩된 날짜 대신 `오늘 기준 이번 달 N일`처럼 테스트 실행 시점에 계산해 넣는다. 화면 코드는 건드리지 않는다. (테스트가 승인·동결(freeze) 워크플로에 묶여 있다면 수정 후 재승인·재동결이 필요하다.)
2. **화면에 기준일 주입점 추가**: 컴포넌트에 `today` prop처럼 테스트가 기준 날짜를 주입할 수 있는 지점을 둔다. 프로덕션 코드를 테스트 때문에 바꾸는 것이라 1번보다 무겁다.

1번이 화면 변경이 없어 더 가볍다.
