# Vite dev서버 프록시로 오리진 고정 CORS 우회

스테이징/백엔드 서버가 API 요청을 특정 오리진(예: `http://localhost:5173`)에서 온 것만 허용하도록 고정해 둔 상태에서, 그 포트를 이미 다른 프로젝트·브랜치의 dev 서버가 점유하고 있어 부득이하게 다른 포트로 dev 서버를 띄우면 브라우저 요청이 CORS로 막힌다(403). 사람이 브라우저로 직접 로그인해 육안 확인해야 하는 상황처럼 "허용된 포트로 옮기기"가 애초에 안 통할 때, Vite dev 서버의 `server.proxy`로 API 요청을 dev 서버가 대신 전달하게 하면 우회할 수 있다.

## 원리

- CORS는 **브라우저가** cross-origin 요청에 거는 정책이다. dev 서버 프록시를 쓰면 브라우저는 자기 자신(dev 서버 오리진)에만 요청을 보내므로 브라우저 쪽에서는 CORS 검사 자체가 발동하지 않는다.
- 실제 백엔드로의 요청은 dev 서버(Node 프로세스)가 서버 대 서버로 전달한다 — 이건 브라우저가 보내는 요청이 아니므로 CORS 정책이 적용되지 않고, 백엔드 입장에선 그냥 dev 서버가 보낸 요청으로 보인다.

## 적용 시 주의

- 확인용 임시 설정이라면 `vite.config.ts`(커밋 대상)에 바로 넣지 말고 git이 무시하는 위치(예: `node_modules/.cache/*.mjs`)에 분리해 둔다 — 확인이 끝나면 지우면 되고, 실수로 커밋에 섞이지 않는다.
- 확인이 끝나면 임시 프록시 설정과 그걸로 띄운 dev 서버 프로세스를 정리한다.
- 같은 서버 접속 문제라도 원인이 다르면 해법도 다르다 — Playwright 등 자동화 테스트가 실제 서버로 요청을 새는 문제는 baseURL/포트 격리로 푸는 게 맞고([[Playwright-reuseExistingServer-실서버-유출]]), 이 프록시 기법은 "허용된 포트 자체를 쓸 수 없는 사람의 수동 브라우저 확인" 상황에 쓴다.
