삭제 API가 **204 No Content**(본문 없음)로 응답하는데 프론트가 `response.json()`을 무조건 부르면 빈 본문 파싱에서 예외가 나, 서버에선 실제로 지워졌는데 화면에는 "삭제 실패"가 뜬다. 상태 코드와 빈 본문을 먼저 분기하면 해결된다.

## 증상과 원인 (xquare-infra-frontend-v3 애드온 삭제 사례)
- 애드온 삭제 API가 `204`로 응답한다.
- 코드가 `response.json()`을 무조건 호출 → 빈 본문 파싱 예외 → catch에서 실패 처리.
- 결과: **실제 삭제는 성공했는데 실패 알림**이 뜬다.

## 해결
- 상태가 `204`면 **본문을 읽지 않고 바로 성공** 처리한다.
- 그 외 응답도 본문을 먼저 `text()`로 읽고, **비어 있으면 성공**, 내용이 있을 때만 `JSON.parse`한다.

## 같은 원인을 다른 곳에서 찾기
- 같은 저장소의 팀원 삭제(`deleteMember.ts`)는 당시에도 `response.json()`을 무조건 호출하고 있었다. 이 API도 204를 주면 같은 버그가 나므로, 하나를 고칠 때 **본문 없는 응답을 주는 다른 삭제/수정 API 호출부**도 함께 점검한다. (확인·수정 여부는 세션에서 미확정)
