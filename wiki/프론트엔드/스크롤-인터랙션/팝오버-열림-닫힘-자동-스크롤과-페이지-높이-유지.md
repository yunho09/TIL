# 팝오버 열림·닫힘 자동 스크롤과 페이지 높이 유지

페이지 아래쪽에서 열리는 달력 팝오버가 화면 밖으로 잘릴 때 모자란 만큼만 부드럽게 스크롤하고, 닫을 때는 열기 전 위치로 부드럽게 되돌리는 패턴. 핵심 함정은 닫는 순간 팝오버가 DOM에서 빠지며 문서가 짧아져 브라우저가 스크롤을 한 번에 끌어올리는 것이고, 돌아가는 동안만 문서 `min-height`를 붙잡아 해결한다. (ToyVillage-Admin-FE 엑셀 다운로드 달력, #272/PR #275)

## 열 때: 모자란 만큼만 내려가기
- 팝오버 패널 ref에 `scrollIntoView({ block: 'nearest', behavior })`. 이미 다 보이면 움직이지 않고, 잘릴 때만 모자란 만큼 이동한다.
- 의존성은 `[variant, cells.length]` — 처음 열 때와 달을 넘겨 줄 수가 5주↔6주로 바뀔 때만 재실행.
- `behavior`는 `matchMedia('(prefers-reduced-motion: reduce)').matches ? 'auto' : 'smooth'` — 움직임 줄이기 설정 사용자는 즉시 이동.

## 닫을 때: 페이지 높이를 붙잡고 되돌아가기
- 원인: 팝오버가 빠지면 문서 높이가 줄고, 현재 `scrollY`가 새 최대 스크롤을 넘으므로 브라우저가 즉시 끌어올림 → 뚝 끊김.
- 해결: `useLayoutEffect`의 **cleanup**(언마운트 시 DOM 제거 전에 실행됨)에서
  - `documentElement.style.minHeight = scrollHeight px`로 높이를 고정하고
  - `scrollTo({ top: openedAt, behavior })`로 열기 전 위치로 부드럽게 이동,
  - 목표 위치에 **실제로 도착했을 때** `minHeight`를 해제(`scroll` 리스너에서 `scrollY <= openedAt + 1`). 안전장치로 3초 타이머 해제.
- 실패한 첫 시도: 일찍 해제하면(이전 스크롤의 stale `scrollend` 등) 고정이 먼저 풀려 536→229로 한 번에 뛴 뒤 0으로 갔다. "도착 확인 후 해제"로 바꿔 해결.
- 예외 처리: 열린 동안 사용자가 더 위로 올려 둔 경우(`scrollY < openedAt`)는 아래로 끌어내리지 않음. 다 열리기 전에 닫아도 진행 중이던 스크롤이 닫힌 뒤 이어지지 않게 정리.
- 한계: 자동화 Chrome에서는 스크롤 중간 위치가 거의 안 잡혀 "부드러움" 자체는 측정 못 했다(시작·끝 위치와 끊김 없음만 확인) — 육안 확인 필요.

## 팝오버 아래 흰 바탕
- 팝오버가 페이지 콘텐츠보다 아래로 내려가면 페이지 래퍼 바깥(`body`)의 흰 바탕이 드러난다. 여백을 늘리면 닫혀 있을 때도 빈 공간이 생기므로, `body` 배경을 페이지와 같은 테마 토큰으로 칠하는 쪽을 택했다(Emotion `<Global>`, 사용자 결정). 위 자동 스크롤과 병행.

## 클릭 시 화면이 움찔하는 레이아웃 시프트 방지
- 선택 시 테두리가 1px→2px로 두꺼워지면 내용이 1px 밀린다 → 테두리 두께는 고정하고 선택 상태는 `border-color` + `box-shadow: inset 0 0 0 1px`로 표현.
- 비활성 사유 문구가 생겼다 사라지며 아래 요소 높이가 바뀌면 `min-height: 1.2em`으로 줄을 항상 예약.
- 확인: JS로 상호작용 15회 전후의 위치·높이를 재서 변화 없음을 검증.

## 관련 함정 (같은 작업에서)
- Vite가 SVG를 data URI로 인라인하면 `url(${icon})`을 따옴표 없이 쓸 때 체크박스 on/mixed 배경이 안 보임 → `url("${icon}")`로 따옴표 필수.
- 키보드(`event.detail === 0`인 click)로 날짜를 고르거나 Esc로 닫으면 팝오버 언마운트로 포커스를 잃음 → 닫은 뒤 트리거 버튼에 포커스 복귀. 팝오버 밖 요소(기간 라디오)에 포커스가 있을 때도 Esc가 먹도록 `document` keydown 리스너 사용.
- 전체 선택 체크박스 규칙: 0개일 때만 모두 선택, 일부·전체 선택 상태에서는 모두 해제(업무 담당자 트리와 동일). 승인 후 규칙을 바꾸면 spec·시나리오를 먼저 고치고 재승인 후 코드·e2e를 고친다 — [[ToyVillage-Admin-FE/하네스-시스템]].
