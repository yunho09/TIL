# 스크롤 트리거 오브젝트 연출 패턴 모음

[[토스식-핀고정-스크롤-장면]]이 "화면을 붙잡아두고 확대/축소·페이드를 안무"하는 큰 틀이라면, 여기는 그 안에서 개별 요소 하나하나에 붙이는 작은 연출 부품들이다. 재밋(Zaemit) 공모전 사이트를 "더 화려하게" 반복 요청받으며 쌓은 것들이라 이름은 사이트 고유 클래스로 되어 있지만, 기법 자체는 CSS `transform`/`clip-path`/`stroke-dasharray`와 `IntersectionObserver`만으로 되어 있어 플랫폼과 무관하게 재사용 가능하다. 공통 원칙: 반복 애니메이션은 기본적으로 `animation-play-state:paused`로 멈춰두고 `IntersectionObserver`가 뷰포트에 들어올 때만 `running`으로 켠다(화면 밖에서 공짜로 태우지 않기 위함) — [[backdrop-filter-blur-애니메이션-배경-스크롤-끊김]]에서 확인한 "안 보이는 애니메이션도 비용"이라는 교훈의 연장.

## 카드 딜(fan-out) — 가운데 뭉쳐 있다가 스크롤로 부채꼴로 펼쳐짐

카드 여러 장을 그리드 중앙 한 지점에 겹쳐 쌓아두고(`transform: translate(중앙까지 거리) rotate(부채꼴 각도) scale(0.88)`), 스크롤 진행도 P에 카드마다 살짝 다른 지연을 줘서(`k_i = clamp((P - i*0.07)/0.72, 0, 1)`) 하나씩 제자리로 돌아오게 한다. 끝에서는 인라인 transform을 지워 그리드 기본 배치로 되돌린다(레이아웃 자체는 항상 정상이고, 시작 상태만 transform으로 흉내 낸 것이라 JS가 실패해도 카드는 정상 위치에 있다).

## 클립패스 리빌 — 사진/텍스트가 아래에서 위로 걷히며 나타남

`clip-path: inset(X% 0 0 0 round Rpx)`에서 X를 100→0으로 스크롤 진행도에 따라 줄이면 이미지가 아래에서부터 걷히듯 드러난다. 이미지엔 동시에 `scale(1.3→1)`을 줘서 걷히는 동안 살짝 줌아웃되는 느낌을 더할 수 있다. `clip-path`도 `transform`처럼 컴포지터 친화적이라 스크롤 중 재계산 비용이 낮다.

## 타임라인 드로잉 — 세로선이 스크롤에 맞춰 그어짐

세로선 역할의 얇은 요소에 `transform: scaleX(0)`(가로선이면 `scaleY`)를 주고 `transform-origin`을 시작점에 고정한 뒤, 스크롤 진행도로 `scaleX`를 0→1로 올리면 선이 자라나는 것처럼 보인다. 선 위의 점(dot)들은 진행도가 자기 위치를 지날 때 `.on` 클래스를 토글해 색이 바뀌게 하면 "지나온 지점이 켜진다"는 느낌이 더해진다.

## 플로우 라인 — 노드 사이를 채우는 진행 바 + 이동하는 점

카드/스텝 여러 개를 잇는 가로선을 두고, 그 위에 겹쳐진 진행 바(`scaleX`)와 진행 바 끝을 따라가는 작은 원(`translate3d`)을 얹는다. 노드 위치는 실제 카드의 `getBoundingClientRect()` 중심점에서 계산해야 반응형에서도 안 어긋난다.

## 도어 오픈 카드 — `rotateY`로 문처럼 열리는 카드 + SVG 도장 드로잉

카드 좌/우 절반에 `perspective`가 걸린 부모 안에서 `transform-origin`을 바깥쪽 모서리로 두고 `rotateY(50deg → 0)`(왼쪽), `rotateY(-75deg → 0)`(오른쪽) 식으로 반대 방향 회전을 걸면 여닫이문처럼 열린다. 열림이 끝나는 시점에 SVG `stroke-dasharray`/`stroke-dashoffset`을 이용한 체크/엑스 표시가 "그려지는" 도장 효과를 얹으면(원+경로 두 개, dash 길이를 도형 둘레에 맞춰 계산) 완료 느낌을 준다.

## 회전 테두리 글로우 — `conic-gradient` + `mask`로 카드 테두리를 도는 빛

카드 `::before`에 `inset:-1px`, `conic-gradient`(또는 `linear-gradient` + `background-size:300% 100%` 스윕)를 걸고 `mask`로 안쪽을 파내 테두리 두께만 남긴 뒤 회전/이동 애니메이션을 건다. hover에서만 `opacity:1`로 켜면 상시 비용이 없다. [[토스식-핀고정-스크롤-장면]]과 마찬가지로 이 레이어도 `transform`만 애니메이션하므로 재래스터화가 없다.

## 배경 대형 마퀴 고스트 텍스트

큰 글자(예: 10~15vw)를 `color:transparent` + `-webkit-text-stroke`로 윤곽선만 남기고, 두 벌 복제해 `@keyframes`로 `translate3d(-50%,0,0)` 무한 이동시키면 배경 장식 문구가 흐르는 효과가 된다. [[무한-마퀴-드래그-클리핑-컨테이너-대신-트랙에-적용]]과 동일하게 트랙에만 transform을 걸고 바깥은 `overflow:hidden`으로 클리핑한다.

## CSS 특이도가 상태 클래스 조합에서 밀릴 수 있다

핀 고정 장면에 "라이브 상태" 클래스(`.yh-m-live`)와 "오브젝트 버전" 클래스(`.yh-m-obj`)를 나중에 하나 더 얹었더니, 기존 2클래스 선택자(`.yh-method.yh-m-live`)가 이겨서 새 스타일이 씹히는 문제가 있었다. 새로 추가하는 상태 조합용 CSS는 관련된 상태 클래스를 전부 이어붙인 선택자(`.yh-method.yh-m-live.yh-m-obj`)로 써야 특이도에서 밀리지 않는다.

## 대형 스크립트를 한 번에 못 보낼 수 있다 — 분할 배포

FX 엔진이 116KB까지 불어나자, 재밋 `component_update` 툴 호출 한 번에 전체를 실어 보내는 시도가 도구 출력 한도에 걸려 실패했다. 기존 엔진 본체는 그대로 두고 **새로 추가하는 연출만 별도의 작은 스크립트(21KB)로 분리**해 같은 컴포넌트의 `js` 슬롯에 이어붙이는 방식으로 우회했다. 전체를 매번 교체해야 하는 슬롯이라도, "기존 코드 + 새 코드"를 이어붙이는 형태로 나누면 한 번에 보내야 하는 양을 줄일 수 있다.

## 배포 후엔 curl로 바이트 단위 대조가 안전벨트

큰 스크립트를 올린 뒤에는 반드시 실제 배포된 페이지를 `curl`로 받아 로컬에 검수해둔 원본과 **글자 단위로 동일한지** 대조했다. 두 가지를 잡을 수 있다 — ① 저장 과정에서 코드가 잘리거나 깨지는 사고, ② 한글이 깨지는 사고. 실제로 한 번은 툴 호출 JSON 자체가 한글을 `\uXXXX`로 이스케이프해서 로그에 남겨 "깨졌나?" 오인할 뻔했는데, curl로 받은 실제 배포본은 한글이 리터럴로 정상 저장돼 있었다 — **로그에 찍힌 이스케이프 표시와 실제 저장된 값은 다를 수 있으므로, 판단은 항상 배포본을 직접 받아서 해야 한다.**

## 로컬 프로토타이핑 하네스로 먼저 확인 후 배포

"수정은 플랫폼 MCP 툴로만" 제약이 있는 사이트라도, 새 연출을 실제 사이트에 바로 올리기 전에 **같은 마크업의 로컬 사본**을 만들어 눈으로 먼저 검증하는 편이 안전하다(사이트에 반영하는 건 검증이 끝난 뒤 한 번으로 줄어든다). 이때 걸린 함정들:
- `file://`로 열면 정적 스냅샷만 렌더되고 스크립트가 정상 동작하지 않는 경우가 있었다 — 로컬 `http.server`를 띄워 `http://localhost:PORT`로 열어야 한다.
- 브라우저 팬이 좁은 폭(모바일 폭)으로 렌더되면 데스크톱 전용 연출이 초기화되지 않는다 — 뷰포트를 데스크톱 크기로 에뮬레이션해야 한다.
- 스크린샷 확대(zoom) 액션이 지원되지 않을 때는 `body`에 `transform: scale()`을 걸어 디지털 줌으로 대체할 수 있다.
- 캡처 타이밍이 이르면 이전 프레임이 찍히는 "오래된 스크린샷" 문제가 있다 — 작은 더미 스크린샷을 한 번 찍어 버리고, 잠깐 대기한 뒤 실제 캡처를 하는 방식으로 우회했다.
