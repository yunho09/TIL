# Commonly 배포본 기능 감사 (2026-10-01) 와 수정·재검증

배포된 admin/user/civil 3개 사이트를 FE 소스 + **배포 번들 직접 대조** + BE `develop` 소스 + 실제 톰캣 재현 + 라이브 클릭으로 감사한 결과. 핵심은 **경력 행을 만들 경로가 둘 다 막혀** 발급·수정·PDF·이력이 도달 불가였다는 것, 그리고 FE 쪽 원인 다수는 수정·배포해 라이브로 확인했다는 것이다. 이전 갭 목록은 [[Commonly-FE/프로젝트-현황]].

## 감사 전제
- 배포본 = `origin/main` 734a65e(2026-09-10). `develop`의 `d415e60`(개별 등록 수정)은 main 미반영이라 **admin·user 번들 모두 구버전**(감사 기준은 배포본, 방법은 [[배포-반영-확인-번들-해시-대조]]).
- 로그인 계정 `abcd1234`는 USER가 아니라 **ADMIN**(`GET /api/admins` 200). `CreateUserService`는 신규 직원을 항상 `USER`로 만드므로 실제 현장 직원(USER) 경로는 재현 못 함.
- 세 사이트 앞에 Cloudflare Basic 인증. JWT는 `{sub, iat, exp}`뿐, 1시간 만료, 갱신 엔드포인트 없음.

## 치명 — 경력 데이터를 만들 방법이 없었음
| 경로 | 상태 | 원인 |
|---|---|---|
| 개별 등록 | 100% 400 | 배포본이 `division`에 근무부서, `employmentType:""` 전송, `department` 키 없음. BE는 division∈{채용,전보,해지,퇴직}/null, employmentType∈{기간제,단시간근로자}/null만 허용(`""`도 거부). 근무형태 입력란이 없어 어떤 입력으로도 통과 불가. 대상자만 생성되는 반쪽 상태 |
| 일괄 등록 | 업로드 503 | 정상 워크북은 파싱 통과 후 `s3Uploader.upload()` 구간에서 사망(깨진 zip은 읽히는 500). 502 `STORAGE_FAILURE`여야 할 곳에서 CORS 없는 5xx. 앱의 garage `depends_on`이 `service_started`뿐이라는 정황. 손으로 만든 xlsx라 "모든 파일 실패"는 미단정 |
→ 대상자 6명 전원 `GET /api/humans/{id}/certificates` = 200 `[]`, 발급 이력 0건, `/api/certificates/{1..12}` 전부 404.

## BE 미구현·버그 (FE로 못 고침)
- **PDF 생성 코드 없음**: `certificates_issued.file_path`를 채우는 곳 0건, PDF 라이브러리 의존성 없음(poi만) → 다운로드 항상 404 "다시 발급해 주세요"(무한 재발급 유도). BE 자체 문서도 미구현 명시.
- **일괄 등록분 `humanId` null** → 조회·발급 쿼리가 `humanId` 조건이라 영원히 안 보임. 일괄 등록 매핑 대상 12개에 `department`도 없음.
- **403→본문 없는 401**: [[Spring-Security-403이-본문-없는-401로-바뀌는-ERROR-디스패치]].
- **인가 구멍(소스 판정)**: `/api/human**`, `/api/files/**`에 역할 제한 없음(`anyRequest().authenticated()`) → 민원인 토큰으로 전 시민 인적사항 CRUD·일괄 적재 가능. FE도 로그인/라우터에 역할 검사가 없어 민원인이 담당자 앱에 로그인됨.
- 대상자 삭제 시 발급 이력 소실(`CertificateIssuedRepository`가 humans와 inner join, `HumanService`는 humans만 삭제, 경력 행은 고아).
- 업무 이력은 발급 테이블만 조회 — '구분' 전 행 "증명서 발급", '업무 처리자' 전 행 `-`, 등록/수정 이력 미적재.
- 워크북 아닌 .xlsx → POI 런타임 예외를 `catch(IOException)`이 못 잡아 의도된 422 대신 500. 목록 API가 total을 안 줘 끝 페이지가 정확히 10건이면 '다음'이 빈 페이지. 성별 enum이 두 벌(`certificate.entity.Gender`=MALE/FEMALE, `human.entity.Gender`=M/F). 세션 연장용 갱신 API 없음. 민원인 본인 경력 목록 API 없음.
- 사후 발견: 경력이 생긴 뒤 `POST /api/certificates`(발급)가 **500**. humanId/certificateIds 오입력은 정상 404라 검증은 통과하고 문서번호 생성·저장 단계에서만 터짐. `DocumentNumberGenerator`의 `insert … on conflict (year)` 네이티브 쿼리 대상 테이블 부재/유니크 인덱스 부재 의심(추정, BE 로그 미확인). 그 여파로 PDF·이력은 여전히 검증 불가.

## 대민(civil) — 로그인 외 되는 게 없음
발급이 3중 차단: ① `POST /api/certificates/self`가 `denyAll()`(`CERTIFICATE_SELF_ISSUE_ENABLED` 기본 false, 본인인증 부재 때문에 의도적) ② 켜도 `PetitionerHumanResolver`가 성명+생년월일 완전일치 `humans` 행 요구(없으면 404) ③ 경력 행 0건. 본인인증은 `window.prompt` 3번이라 서버 검증이 전무. 가입 prompt에서 생년월일 형식을 틀리면 칸이 `readOnly`라 못 고침. 아이디/비밀번호 찾기는 가짜 링크. 서로 다른 실패("인적사항 미등록"/"경력 없음")가 같은 문구로 합쳐짐.

## FE 버그·과잉 제한·UI만 있는 것
- 경력 수정 저장 100% 400: gender `M/F`(BE는 MALE/FEMALE) + `division`/`employmentType`/날짜 `""`(BE는 null만 허용).
- 발급 표 '근무부서' 칸에 `certificate.division`을 매핑(`department: certificate.division`). 쓰기를 고치자 읽기 쪽 혼동이 드러남 → `toCareerRow` 순수 함수로 분리+회귀 테스트(같은 실수가 두 번 났음).
- 발급 10건 상한(`@Size(max=10)`) 안내·400 매핑 없음, 퇴직일 사실상 필수(BE nullable), 주소 필수(BE 선택, juso 단일 장애점·`dev` 키), 일괄 등록 필수 열 불일치(FE: 이름/생년월일/채용일, BE: 이름/성별), 업로드 용량 안내 20MB vs 실제 10MB, 대상자 삭제가 `window.confirm`, `IndividualRegistrationCareerPage`가 앱별 복제라 한쪽만 고치면 어긋남.
- UI만 있고 동작 없음: 세션 연장(`onExtend` 미전달 + BE API 없음, 3앱 공통), 발급 사유·수정 사유(서버로 안 감), 대민 선택 발급, 표준 서식 다운로드 링크 없음, 계정 수정·비밀번호 재설정 화면 없음(BE `PATCH /api/auths/{userId}`·`/password/{userId}`는 있는데 FE 호출 0건).
- 에러 표시 관련 3건은 [[API-에러-메시지-우선순위와-화면-밖-렌더링]].
- 정상 확인: 로그인·세션 유지·라우트 가드, 대상자 조회·등록·인적사항 수정, 도로명주소 검색, 사용자 목록, 계정 등록(201), 업무 이력 필터, 초기 비밀번호 변경 감지, 토큰 만료 시 로그인 리다이렉트(`useSessionGuard`), 발급ID/경력행ID 구분(의심했으나 기우), HTTP 메서드 FE↔BE 일치.
