# Bium FE Sprint 4 마무리 — 전체 기능 점검과 수정 (2026-11-25)

내 파트 PR을 모두 머지한 뒤, 최신 develop(FE+BE)을 로컬에서 띄워 52개 항목을 브라우저로 점검하고 나온 문제를 PR #109~#119로 고친 기록. 기능 실패는 없었고 화면 깨짐 1건과 작은 문제들이 나왔다. 로컬 환경 함정과 시연(ngrok) 전 체크리스트도 함께 남긴다.

## 로컬 환경 함정
- **8080은 Argo CD(kubectl port-forward)가 이미 사용** → 로컬 BE는 **8081**, FE는 `VITE_API_URL=http://localhost:8081 npm run dev -- --port 5173 --strictPort`. BE CORS 허용 목록(`CORS_ALLOWED_ORIGINS`, 기본 localhost:3000·5173)에 있는 포트만 쓸 수 있어서, 점검 일꾼을 5174~5180에 따로 띄울 때마다 BE 쪽에 포트를 열고 재시작해야 했다.
- **Homebrew가 Java를 업데이트하면 이미 떠 있는 JVM의 모든 외부 HTTPS가 깨진다.** 증상은 AI 레시피 추천 502(`trustAnchors parameter must be non-empty`). openjdk@17 17.0.21→17.0.21.1로 바뀌며 옛 버전 파일이 지워져 인증서 저장소를 못 읽은 것. 키·코드 문제가 아니었고 **BE 재시작으로 해결**. Gemini·KAMIS·식약처 호출이 전부 해당. 같은 시각 MySQL 컨테이너도 꺼졌는데 이유는 미확인.
- 로컬에 KAMIS 키·SMTP가 없으면 시세는 `marketPrice: null`(장보기 화면은 이름만 보이고 안 깨짐), 테스트 메일은 502 `NOTIFICATION_MAIL_FAILED`. 코드 정상 여부는 키 없이 확인 불가.
- **이메일 로그인(BE #70 + FE #85)은 한쪽만 머지하면 가입·로그인이 400.** `users.login_id`를 삭제하고 `email`을 유니크로 바꾸는 마이그레이션이 기동 시 돌아 **되돌릴 수 없고**, 이메일 없던 기존 계정(`expirytest` 등)은 로그인 불가 → 올릴 때 이메일을 넣거나 새로 가입.

## 시연(ngrok) 전 BE 환경변수
- 필수: `DB_URL`·`DB_USERNAME`·`DB_PASSWORD`, `JWT_SECRET`(32바이트 이상), `GEMINI_API_KEY`(없으면 AI 레시피·영수증 실패), `CORS_ALLOWED_ORIGINS`(FE ngrok origin을 정확히, 무료 ngrok은 주소가 바뀔 때마다 값 수정+서버 재시작).
- 선택: `NUTRITION_API_KEY`(없으면 기본 76개 외 영양 정보 없음), `KAMIS_CERT_KEY`·`KAMIS_CERT_ID`(시세), `MAIL_*`+`APP_URL`(메일 링크가 ngrok 주소로 가려면).
- 시연용 DB는 #70 마이그레이션 전에 백업하거나 새로 만들고, 서버는 시연 직전에 다시 켠다(Java 업데이트 함정). 재료 사진은 DB(BLOB) 저장이라 폴더 설정 없음.

## 점검에서 나온 문제와 원인·수정
| 문제 | 원인 | 수정 |
|---|---|---|
| `/notifications`가 390px에서 가로 31px 넘침 (#109) | 이메일 input·시각 select의 **브라우저 기본 너비(~336px)가 grid 폼 카드의 최소 너비를 결정**. 처음엔 Card 최소 너비로 추정했으나 원인은 입력칸 | `Field` 안 `input, select`에 `width: 100%`. 대안(`Wrapper`에 `minmax(0,1fr)`)은 페이지 넘침은 풀어도 입력칸이 카드 밖으로 8px 삐져나옴 |
| 로그인 만료 시 안내 없음 (#114) | 401 시 로그인 화면으로만 이동 | `authStore`에 `isExpired`(localStorage 저장 제외, `partialize`)·`expireAuth`·`dismissExpired`. **토큰을 담은 요청의 401만** 만료로 처리해 비밀번호 오류와 구분. 헤더 로그아웃이 `onClick={clearAuth}`로 이벤트를 넘기므로 `clearAuth`에 인자를 붙이지 않고 만료용 함수를 따로 둠 |
| 피드 코멘트 빈 값 오류가 입력해도 남음 (#111) | `onChange`가 `formError`를 안 지움 | 오류에 종류(입력 오류/요청 실패)를 기록해 **입력 오류만** 타이핑 시 지움. 연결 실패 같은 "다시 시도" 오류는 다음 제출까지 유지 |
| 요리 완료 뒤에도 레시피 상세에 "냉장고 보유" (#117) | **레시피 응답의 보유 여부(`FRIDGE`/`fridgeMatches`)는 생성 시점 값으로 고정**돼 다시 불러와도 안 바뀜(curl로 확인). 근본 해결은 BE가 현재 냉장고 기준 값을 내려주는 것 | `GET /recipes/{id}/cooking-candidates`(현재 냉장고 기준)를 화면 열 때와 요리 완료·되돌리기 뒤에 받아 **이름으로 매칭**해 태그 조정. 응답에 없는 재료(기본 양념)·`MISSING`/`BASIC` 태그는 유지, 요청 실패 시 레시피 원래 태그로 복귀. 한계: 생성 때 "부족"이던 재료는 나중에 넣어도 "부족" |
| 냉장고 화면 안내가 다음 동작까지 남고 도구 막대가 두 줄로 밀림 (#115) | `notice`에 자동 해제 없음 | ref 타이머 `showNotice`(5초, 새 안내가 이전 타이머 정리, 언마운트 정리), 안내는 버튼 줄 아래 별도 줄. 부작용: 안내가 뜰 때 보드가 ~17px 내려감 |
| 헤더 메뉴가 가운데보다 왼쪽 (#119) | 알림 종 아이콘 추가로 오른쪽 칸이 302px로 늘어남 | 아이콘 간격 8→6px, 메뉴 간격 24→10px 등. 1345px+ 편차 −69→−17px, 대신 메뉴 항목 간격 28→14px. 1095~1344px에선 여전히 최대 −104px |
| 영수증 인식에서 두부 아이콘이 ⬜ (BE #73) | AI가 맞는 이모지가 없자 하얀 네모 문자를 돌려줬고 BE가 거르지 않음 | 이름이 도감 기본 재료와 같으면 도감 이모지(두부→🧈), 도형·상자 문자만이면 null, 프롬프트에 "없으면 null". 응답 형식 불변 |

- 설계대로라 안 고친 것: 같은 이름을 장보기 목록에 또 담으면 두 줄로 쌓임(수량 개념 없음), 냉장고 화면 장본 음식 패널엔 "빼기" 없음(도감에만), 도감에서 넣을 때 유통기한 선택 불가(기본값 사용).
- BE의 알려진 제약: 비공개 냉장고에서 비멤버 작성자는 자기 코멘트를 보거나 지울 수 없음(#67), 피드 순서가 공개순이 아니라 냉장고 id순(#52), 다음 구매 날짜 계산에서 냉장고로 안 옮긴 장본 음식 제외(#68), 서버를 #65 이전으로 되돌리면 REMOVE 기록 있는 냉장고의 활동 조회 500. 코멘트 수정·새 코멘트 알림은 미구현.

## UI 결정 기록 (장보기·냉장고·도감)
- **장보기 목록 개편(#102)**: 살 것 목록을 첫 화면 왼쪽으로 올리고 살 것·산 것을 한 카드에 합침, 달력은 8/12 열로 넓게. 색은 머리(라임)와 피버타임(코랄) 두 곳만 남기고 크림·회색·라일락·분홍 박스는 흰 배경+구분선으로. 체크하면 이름에 줄이 그어지며(배경선으로 그려 애니메이션 가능) 산 것으로 이동. 모바일은 목록→달력 순. 디자인 규칙은 GlobalStyle CSS 변수만 사용.
- 냉장고 화면의 피버타임 배너는 삭제(#101, 달력에 피버타임이 들어갔기 때문). 유통기한 알림 링크는 도구 막대(5개→4개)에서 헤더 종 아이콘으로 이동(#104), 390px에서 냉장고 이름을 지키려고 425px 이하에서 "Bium" 글자를 숨기고 로고만 남김.
- **문칸 카드 아이콘·이름 겹침(#106)**: 🥩 이모지가 실제로 30~32.5px로 그려져 24px 칸을 넘어 이름과 ~3px 겹침 → 칸을 `32px minmax(0,1fr) auto; gap: 8px`로.
- 도감 "기본" 배지가 칸이 좁아지면 글자 단위로 줄바꿈 → 줄바꿈 금지, 카드 폭을 넓혀 PC 4열(#96). 실온 구역의 햇빛 효과는 "별로"라는 피드백으로 제거해 구역 색만 남김(#95).

## 멀티에이전트 점검 운영에서 겪은 것
- 점검 일꾼 여럿이 **Chrome 창 하나를 공유**하면 좌표 클릭·키 입력이 자기 탭에 안 닿아, 대부분을 페이지 안 `click()`·합성 마우스 이벤트(dnd-kit MouseSensor)로 보냈다. 요청과 화면 결과는 확인되지만 실제 손 조작과 같지 않고 **터치 드래그(TouchSensor 200ms)는 검증 불가**. 일꾼마다 **계정(qa1~qa4)과 dev 포트를 따로** 써야 서로 로그인 상태를 덮어쓰지 않는다(5174에 남아 있던 `expirytest` 로그인으로 저장 확인이 한 번 실행된 사례).
- 창 크기 조절이 화면 폭에 반영되지 않는 환경에서는 같은 페이지를 **390px 폭 iframe**에 띄워 모바일을 확인하고, `scrollWidth === clientWidth`로 가로 넘침을 판정(스크롤바 폭만큼 iframe을 넓혀 실제 폭을 맞춤). iframe이 브랜치 전환 전 코드를 캐시하면 다시 불러와야 한다.
- 백그라운드 명령은 기본 30분, 최대 2시간 제한에 걸려 dev 서버가 꺼진다(다시 켤 땐 최대치로). 사용량 5시간 한도에 걸린 일꾼은 한도 해제 후 SendMessage로 이어서 돌릴 수 있고 작업은 보존된다.
- 같은 파일을 건드린 팀원 PR이 먼저 머지되면(#89 재료 사진 vs #88 냄새) develop을 브랜치에 **합치는 방식**으로 충돌을 풀어 강제 푸시를 피했다.
- 디스코드 공유용 정리는 메시지당 2000자 제한 때문에 두 개로 나눔. 노션 스프린트표의 행 번호(#17 등)가 PR 번호와 섞이지 않게 "노션 스프린트표 번호"로 명시.
