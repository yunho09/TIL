# 유통기한 단계별 애니메이션과 다음 구매 달력 (bium-fe #80·#81 / PR #82·#83)

재료 카드의 아이콘·배지를 유통기한 단계별로 다르게 움직이게 하고(#82), 장보기 목록 화면에 "다음 구매 날짜" 달력을 붙인(#83) FE 설계 기록. 달력은 BE API([[재료별-다음-구매-날짜-API-설계]])와 **같이 머지해야** 한다(BE가 없으면 달력 자리에 오류 안내가 뜬다).

## 유통기한 단계별 애니메이션
- 움직이는 대상은 **카드 전체가 아니라 아이콘과 배지뿐**. 카드에 transform을 걸지 않아 드래그(dnd-kit) 위치 계산과 겹치지 않고, 배지가 absolute여도 transform은 위치를 바꾸지 않는다.
- 단계별 값

| 단계 | 아이콘 | 배지 |
|---|---|---|
| safe(7일 이상) | 4.5초 주기로 1.5px 떠 있기 | 없음 |
| soon(6일 이내) | 2.2초 주기로 4px 통통 튀기 | 없음 |
| urgent(3일 이내·오늘) | 1.8초 주기 중 앞 40%만 ±9° 흔들고 쉼 | 1.8초 주기 크기 1→1.1배·투명도 1→0.75 |
| expired | 정지(흑백·흐림 유지) | 정지 |

- **시작 시점 분산**: 재료 id로 `((id*7)%10)/10`을 계산해 그 비율만큼 **음수 `animation-delay`**를 준다. 렌더마다 같은 값이고 카드가 10가지 시작점으로 흩어져 전부 동시에 움직이지 않는다(식은 임의로 정한 값).
- **끄는 경우**: `@media (prefers-reduced-motion: reduce)`는 `animation: none`, 드래그 중도 끈다. `DragOverlay` 복제 카드는 `isDragging`을 넘기면 카드가 0.35로 흐려져서 별도 `animated`(기본 true) prop으로 껐다.
- 검증: 실제 백엔드로 띄워 `getComputedStyle`로 단계별 animation 값(이름·주기·infinite)과 reduced-motion에서 전부 `none`임을 확인. 캡처는 정지 화면이라 **움직임의 느낌은 사람이 직접 봐야** 한다.

## 다음 구매 달력
- 위치: `ShoppingListPage`의 장보는 날 카드 아래 `PurchaseCalendar`(`key={fridge.id}`). 장보는 요일 열은 라임색이고 `ShoppingDayCard`가 바꾸는 스토어 값을 그대로 따라간다.
- **냉장고 전환/늦은 응답 처리**: `key={fridge.id}`로 냉장고가 바뀌면 컴포넌트를 새로 만들어 이전 일정이 남지 않게 하고, `useEffect`에 `ignore` 플래그(정리 함수에서 true)를 둬 늦게 온 이전 냉장고 응답을 버린다. 404 `FRIDGE_NOT_FOUND`는 `client.ts`가 이미 `markFridgeListStale()`을 부르므로 화면에서는 안내 문구만 보여 준다([[Bium/FE-Sprint3-감사와-수정-2026-11-20]]의 낡은 캐시 문제와 같은 흐름).
- **기본 선택 날짜**: 이번 달에 오늘 이후 예정일이 있으면 가장 가까운 날, 없으면 오늘. 오늘로 고정하면 첫 화면이 거의 항상 빈 목록이기 때문. 한 달 안으로 한정해 "기본은 이번 달"을 지킨다.
- **지난 예정일 재료는 칸에 표시하지 않고** 상단 "지난 구매 예정" 띠("N일 지났어요")에만 모은다.
- 날짜는 전부 지역 날짜 문자열 `yyyy-MM-dd`로 비교(`libraryDate.ts`·`fridgeLayout.ts` 재사용). 칸은 button + `aria-pressed`, `aria-label`은 "11월 27일, 우유 외 2개 구매 예정".
- 모바일(760px 이하)은 칸이 `minmax(0, 1fr)` 7열이라 이름은 한두 글자만 보여 **아이콘만** 남기고, 이름은 날짜를 눌러 열리는 하단 목록에서 본다(PC는 아이콘+이름, 2개까지+`+N`).

## 후속 추가 (2026-11-25)
- **냄새 애니메이션(#88)**: urgent(오늘~3일) 카드의 아이콘 **위로** 초록(`--success`) 물결 줄 3개가 2.4초 주기로 시차를 두고 피어올라 흔들리며 사라진다(위로 10px, 투명도 최대 0.85). 줄을 아이콘과 **별도 요소**로 두어 아이콘이 흔들려도 제자리에서 올라온다. 드래그 오버레이 카드엔 없고, reduced-motion에선 줄이 사라지지 않고 **멈춘 채 투명도 0.6**으로 남는다. 지난 재료·4일 이상엔 없음. 팀원 PR #89(아이콘을 사진 `IngredientIcon`으로 교체)와 같은 파일에서 충돌 → 사진 아이콘 안쪽 + 냄새 감싸기 바깥쪽으로 합쳐 해결.
- **구역 배경 효과(#93, 이후 #95)**: 효과는 선반 **뒤**에만 깔아 카드 클릭·드래그에 영향 없음. 냉장실=위에서 내려오는 안개+옆으로 흐르는 바람 줄(바람 줄이 흰색이면 묻혀서 구역 테두리 색으로 바꿈), 냉동실=눈송이+가장자리 서리. 실온의 햇빛·먼지 효과는 "별로"라는 피드백으로 **제거**해 구역 색만 남김.
- **달력 피버타임(#91)**: 같은 날 산 재료가 2개 이상이면 산 날 + 구매 주기들의 **최소공배수**(예: 7·7→7일, 4·6→12일, 3·5·10→30일)를 더한 날을 코랄색+불꽃 아이콘으로 표시하고, 그날이 지났으면 오늘 이후 처음 겹치는 날을 쓴다. 상단 "다음 피버타임은 N월 D일이에요" 안내를 누르면 그 날짜로 이동. 계산은 FE에서만 하고 BE는 안 바꿈. 문구의 조사(을/를)는 재료 이름 받침에 따라 틀릴 수 있어 별도 처리. 혼자 산 재료엔 표시 없음. (냉장고 화면의 피버타임 배너는 #101에서 삭제.)
- **달력 칸 표시 변경(#97)**: 그날 살 재료를 **전부** 칸에 넣고(피버타임으로 같이 사는 재료 포함) "2개까지+`+N`" 규칙을 없앴다. 세로로 길어지니 재료를 **옆으로 이어 붙이고 칸 폭이 넘칠 때만 줄바꿈**. (위 "달력" 절의 2개까지+`+N`은 이 변경 전 설명.)

## 상충하는 정보
- urgent 아이콘 흔들기 구간: 위 표(2026-11-23 기록)는 1.8초 주기 중 **앞 40%**, 2026-11-25 세션의 동작 설명은 **앞 30%**. 어느 쪽이 현재 코드인지 확인 못 함(`IngredientItem.tsx`의 keyframes로 확인 필요).

## 실제 화면 확인에서 나온 수정
- **월 이동 뒤에도 선택 날짜 패널이 이전 달 날짜로 남던 문제**와 **칸 아이콘이 14px로 작던 문제**(→18px)를 확인 중 발견해 고쳤다(수정 뒤 화면 재확인 없이 lint·build만 통과).
- 모바일 `fullPage` 캡처에 재료 15개 중 6개만 보인 것은 DOM엔 15개가 다 있어 기존 선반 레이아웃(높이 제한·내부 스크롤) 문제로 추정(원인 미확인).
- 처음 `bootRun`이 MySQL 준비 전에 떠서 접속 실패 → DB 준비 후 재기동.

## 기능 미리보기 방식
- 서로 다른 브랜치의 FE 두 기능을 보여 줄 때는 **미리보기용으로만 합친 로컬 서버**(push 안 함)에 임시 MySQL·BE·시드 계정을 붙여 연다. 머지는 사용자가 디자인을 본 뒤.
