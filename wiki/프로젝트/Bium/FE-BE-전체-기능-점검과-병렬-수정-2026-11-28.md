# FE·BE 전체 기능 점검과 병렬 수정 (2026-11-28)

bium-fe·bium-be를 4개 영역으로 나눠 대조한 점검 결과와 이어진 병렬 수정 기록. 주소·메서드·필드·enum 계약과 타인 데이터 접근 차단(curl)은 문제가 없었고, 결함은 **"화면은 정상처럼 보이는데 동작하지 않는 것"**과 상태 전환 뒤의 흐름, 없는 기능에 몰려 있었다. 같은 날 BE 단독 점검은 [[Bium/BE-버그-점검-재료명-매칭-시세-CORS-2026-11-28]].

## 원인과 해결 — 다시 만날 만한 패턴

### 보여 주는 기본값을 저장하지 않으면 배치 작업이 못 본다 (BE #85)
- 알림 설정 GET은 행이 없으면 기본값(켜짐·로그인 이메일·09:00)을 **만들어 보여 주기만** 했고, 스케줄러 `findDue`는 `notification_settings`에 행이 있는 사용자만 골랐다 → "알림 받기 켜짐"인데 메일이 영원히 안 감.
- FE 저장 버튼은 `isDirty`일 때만 눌려 사용자가 스스로 빠져나올 수 없었다.
- 테스트 메일은 행이 없어도 로그인 이메일로 보내져 사용자가 더 확신하게 된다.
- 고칠 방향(점검 제안): 가입 때 행 생성 또는 스케줄러가 행 없는 사용자를 기본값으로 처리. 실제 머지본이 어느 쪽인지는 기록에 없음.

### "보냈다" 표시를 발송 전에 찍는 문제
- 중복 발송을 막으려고 먼저 차례를 잡으면서 `lastSentDate`를 오늘로 바꿔, 알릴 재료가 없거나 D-3·D-day를 모두 끈 날, 발송 실패한 날에도 "마지막으로 보낸 날"이 오늘이 됐다.
- **선점용 값과 사용자에게 보여 주는 발송 기록은 의미가 다르다.**

### 취소·삭제에 "볼 수 있는가"를 먼저 검사 (BE #75, #83)
- 냉장고가 비공개로 바뀌면 외부인이 자기 댓글 삭제(404), 좋아요·저장 취소(404)를 못 했다. 저장은 재공개 때 목록에 되살아남.
- 댓글 해결: (댓글, 냉장고)로 먼저 찾고 **작성자 본인이면 공개 여부와 무관하게 삭제**. 아니면 기존 순서(조회 가능 → 존재 → 소유자) 유지 → 남의 댓글 존재는 여전히 안 드러남.
- 좋아요·저장 해결: **취소만** 공개 확인 제거(내 기록만 삭제, 없어도 성공). 누르기(PUT)는 공개 냉장고만.
- 남음: 비공개 전에 저장한 냉장고는 저장 목록에 안 보여 목록에서 해제할 수 없다.

### 요리 차감 후보와 유통기한 (BE #79)
- 후보를 유통기한 빠른 순으로 정렬해 **지난 재료가 첫 번째**였고, FE가 첫 후보를 미리 골랐다. 추천·만들기는 지난 재료를 "없는 재료"로 보는 것과 어긋남.
- #79로 지난 재료를 뒤로 보냈지만, **지난 재료가 유일한 후보면** 여전히 미리 선택되고 "보유"로 셌다. 후보에 `expired` 플래그를 주고 FE 선택·보유 계산에서 빼는 안이 제안됨.

### 그 밖
- **서버에만 있고 응답에 없는 값**: 도감 `defaultStorage`가 응답에 없어 "냉장고에 넣기"가 늘 냉장실(BE #80·FE #132), 레시피 `type`이 없어 직접 만든 것도 "AI 추천" 표시(BE #89·FE #135).
- **여러 요청을 한 번에 기다리면 하나의 실패가 화면 전체를 막는다**: 도감 화면이 장본 음식 API 실패만으로 오류 화면(FE #121).
- **만료 시각이 지나도 화면이 그대로**: 초대 코드. 만료 시각에 다시 검사해 코드·복사 버튼을 숨김(FE #123, 24시간 대기 실확인은 안 함).
- **검사 순서**: `lockFridge`(SELECT … FOR UPDATE) 뒤에 멤버 확인 → 비멤버가 남의 냉장고 쓰기를 지연시킬 수 있음. 파일 디코딩(`toPng`)이 권한 확인보다 먼저.
- **영수증 형식 검사**가 클라이언트 Content-Type뿐 → 위장 파일이 유료 AI 호출까지 감(코드 확인, 위장 요청은 비용 때문에 미실행).
- **FE만 검사하는 규칙**: 문칸 5개 제한, 이모지 1개, 닉네임 trim — API 직접 호출로 통과(curl 확인).
- **ERD에는 있고 구현이 없는 것**: `purchaseCycleDays`를 넣는 곳이 없어 도감 76개 중 값 0개([[재료별-다음-구매-날짜-API-설계]]), 부분 차감(`deducted_quantity`).
- **추측(미확인)**: ngrok 경고를 건너뛰는 헤더는 `<img src>`에 붙일 수 없어 사진이 이모지로 대체될 수 있음.

## 점검에서 나온 없는 기능
- 레시피 목록·삭제 API(목록이 localStorage에만 있어 "만들고 싶은 음식" 레시피는 상세를 나가면 못 찾음), 계정 관리·토큰 갱신(1시간 만료), 도감 재료 수정, 냉장고 이름 변경·생성, 댓글 수정, 초대 링크, 소유자 넘기기, 활동 기록 50개 이후 보기.

## 병렬 수정 운영에서 배운 것
- 방식: 영역별 일꾼, 버그마다 이슈·브랜치·PR, BE `./gradlew test`·FE `npm run lint`/`build` 통과 시 리뷰 없이 develop 머지(사용자 지시, 시간 부족). BE를 먼저 머지하고 의존하는 FE를 뒤에.
- **작업 도중 Orca 작업 폴더가 사라짐**: BE `manta` 폴더와 일꾼 worktree·브랜치가 지워져 커밋 전 변경을 잃음(Orca 정리로 **추정**). 이후 규칙: worktree는 원본 클론에서만 만들고 자주 커밋·push. 지워진 폴더에서 띄운 서버 프로세스는 계속 떠 있으므로 새 폴더에서 재기동해야 수정이 반영된다.
- **합치면 깨지는 PR**: 소유자 넘기기(#127) 테스트가 `$.data[0]`을 읽는데 활동 기록 페이지(#135)가 응답을 `$.data.activities[...]`로 바꿔 develop 테스트 1개 실패 → #138로 수정. **응답 모양을 바꾸는 PR은 최신 develop을 합쳐 전체 테스트**.
- **사용량 한도(5시간)로 일꾼 전원 중단**: 새 일꾼에게 이전 커밋과 미커밋 변경을 버리지 말고 이어서 하라고 맡김.
- **AI 표기 줄**: 사용자가 커밋·PR에서 빼라고 함. `Co-Authored-By`가 초기 커밋과 팀원 커밋까지 기록 전체에 퍼져 있어 지우려면 수백 커밋 재작성이 필요하고 모든 브랜치가 어긋남 → 개수를 세어 범위를 확인받기로 하고 보류([[Claude-Code-AI-표기-attribution-끄기]]).
