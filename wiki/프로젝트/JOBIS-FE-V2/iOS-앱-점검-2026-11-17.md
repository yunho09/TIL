# JOBIS iOS 앱 코드 점검 (2026-11-17)

`JOBIS-DSM-iOS-v2`(main = develop, 커밋 `c79f252`)와 BE develop 코드를 대조해, 11/11 점검 중 이미 고쳐진 것을 빼고 **iOS에서 고쳐야 할 것**만 추린 결과다. 앱 실행·운영 서버 실제 응답·스토어 배포 버전은 확인하지 못했고 전부 코드 기준이다. 후기(`year`→`time`)는 팀 요청으로 제외했다. 상위 프로젝트: [[JOBIS-FE-V2/프로젝트-현황]].

## 화면이 깨지거나 데이터가 잘못 저장됨

1. **지원·재지원 첨부를 업로드하지 않음** — `ApplyViewController.swift:175`가 `lastPathComponent`만 넘기고 `ApplyReactor.swift:100`이 업로드 없이 전송해 서버에 `파일명.pdf`로 저장 → 어드민·기업에서 S3 `NoSuchKey`([[JOBIS-FE-V2/프로젝트-현황]]의 첨부 원인). 수정: 파일 선택기 `asCopy:true` → `/files/pre-signed` → PUT → 응답 `file_path` 전송([[S3-Presigned-URL-업로드]]). 같이 볼 것: `PresignedURLAPI.swift:44` Content-Type이 `image/jpg` 고정, `:24` `URL(string:)!` 강제 언래핑(BE가 URL을 디코딩해 돌려줘 한글 파일명이면 iOS 15/16 크래시 추정), BE 확장자 검사가 대소문자 구분·`.jpeg` 없음(`FileType.java:13`).
2. **홈 배너 디코딩 실패** — BE #1083에서 `banner_url`이 삭제됐는데 `FetchBannerListDTO.swift:10`이 필수로 받음. 배너가 하나라도 있으면 실패. `title`·`content`·`detail_id`로 교체.
3. **면접 절차 `ETC` 미지원** — BE `ProgressType.ETC`(#1076) 추가, iOS `InterviewType`엔 없어 ETC 공고의 상세·겨울인턴 상세 디코딩 실패. `case etc` + unknown fallback. **(정정 2026-11-20)** 기업 웹 채용 절차 선택지 9개에 '기타'가 없어 지금은 ETC 공고가 생길 일이 없다 → 🚨가 아니라 선제 대비 항목. [[JOBIS-FE-V2/프로젝트-현황]]의 "면접 절차 ETC 정정" 참고.
4. **모집 목록 `hiring_jobs: null`** — BE develop #1171(미배포)의 `leftJoin`+`groupConcat`이 직무 코드 없는 공고에서 null을 내는데 iOS는 `String` 필수(`RecruitmentListResponseDTO.swift:13`) → 목록 전체 실패. iOS `String?`, BE는 `coalesce`.
5. **반려 사유 화면 무한 로딩** — 사유 없으면 `rejection_reason: null`인데 DTO가 `String`이라 디코딩 실패, `RejectReasonReactor.swift:50`에 에러 처리가 없어 "불러오는중..."이 계속 뜸(404도 동일). `String?` + "등록된 반려 사유가 없어요".

## 기능 버그

- **지원 취소 없음(#482)** — `CancelApplyUseCase`는 `UseCaseAssembly.swift:140`에 등록만 되고 어떤 Reactor에도 주입 안 됨, `ApplicationsAPI.swift:80-81`의 `default: return .none`이라 **토큰도 안 붙음**. BE는 REQUESTED도 진행 중 지원(HAS_ACTIVE_APPLICATION)으로 봐서 취소가 없으면 다른 회사 지원 불가. 원격 브랜치 37개 전부에서 화면 사용처 없음을 재확인했고 이슈에 댓글·PR도 없음(iOS 쪽에서 "된다"고 했으나 코드로는 미확인 → 어느 화면인지·로컬 작업인지 확인 요청).
- **지원 실패 토스트가 하나** — 원인 불문 "합격된 회사가 존재합니다"(`ApplyReactor.swift:127`), 409 두 종류도 `ApplicationsAPI.swift:90`에서 하나로 합쳐짐. BE 에러 코드 분리와 함께 고친다.
- **지원 버튼 연타 중복 제출** — `ApplyReactor.swift:99`에 로딩 상태·버튼 잠금 없음, 두 번째 요청은 409+엉뚱한 토스트.
- **지원 후 상세가 갱신되지 않음** — 상세는 `viewDidLoadPublisher`(`RecruitmentDetailViewController.swift:117`)에서 한 번만 조회하고 `viewWillAppear`(:182)는 탭바만 숨김, 성공 시 `ApplyFlow.swift:64`는 `popViewController`만 해서 "지원하기"가 켜진 채 남고 성공 토스트도 없음 → 다시 누르면 409 → "합격된 회사가…" 토스트. 수정: 상세가 다시 보일 때 재조회(홈 `HomeViewController.swift:183`이 이미 이렇게 함) + 성공 토스트, 재지원도 같은 경로.
- **지원 가능 학년을 앱이 직접 판단** — 일반 3학년·겨울인턴 2학년이 앱에 고정(`RecruitmentDetailViewController.swift:161`, `WinterInternDetailViewController.swift:170`), 학년 값은 홈 진입 때만 저장돼(`HomeReactor.swift:88`) 푸시로 바로 들어오면 값이 없을 수 있음. 서버의 `is_applicable`·`unapplicable_reason`만 쓰게 한다. BE도 상세 `is_applicable`(일반 공고 3학년만)과 지원 API(겨울인턴 2학년만, 일반은 졸업생·1학년 불가) 규칙이 달라 통일이 필요하다. #478이 4가지 사유를 버튼 문구로 이미 보여주므로 "학년만 막는다"는 틀린 설명. **(Android 점검 보정)** BE 지원 API는 일반 공고 **2·3학년**을 허용(`Recruitment.java:121-133`)하는데 iOS가 3학년으로 고정해 BE가 받아 주는 2학년까지 막으므로, BE 요청 줄은 "지원 API 일반 공고 2·3학년 허용인데 iOS는 3학년 고정, 상세 `is_applicable`과 규칙 맞추기(학년 오류는 403)"로 쓴다(위 본문의 "일반 3학년만 허용" 서술은 상세 `is_applicable` 기준).
- **빈 URL 칸만 추가해도 지원 버튼 활성**(`ApplyReactor.swift:82` `!newUrls.isEmpty`) → 서버 `@NotBlank` 400. 형식 틀린 URL도 막아야 함.
- **재지원 때 기존 첨부 미리 채움 없음** — BE `ReapplyUseCase`는 기존 첨부를 전부 지우고 새로 받은 것으로 교체.
- **공지가 최신 12개만** — `NoticeAPI.swift:6,36`이 `page` 없이 호출, BE 기본 `page=1`·`PAGE_LIMIT=12`. `page` + `GET /notices/count`로 무한 스크롤(Android도 동일).
- **알림** — 목록 탭은 읽음 처리만(`AlarmViewController.swift:46`, AlarmStep에 이동 없음), 푸시 탭 처리 없음(`AppDelegate`에 `willPresent`만, `didReceive` 없음), 설정 '전체' 판정이 화면에 없는 `INTERVIEW`까지 검사(`NotificationSettingReactor.swift:61`)해 4개를 다 켜도 전체가 꺼진 채.
- **버그 제보 사진** — 업로드 없이 `file:///` 로컬 경로를 `attachment_urls`로 전송(`UIImage+resize.swift:54` → `BugReportReactor.swift:80`), 다시 고르면 `imageStringList`가 안 비워져 누적(`:257`), 문구는 "최대 5장"인데 `selectionLimit = 0`·동영상 허용(`:205-206`). 마이페이지의 pre-signed 업로드 유스케이스 재사용. 제보함 진입은 주석 처리.
- **검색** — 이전 요청 미취소(flatMap 병합)로 늦은 응답이 결과를 덮어쓰고, `incrementPageCount`가 응답 뒤라 같은 페이지 중복 로드 가능(코드 판단, 재현 안 함). `flatMapLatest`/`take(until:)`.
- **토큰 만료를 기기 시계로만 판단 + 재발급 무한 반복** (`BaseRemoteDataSource.swift`, 코드 판단·실기기 미확인):
  - 서버에 묻지 않고 저장된 `accessExpiresAt`과 기기 현재 시각만 비교(`:94-97`), 만료로 보이면 `.retry(when:)`으로 재발급을 횟수·대기 제한 없이 반복(`:78-87`). 서버가 401을 줘도 재발급하지 않고(`:50-67`) 재발급이 실패해도 로그인 화면으로 안 보냄.
  - ① **무한 로딩:** 재발급해도 계속 만료로 보이는 경우 — `toJobisDate()`가 형식(`yyyy-MM-dd'T'HH:mm:ss.SSS`)이 안 맞으면 **현재 시각을 반환**(`String+toJobisDate.swift:8`)해 항상 만료 판정, 또는 BE가 시간대 없는 한국 시각(`LocalDateTime.now().plusSeconds`)을 보내는데 앱이 기기 시간대로 읽어 시계가 앞서거나 시간대가 한국보다 동쪽이면 방금 받은 토큰도 만료로 보임.
  - ② **로그인 필요한 화면 전부 실패:** 기기 시계가 늦거나 시간대가 서쪽이면 서버는 401인데 앱은 유효하다고 봐 저장된 만료 시각까지 모든 요청 실패(지원 화면에선 "합격된 회사가 존재합니다" 토스트로 보임).
  - ③ 리프레시 토큰까지 만료되면 에러만 나고 로그인 화면으로 안 가 직접 로그아웃·재설치해야 함. 덤: `:96 print(Date(), expired)`가 릴리스 빌드에서도 요청마다 출력.
  - 수정: 요청당 재발급 1회 후 그래도 만료면 로그인 화면, **401 받으면 재발급 후 1회 재시도**(시계만 믿지 않기), 재발급 실패 시 토큰 삭제+로그인 화면, 만료 시각 파싱 실패를 "지금"으로 처리하지 말기, BE와 시간대(`+09:00`) 포함 형식으로 맞추기. BE가 재발급 때 리프레시 토큰을 새로 바꾸는지는 코드를 못 찾음(바꾼다면 동시 재발급 시 일부 실패 가능). Android의 같은 계열 문제는 [[JOBIS-FE-V2/Android-앱-점검-2026-11-17]].

- **8. 지원현황이 내려감(짐작)** — #453의 '최근 본 기업' 섹션(177pt+여백)이 생기면 지원 현황이 밀려 첫 화면에서 안 보임. 시안대로 순서를 정하거나 지원 현황을 '현장실습' 카드 바로 아래로. 지원 현황 테이블 높이가 `greaterThanOrEqualTo(contentSize.height + 4)`로 처음 한 번만 잡히니 목록 수신 후 `행 수 × 72`로 재설정.
- **9. 북마크 연타** — BE `PATCH /bookmarks/{id}`는 **호출마다 토글**인데 앱은 화면부터 바꾸고 즉시 요청해 연타 시 요청이 겹쳐 서버·화면 상태가 어긋나거나 중복 저장 가능. 실패해도 화면이 안 되돌아감(`RecruitmentReactor.swift:109`, `WinterInternReactor.swift:92`). #490 지원 버튼처럼 `bookmarkingIDs: Set<Int>`로 진행 중 id를 막고, 실패하면 `updateBookmark(id)`를 한 번 더 보내 되돌림. 적용처 6곳(모집의뢰서·겨울인턴·검색·모집의뢰서 상세·겨울인턴 상세·북마크 목록).
- **10. 반려→재지원으로 합격 후에도 지원 들어감 — BE 수정 필요** — 첫 지원(`CreateApplicationUseCase`)은 `checkApplicationDuplicated`로 진행 중·합격 지원이 있으면 409인데 `ReapplyUseCase.java`는 상태(반려/승인요청)만 보고 이 검사가 없음. BE: 본인 지원서 확인 + 이 지원서를 뺀 나머지에 `DUPLICATE_CHECK` 상태가 있으면 409. 앱: 진행 중·합격 지원이 있으면 반려사유 화면의 "재지원 하기" 숨기고 409는 기존 안내로. 학생 웹도 같은 API라 똑같이 뚫려 있음.
