# JOBIS 포트폴리오 이슈 선정과 Sentry·측정 정리 (2026-11-21)

JOBIS(V2 프론트)에서 포폴에 쓸 소재를 git·노션·디스코드로 골라 **이슈 2개(NFD 첨부파일, 403·재시도 정책)**로 확정한 과정과 근거. 토이빌리지가 "측정과 개선"을 맡으니 JOBIS는 "원인을 끝까지 판 기술 문제"로 역할을 나눈 결정, Sentry 연결 상태, Sentry 없이 재는 방법을 담았다. 관련: [[ToyVillage-Admin-FE/포트폴리오-숫자-코드-대조와-면접-주의점-2026-11]], [[JOBIS-FE-V2/프로젝트-현황]].

## 소재 선정 결정

- 커밋 약 830개 중 285개가 본인 계정. 그러나 "페이지 퍼블리싱·시안 반영·필드명 수정"은 누구나 하는 일이라 **차별점이 안 된다** → 한 줄로 줄이고 원인을 직접 찾은 사례를 깊게 쓴다.
- 포폴(Figma 8장)에는 JOBIS가 아예 없었고, 토이빌리지가 이미 **성능·Sentry·AI 하네스·디자인 소통**을 다룬다 → JOBIS에서 같은 주제를 쓰면 겹친다. **토이빌리지에 없는 축**을 고른다: 환경 의존 버그 추적, 인증·네트워크 정책, "무엇을 잡는 테스트인가", 배포.
- 최종 확정: 이슈 **01 맥 한글 첨부파일(NFD)**, **02 토큰 만료 403과 재시도 정책**. 이슈 3(API 에러 0 회귀 E2E)·Cloudflare Workers 배포는 지원 회사 성격에 맞춰 하나 고르거나 성과 칸에만.
- 맡은 일 칸에 한 줄씩: URL을 필터의 단일 상태로(쿼리 값 검증·레거시 키 호환), 프리페치 키를 화면 쿼리 키와 일치, 드롭다운·메뉴 키보드 조작과 aria 연결, Cloudflare Workers 3개 앱 운영·스테이징 배포.
- Open API 프로젝트는 아직 결과가 없어(in-progress) JOBIS를 2번째 프로젝트로 올리는 안도 검토 대상. 초안 6·8장에 토이빌리지 내용이 그대로 남아 있었음.

## 이슈 01 — 맥 한글 첨부파일 (요지)

- 원인 1: 맥 브라우저가 한글 파일명을 자모 분리형(**NFD**)으로 넘겨 S3 키가 NFD가 되고, 완성형(**NFC**)으로 요청하는 쪽과 키가 달라진다. 해결은 업로드 전 `normalize("NFC")`를 공용 api 패키지 한 곳에 → 3개 앱 동시 적용. 상세: [[한글-파일명-NFD-NFC-불일치-S3-NoSuchKey]]
- 원인 2: 출처가 다른 S3 주소에서 `<a download>` 무시. 해결은 blob으로 받아 같은 출처 URL로 저장. 상세: [[크로스오리진-파일-다운로드-a-download-무시]]
- 이 세션에서 더 나온 구현 디테일: 캐시된 응답에 CORS 헤더가 없어 막히는 경우가 있어 `cache: "no-store"`로 받고, 실패하면 새 탭 폴백, Blob URL 해제를 늦춰 저장이 끊기는 브라우저를 피한다.
- 회고 포인트: 원인이 화면 코드가 아니라 **OS·브라우저 동작 차이**, 여러 앱이 같이 쓰는 문제는 공용 레이어 한 곳에서 막는다.

## 이슈 02 — 403과 재시도 정책 (요지)

- 403을 무조건 재시도하면 권한 부족 403에서도 POST가 두 번 나가 **중복 생성 위험**. 반대로 403을 아예 빼면 쿠키 만료로 생긴 403에서 재발급 없이 막힘(쿠키가 사라지면 Authorization 헤더 없이 나가 서버가 401이 아닌 403을 줌).
- 판정: `401 || (403 && 토큰 쿠키 없음)`일 때만 만료로 보고 재발급 1회. React Query는 4xx 재시도 안 함(다시 보내도 결과가 같음), 5xx·네트워크 오류만 1회. 코드 위치 `packages/api/src/instance.ts`, `query-client.ts`. 경위는 [[JOBIS-FE-V2/프로젝트-현황]]의 "401만 → 쿠키 없는 403 재조정" 절과 [[401을-세션만료로-오인한-로그인-루프]].
- 회고 포인트: 상태 코드만 보고 정하지 말고 **그 코드가 왜 왔는지**까지, 재시도는 부작용 있는 동작이라 안전한 요청인지부터 따진다.

## 포폴에 쓰면 안 되는 표현 (면접 꼬리질문 위험)

- **API 훅 팩토리 "설계"**: `create-hook.ts` 팩토리는 팀원이 만들었다(2026-02~03). 본인 몫은 버그 수정 2개(params 없는 경로는 쿼리 실행 막기, id 뮤테이션 URL 슬래시 중복) → "팀원이 만든 팩토리 위에서 경로 버그를 막았다"로 낮춘다.
- **Sentry 도입**: `@jobis/sentry` 패키지와 3개 앱 적용도 같은 팀원이 2025-12-19~20에 했고(PR #72·#74), 토이빌리지와 겹친다.
- 노션 JOBIS 페이지의 수치(커밋 225개)는 9월 기준이라 현재(285개)와 다르다.
- 결과 칸의 "2회 → 1회", "실패 → 정상"은 **코드 변경에서 추정한 값**이지 측정값이 아님 → 포폴에 넣기 전 직접 재현 확인(Claude 보충).
- 이슈 3개 모두 AI 없이 소리 내어 설명할 수 있어야 한다(노션 분석의 약점).

## JOBIS의 Sentry 연결 상태 (코드 기준)

- 3개 앱 `main.tsx`에서 `@jobis/sentry` `init` 호출, `SENTRY_DSN`이 있을 때만 실행. 앱별 `SENTRY_<APP>_DSN`을 빌드 때 주입(운영 Worker 3개에는 9/30에 넣고 스테이징은 일부러 뺌). 조직 `team-return`, 프로젝트는 앱 이름(`vite.config.common.ts`).
- 켜진 기능: 에러 수집, 성능(Long Task·INP), 세션 리플레이(운영 10%·에러 세션 100%), 400~599 HTTP 실패 수집, 소스맵 업로드 플러그인.
- **미확인**: `SENTRY_AUTH_TOKEN` 주입 여부(없으면 스택트레이스가 압축 코드), 실제 이벤트 유입.
- **패키지에만 있고 앱에서 안 쓰는 것**: `SentryErrorBoundary`, `useTrackPageView`, `perf.trackApiCall`, `setUser`.
- **개선 소재**: 리플레이가 `maskAllText: false`, `maskAllInputs: false`라 학생 이름·입력값이 녹화될 수 있음 → 개인정보 최소 수집 방향 수정(토이빌리지 포폴 결과 이어짐).
- **Sentry를 새로 붙이는 건 비추천**: 이미 연결돼 있고, 새 조직은 팀 Sentry를 둘로 가르며 포폴도 토이빌리지와 겹친다. 필요한 건 기존 조직의 **가입 요청 승인/초대**뿐.
- git으로 알 수 있는 건 "코드를 붙인 사람"까지이고 **Sentry 조직 생성자·현재 owner는 코드에 안 남는다** → 선배에게 보낼 문구에 "만드셨죠" 같은 단정을 쓰지 말고 관리자 여부를 먼저 묻는다.
- 계정 정보: 팀 노션에도 Sentry 계정 항목이 없었다(AWS·Cloudflare·Grafana·GitHub 등만). Sentry 로그인 화면은 이메일/비밀번호 외 Google·GitHub 로그인도 제공 — 조직에 초대된 계정이어야 들어가진다.

## Sentry 없이 측정하는 방법 (아직 측정 안 함, 정리만)

| 이슈 | 측정 | 방법 |
|---|---|---|
| 01 | NFD 업로드 후 열림 | NFD 이름 파일을 스테이징에 올려 수정 전(`888586a^`)·후 비교 |
| 01 | 다운로드 동작 | Playwright로 클릭 시 `download` 이벤트 vs 새 탭, Chromium·Firefox·WebKit 3종, 수정 전(`625dc78^`)·후 → 저장 0/3→3/3 |
| 01 | 기존 영향 건수 | DB 파일 경로 중 NFD 포함 건수(팀 권한 필요) |
| 02 | 4xx 1건당 요청 수 | Playwright로 API를 400으로 가짜 응답, 실제 요청 수 집계(2→1 기대) |
| 02 | 만료 403 복구 | 쿠키 삭제 상태에서 403 응답 → 재발급·원 요청 재시도 확인 |
| 02 | 권한 부족 403 + POST | 쿠키 있는 상태 POST 403 → 중복 전송 0건 |
| 02 | 회귀 방지 | axios 인터셉터 유닛 테스트로 세 경우 고정 |
| 덤 | API 에러 E2E | 수정 전 커밋 vs 현재, 13개 라우트에서 잡힌 에러 수(N→0) |
| 덤 | Grafana·GitHub | 백엔드 4xx·5xx 비율 배포 전후, QA 이슈별 처리 기간 |

- Cloudflare Workers 분석은 정적 파일 요청 수·상태 코드뿐이라 이번 이슈와 관련이 적다.
- Sentry에서 볼 후보 지표(접근 가능해지면): 운영 에러 수·상위 에러(11/12~11/19 첨부·NFC 수정 배포 전후), API 실패율, 학생 앱 LCP·INP. 번들 크기는 `vite build` 결과로 직접(현재 `lazy(` 사용 안 보임).

## 정보 수집 한계와 보안 메모

- 디스코드(JOBIS 4기·Team return 서버)에는 기술 이야기가 거의 없고 frontend 채널은 PR 봇 알림 위주. 쓸 만한 건 2026-05-27 "코드래빗 리뷰와 팀 리뷰를 거친 뒤 머지하자"고 먼저 제안한 기록(협업 한 줄).
- 팀 노션(Team: return)은 별도 워크스페이스라 노션 MCP 검색·페이지 조회가 404 → 로그인된 Chrome으로만 열 수 있었다. **자비스 팀 노션은 읽기만 하고 수정하지 않는다**(사용자 지시, 2026-11-21). 개인 노션의 JOBIS 페이지도 요청 전엔 손대지 않는다.
- 팀 노션의 「극비」 페이지에 운영 DB·SSH·AWS·Cloudflare 계정 정보가 **평문**으로 있고 게스트 포함 28명 이상에게 공유돼 있음 → 비밀번호 관리자로 이전·운영 계정 교체를 팀에 제안할 만한 "운영 보안 개선" 소재(값은 위키에 옮기지 않음). 개인 노션 쪽에도 앱 비밀번호가 적힌 페이지가 있어 재발급·삭제 권고.

## Figma 포폴에 JOBIS 3장 추가 (2026-11-23)

- 기존 8장은 건드리지 않고 그 아래에 따로 **개요 → 맡은 일·주요 성과 → 주요 이슈 01–02** 3장을 토이빌리지 페이지(2·3·4번)를 복제해 같은 형식으로 채웠다. 이슈 페이지부터 만들었다가 "프로젝트 개요부터 해야지"라는 지시로 순서를 바로잡음 → 포폴 프로젝트 섹션은 **개요부터** 시작한다.
- 개요 값: 기간은 첫 커밋일(2026.02.08)부터, 로고는 레포 `logo-with-text.svg`에서 아이콘만 꺼내 사용, 팀 구성은 사용자 확인값(Frontend 3·Backend 2·Design 2·iOS 1·Android 1 — git 작성자로 센 Frontend 5는 틀린 값이었음). 모르는 인원은 추측하지 않고 "–"로 비워 둔다.
- 쓸 숫자가 없는 배지·남는 칸은 삭제하지 않고 **숨김** 처리. 결과 칸 값(2회→1회 −50% 등)은 여전히 코드 변경에서 추정한 값이라 재현 테스트 후 교체 필요.
- 협업 줄의 "리뷰 절차 제안"은 디스코드에서 "이렇게 해도 되나요?"라고 물은 메시지가 근거라 표현이 센 편 → 사용자가 조정.
- 주요 기능 스크린샷은 운영 사이트가 로그인 필요(에이전트는 자격 증명 입력 불가)라 사용자가 로그인한 탭에서 찍는 방식. 아래 이미지 깨짐 때문에 로컬로 대체.

## 운영 학생 웹 이미지 깨짐 발견 (2026-11-23, 팀 보고 필요)

- 운영 `student-v2`에서 기업 로고·프로필 이미지가 전부 회색 빈칸. 이미지 URL에 파일 서버 주소가 안 붙어 자기 도메인(`student-v2.jobis-dsm.kr/LOGO_IMAGE/companydefault.png`, `EXTENSION_FILE/...profile.png`)에서 파일을 찾는다.
- 코드에는 `FILE_URL`을 앞에 붙이는 헬퍼가 있고 로컬(FILE_URL 설정)에서는 정상 → 원인은 **운영 빌드의 `FILE_URL` 빈 값** 또는 **배포 버전이 수정 이전 것**, 둘 중 하나(미확정). 이전 상대경로 이슈는 [[JOBIS-FE-V2/프로젝트-현황]]의 stag QA #166/PR #167 참고. 실사용자에게 보이는 버그.
- 운영 사이트 네트워크에서 **Sentry 이벤트가 실제로 전송 중**임을 확인(데이터 유입은 가입 승인 후 대시보드로 확인).

## 로컬 학생 웹으로 스크린샷 찍는 방법 (워크트리)

- 워크트리에 패키지 설치 후 공용 패키지 3개 빌드, 워크트리 `.env`에 `BASE_URL`(운영 API)·`FILE_URL`(메인 체크아웃 `.env`의 S3 주소)·`MODE=development`만 넣고 Sentry 키는 제외(로컬 테스트 에러가 팀 Sentry로 가지 않게). `.env`는 git 무시 파일.
- 로컬은 쿠키가 따로라 `localhost:5173`에서 다시 로그인해야 한다. 운영 API가 localhost를 CORS로 막으면 로그인 실패 → 스테이징 API·스테이징 계정으로 전환.
