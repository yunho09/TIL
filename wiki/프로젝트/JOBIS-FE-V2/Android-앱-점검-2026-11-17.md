# JOBIS Android 앱 코드 점검 (2026-11-17)

`JOBIS-ANDROID-V2` develop(`a8282b1b`, main = v2.5.5 태그 + #549·#551 미배포)과 BE develop 코드를 대조해, 이미 고쳐진 것을 빼고 **Android에서 고쳐야 할 것**만 추린 결과다. 앱 실행·운영/스테이징 서버 실제 응답·스토어 버전은 확인하지 못했고 전부 코드 기준이다. 후기(`year`→`time`)는 팀 요청으로 제외. iOS판은 [[JOBIS-FE-V2/iOS-앱-점검-2026-11-17]], 상위: [[JOBIS-FE-V2/프로젝트-현황]].

## 공통 원인: Moshi 파싱 실패는 조용히 화면만 비움

- Moshi 1.15.1 + `KotlinJsonAdapterFactory`(`NetworkModule.kt:64`). 모르는 키는 무시하지만 **non-null 필드가 null이거나 빠지면, enum에 없는 값이 오면 `JsonDataException`**.
- 모든 UseCase가 `runCatching`이라 앱은 안 죽고 그 화면만 빈 채로 나온다(크래시는 아래 토큰 건 하나).

## 앱이 꺼지거나, 데이터가 잘못 저장되거나, 화면이 비어 보임

1. **토큰 재발급 실패 시 릴리스 앱 강제 종료** — `TokenInterceptor`(401이면 reissue, `:45-51`)와 `TokenAuthenticator`(401마다 reissue, 횟수 확인 없음, `:50-68`)가 **둘 다 등록**(`NetworkModule.kt:76,78`)돼 재발급이 이중으로 돌고 재시도 상한은 OkHttp 기본 20회뿐. 재발급 실패 시 `RefreshTokenService.kt:44`가 `ReissueException`(RuntimeException)을 던지는데 OkHttp dispatcher 스레드에서 아무도 안 잡고, 예외 핸들러는 `JobisApplication.kt:25 if (BuildConfig.DEBUG)` 안에만 있어 **릴리스는 강제 종료**(디버그는 토스트 후 재시작). 트리거: 오래 안 써 리프레시 토큰 만료, 재발급 중 오프라인. 같이 볼 것: 토큰을 `by lazy`로 한 번만 읽어 낡음(`:26-32`), `hasException`이 한 번 true면 안 돌아옴(`:64`), `addHeader`라 Authorization 중복(`:76`), 동시 401에 재발급 중복(동기화 없음). 수정: Authenticator 하나만 + Mutex + 재시도 1회, 실패 시 null 반환해 로그아웃, `header()` 사용. (코드 판단, 실기기 미확인)
2. **첨부를 지원 요청보다 나중에 올림** — `ApplicationViewModel.kt:191-213`이 지원/재지원을 **먼저** 호출하고 그 뒤 업로드, 결과를 버림. 지원 성공 시 `ApplicationScreen.kt:146 onBackPressed()`로 화면이 닫히면 업로드하던 `viewModelScope` 코루틴이 취소돼 업로드가 끊길 수 있어 **S3 `NoSuchKey`의 유력 원인**(런타임 미확인). 지원이 실패해도 업로드는 돌아 주인 없는 파일이 남음. 수정: presign → 업로드 전부 성공 확인 → 그다음 지원, 실패 시 중단+토스트([[S3-Presigned-URL-업로드]]). 같이 볼 것: 실패 후 다시 내면 `:227 addAll`로 첨부 중복, 같은 이름 파일은 `FileUtil.kt:76-77`에서 덮어써 같은 내용이 두 번 올라감, 모든 파일 content-type이 `application/octet-stream`(`RemoteFileDataSourceImpl.kt:31`), 용량 제한 없고 `readAllBytes`로 통째 메모리. BE: presigned URL 만료 **2분**(`S3Adapter.java:45`), 첨부 개수 `@Size` 제한 없음.
3. **홈 배너 안 보임(운영 포함 가능)** — BE #1083이 `banner_url`을 삭제했는데 `FetchBannersResponse.kt:14`가 필수 → 배너 0개(`HomeViewModel.kt:50`은 onSuccess만 처리). BE main에도 반영돼 prod v2.5.5도 이미 비었을 가능성. `HomeScreen.kt:281`을 title/content 배너로 교체. BE: 이미지 배너를 계속 쓸지 결정(쓰면 `banner_url` 복구).
4. **면접 절차 `ETC` 없음** — `HiringProgress.kt:3-15`에 없고 BE #1076(운영 반영)이 추가 → ETC 공고는 상세 전체 파싱 실패, `RecruitmentDetailsViewModel.kt:28`은 NPE만 처리해 빈 기본값 화면. `ETC("기타")` + `EnumJsonAdapter.withUnknownFallback`.
5. **`hiring_jobs` null** — `FetchRecruitmentsResponse.kt:18`이 `String`, BE `groupConcat`+left join(#1171, develop만 → stag부터)이라 직무 코드 없는 공고가 한 건만 있어도 **그 페이지 전체** 실패. `String?`+`orEmpty()`. BE가 `COALESCE(...,'')`로 내리면 구버전 앱도 안전.
6. **학교 밖 합격 처리 학생은 홈 지원 현황 전체 실패(운영)** — BE `CreateNonSchoolContactPassApplicationsUseCase.java:52`가 첨부 타입을 `NONE`으로 저장하는데 `FetchAppliedCompaniesResponse.kt:24`의 AttachmentType은 FILE·URL뿐. `NONE` 추가 + fallback.
7. **반려 사유 창이 안 열림** — `FetchRejectionReasonResponse.kt:8`이 non-null. 반려 전용 API는 사유 `@NotBlank`지만 **일반 상태 변경 API로 REJECTED를 지정하면 사유가 null**(`ChangeApplicationsStatusUseCase.java:33`, 선생님·기업 가능). `HomeViewModel.kt:102-112`가 NotFound만 처리해 눌러도 무반응. nullable + "사유가 등록되지 않았어요". BE: 상태 변경 API에서 REJECTED 막을지 검토(어드민 웹은 상태만 바꿔 사유가 비는 문제와 같은 뿌리, #977).

## 기능 버그

- **지원 취소 없음** — `RequestUrls.kt:68 const val cancel`뿐, API `@DELETE`도 UI도 없음(원격 브랜치 전체 grep 0건). BE는 본인·REQUESTED를 이미 검증(`Application.java:94-99`).
- **지원 실패 문구가 원인과 다름** — `ApplicationViewModel.kt:178` `ConflictException`이면 무조건 "이미 지원한 기업이에요". BE 409는 `APPLICATION_ALREADY_EXISTS`/`APPLICATION_IN_PROGRESS` 두 종류(`ApplicationErrorCode.java:23-24`)인데 Android는 `RequestHandler.kt`에서 **상태 코드로만** 예외를 나눠 구분하려면 응답 본문에 에러 코드 필드가 필요. 상세는 `is_applicable`만 읽고 `unapplicable_reason`은 안 읽어 "지원할 수 없어요"만 표시.
- **학년 막힘 무반응** — 학년 판단은 서버가 하고 하드코딩은 문구뿐("3학년만 지원할 수 있어요", `strings.xml:16`). 그 문구가 **401에 묶여**(`:170 UnAuthorizedException → UnexpectedGrade`) 있는데 BE는 **403**(`INVALID_GRADE(FORBIDDEN)`)이라 `ForbiddenException` 분기가 없어 무반응. 문구도 틀림 — **BE는 일반 공고 2·3학년, 겨울인턴 2학년만 허용**(`Recruitment.java:121-133`).
- **실패 후 버튼 영구 비활성** — `:186`에서 끄고 다시 안 켬. presign은 400만, 지원은 409/404/401만 처리해 400·403·5xx·오프라인은 토스트 없이 멈춤.
- **링크만으로 지원 불가 + 빈 링크 전송** — 파일 없으면 버튼 꺼짐(`:122`), `:126 urls.add("")`가 걸러지지 않아 BE `@NotBlank` 400 무반응.
- **재지원 때 기존 첨부 미리 채움 없음**(`:38-40`) — BE는 전부 교체. 상태 불일치 400은 분기 없음.
- **공지 최신 12개만** — `NoticeApi.kt:11`에 page 없고 `/notices/count` 미호출(BE `page=1`·`PAGE_LIMIT=12`, #1137은 09월 반영이라 prod도 해당).
- **알림** — 푸시 탭은 앱만 열림(`NotificationManager.kt:34` extras 없음, `JobisMessagingService.kt:36`은 `message.notification`만, MainActivity가 intent 미처리), `NOTIFICATION_ID = 0` 고정이라 새 푸시가 이전 것을 덮어씀. 목록 탭 이동은 **고쳐짐**(지원→홈, 모집의뢰서·공지→상세). 겨울인턴 알림 탭은 `else` TODO, 면접 알림은 일정 화면으로 이동(일정 기능은 팀이 뺐는데 4242bcfc가 홈 아이콘만 제거, `MainNavigation.kt:161-171` 경로 잔존)하고 #551이 면접 알림 토글을 새로 넣어 정리 필요. 서버가 모르는 topic을 보내거나 날짜 형식이 바뀌면(`NotificationsEntity.kt:41 parse(...)!!`) 목록 전체 실패.
- **버그 제보** — 사진 업로드를 따로 launch해 끝나기 전에 `reportBug()` 호출(`ReportBugViewModel.kt:85-92`), 실패 처리·제출 중 잠금 없음, `files.addAll`이 누적돼 재시도 시 중복, 변환을 메인 스레드에서. 제보함 없음(Figma엔 있음).
- **기업 상세** — 주소 `"${mainAddress} ${mainAddressDetail}"`(`CompanyDetailsEntity.kt:54`)라 상세 주소가 없으면 "… null"(`listOfNotNull().joinToString(" ")`). "모집의뢰서 보기"는 `isMovingToRecruitmentDetails`가 안 풀려 갔다 오면 계속 비활성(`:76`), 노출이 후기 조회 성공에 묶임(`:59`). iOS처럼 뺄지 결정 필요.
- **모집의뢰서 검색·필터** — `RecruitmentsViewModel.kt:137`에 이전 요청 취소 없음(기업 검색은 `:143`에서 고쳐짐), 실패하면 로딩용 빈 칸 12개가 남고 페이지 번호만 넘어감. #545 일부만 고침: 초기화 때 `clear()`(`:50, :90-94`)가 공유 필터를 null로 만들어 검색·체험형 화면에 들어가기만 해도 필터가 사라짐.
- **겨울인턴 시즌인데 필터 결과 0건이면 "시즌이 아니에요"** — `WinterInternScreen.kt:79`.
- 홈 지원 현황 상태 라벨 갱신 안 될 수 있음 — `ApplyCompanyItem.kt:47 remember`, `HomeScreen.kt:581` key 없음.

## 정리·문구·출시

- 상태 문구: SEND "전송"→"지원 중"(iOS·Figma와 통일), PROCESSING "진행중"→"진행 중". 지원 상태 enum에 fallback 없음(10개는 BE와 일치).
- 오탈자: "알림을 변경에 실패했어요", "안읽음", "관련 된 회사를 못찾았어요", "재지원 하기", "탐색 하기", "확장자에요/모집의뢰서에요"→예요, 화살표 `->`/`→` 혼용. 명칭 혼용: 겨울인턴/겨울 인턴/체험형 현장실습/현장실습 공고 시즌. 회원 탈퇴는 "추후 업데이트" 토스트만(`MyPageViewModel.kt:120`). #537은 증상만 가림(목록 교체 시 인덱스 예외 그대로), #533은 0개 선택 시 저장 불가.
- **출시·빌드:** 버전 2.5.5(38) 그대로인데 develop에 미출시 커밋 10개 → **운영 알림 설정 화면이 지금 깨져 있음**(main `NotificationTopic`에 INTERVIEW가 없는데 BE `/notifications/topic`은 모든 토픽을 반환; develop #551에서 고쳐졌고 출시만 하면 됨). stag 전용 flavor 없음 — release는 `BASE_URL_PROD`, debug는 `BASE_URL_DEV`(커밋 안 되는 `local.properties`)라 **debug에 `BASE_URL_DEV=stag`를 넣는 게 유일한 방법**, 이미지 S3 주소는 `ResourceKeys.kt:9`에 운영으로 하드코딩. **main에 push하면 `publishReleaseBundle`로 production 트랙에 바로 배포**(내부 테스트 트랙 없음).
- 영향 없음: `FetchInterestsRecruitmentsResponse.kt:12`의 필수 `company_id`는 BE 응답에 없어 항상 실패하나 UI에서 안 씀.
