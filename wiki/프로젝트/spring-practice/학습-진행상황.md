# 학습 진행 상황과 다음 단계

# 학습 진행 상황 (2026-09-02 기준)

사용자는 스프링 기초 로드맵 진행 중. JS/프론트 배경이라 설명 시 JS/TS 비유가 잘 통함.
학습 스타일: 파일 뼈대를 만들어주고 내용은 직접 손으로 타이핑 → 코드 한 줄씩 설명 요청 → 실행해서 눈으로 확인. 설명은 "실무에 필요한 선까지만"을 선호.

## 완료 (이해 확인됨)
- 빈/컨테이너/DI/IoC — MessageSender/EmailSender/KakaoSender 실습으로 체득 (실습 파일은 역할 끝나 삭제함)
- 생성자 주입 패턴, final의 의미, List<MessageSender> 다중 주입
- 인터페이스/implements/다형성 (Animal-Dog 비유로 잡음)
- getBean은 학습용, 실무는 컨트롤러 주입이라는 것
- 4계층 CRUD: Entity → Repository → Service → Controller 순으로 각 계층 정리 완료
- 엔티티 상세: @Entity, @Id, @GeneratedValue(IDENTITY), Long vs long, protected 빈 생성자 (자바의 "생성자 쓰면 기본 생성자 소멸" 규칙 포함), getter=JSON 변환 창구, setter 대신 update()
- JpaRepository: 빈 인터페이스인 이유(상속+스프링이 구현체 생성), 쿼리 메서드(findByTitleContaining 직접 추가함)
- MySQL 연동: datasource yaml, ddl-auto, Docker 컨테이너
- HTTP 메서드와 매핑: 같은 URL도 메서드가 다르면 다른 입구 (GET/POST 혼동 사건으로 체득)
- @PathVariable / @RequestParam / @RequestBody 구분
- Postman 테스트 (JSON 키 이름이 record 필드명과 일치해야 함 — "post" 키로 보내 null 저장된 사건)

## 겪은 에러들 (교육적으로 활용됨)
- cannot find symbol → import 누락 (ApplicationContext, List 두 번)
- Failed to configure a DataSource → 의존성은 있는데 접속 정보 없음
- @RestController("/") → 괄호 값은 경로가 아니라 빈 이름 (수정함)
- null title 저장 → 검증 부재 인식

## 다음 단계 후보 (사용자에게 제시된 상태)
1. 검증 @Valid — null 글 사건 재발 방지
2. 예외 처리 + 404 (ResponseEntity, @ExceptionHandler) — 현재 없는 id 조회 시 200 빈 응답
3. git init + 첫 커밋 — 아직 저장소 아님
4. @Transactional 개념 (이름만 예고해둠)
5. Lombok @RequiredArgsConstructor 전환 (개념 이해됨, 적용은 보류 중)
