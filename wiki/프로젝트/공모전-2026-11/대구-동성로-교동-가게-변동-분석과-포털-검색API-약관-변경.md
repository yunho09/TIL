# 대구 동성로·교동 가게 변동 분석과 포털 검색 API 약관 변경

골목결 대구판에 쓸 데이터를 모으다가 (1) 후기 수집의 전제였던 **네이버 검색 API 약관이 2026-09-07부터 AI 입력·저장 금지로 바뀐 것**을 발견했고, (2) 약관과 무관한 **소상공인 상가정보 3개 시점 비교**로 동성로·교동의 가게 변동률을 계산했다. 후속 근거자료는 [[대구-상권-근거자료-후보와-공실률-지표-주의]] 참고.

## 포털 검색 API 약관 변경 (2026-09)
- 네이버 검색 API는 개발자센터 **신규 신청이 막혔고 네이버 클라우드 'NAVER API HUB'로 이전**됐다. 키 등록 화면에 '검색'이 없던 이유.
- **9월 7일부터** 검색 API로 받은 데이터를 AI에 넣거나 저장·캐싱하는 것을 금지하고, 네이버 검색 결과를 보여 주는 목적으로만 쓰게 했다. 저장은 서버 이력 조회용 21일까지라는 해석이 있다 (언론·해석 블로그 기준, 약관 원문 직접 확인은 아님).
- 카카오(다음) 검색 API도 개발자 포럼 답변상 AI 입력·응답 저장 불가 (공식 약관 원문은 미확인).
- 골목결은 블로그 후기 문장을 저장·임베딩하는 서비스라 **새로 후기를 모아 대구판을 만드는 것이 약관에 바로 걸린다.** 7월에 모아 둔 후기 발췌문이 들어 있는 기존 K-AWARDS 데모도 걸릴 수 있어 팀 판단이 필요. 대회 공고도 "적법한 수집·제3자 권리 비침해"를 요구.
- 대응: 제안서 고도화 내용에 "포털 약관 변경으로 후기 데이터 원천을 바꾼다"를 넣으면 K-AWARDS판과 차별점이 된다. 후기 대체 원천은 미정.
- 교훈: API 기반 수집 설계는 **약관 개정일을 먼저 확인**한다. 키 발급 사이트는 크롬 확장이 안전상 접근을 막아 자동화 불가 → 사람이 직접 등록.

## 소상공인 상가(상권)정보 3개 시점 비교
- 2024-09, 2025-10, 2026-09 세 판을 로그인·키 없이 내려받음(이용 조건 제한 없음, 최신판 약 214MB). 세 시점 **업종 분류 체계가 같고 가게 번호가 1년 사이 88% 유지**돼 비교 가능.
- 일반음식점 인허가 표준데이터는 2021년에 멈춘 빈 파일이었고, 인허가 사이트는 스크립트·브라우저 모두 403 → 개·폐업일 기반 분석은 못 함.

| | 동성로 | 교동 | 대구 전체 음식점 |
|---|---|---|---|
| 현재 음식점 | 598곳(골목 517) | 102곳 | |
| 2년 전 가게 중 목록에서 사라진 비율 | 28.7% | 34.1% | 24.4% |
| 현재 가게 중 2년 안 신규 비율 | 33.3% | 45.1% | 26.9% |

- 동성로 **2층 이상은 2년간 36.3% 소멸, 1층은 26.9%** — 층별로 나눠야 차이가 드러남.
- '사라진 가게'는 폐업뿐 아니라 이전·업종 변경이 섞여 있으므로 제안서에는 **"목록에서 빠진 가게"**로 표기.

## 다운로드 함정
- zsh는 변수를 단어 분리하지 않아 `for d in $LIST` 식 반복이 한 덩어리로 처리돼, 옛 판 두 개 대신 **최신판을 두 번** 받았다 → 날짜를 직접 넣어 재다운로드. (배열/`${=VAR}` 필요)
- 과거 판은 현재 판과 받는 경로가 달라 0바이트 파일이 내려왔다 → 서버 응답을 확인하고 이력 팝업의 키로 받음.
- 받은 데이터는 신뢰하지 않는 입력으로 취급(압축 풀어 표로 읽기만, 실행 금지).
