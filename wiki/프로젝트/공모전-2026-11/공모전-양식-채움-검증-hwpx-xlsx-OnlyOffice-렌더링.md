# 공모전 양식 채우기 — hwpx 수정 검증, xlsx 가독성, OnlyOffice 렌더링 확인

한글·엑셀 프로그램 없이 제출 양식(hwpx, xlsx)을 스크립트로 채울 때의 방법과 검증 요령. 핵심: **hwpx는 zip+XML이라 파이썬으로 채울 수 있고**, 직접 열어 보지 못하는 레이아웃은 OnlyOffice 변환 엔진으로 PDF를 뽑아 확인한다. 한글에서의 실제 모양은 끝까지 미검증임을 명시한다.

## hwpx 채우기와 무결성 검증
- 바이너리 hwp는 못 다루므로 사용자가 hwpx/docx로 변환해 줘야 함.
- 채운 방식: `Contents/section0.xml`의 빈 칸에 `【직접 입력】` 표시(개인정보·서명 칸은 임의 기입 금지), 체크박스는 건드리지 않고 지원 형태만 "□ 팀단"→"■ 팀단".
- 안내문("※ … 기재")이 이미 든 칸은 안내문을 지우지 않고 앞에 표시만 넣는다.
- 검증 체크: `zipfile.testzip` 통과 / `mimetype`이 **맨 앞·무압축** / 항목 순서·압축 방식이 원본과 동일 / 바뀐 항목이 `section0.xml` 하나뿐 / 모든 XML이 `xml.etree`로 파싱 / 텍스트 diff가 의도한 칸만 / 동의·미동의 체크박스 원형 유지.
- 스크립트는 `python3 -I`로, 원본 복사본(`_original`) 밖에서 실행해 원본을 보호.
- 한계: 글자가 늘어난 칸의 줄바꿈·서명 줄 정렬은 한글로 열어야 확인 가능 → 체크리스트에 남김.

## xlsx 긴 글 가독성
- 잘림의 주원인은 **한글 폭을 반영하지 않은 행 높이 계산**. 한글 기준으로 다시 계산해야 한다.
- 엑셀 행 높이 상한은 **409pt**. 긴 본문은 여러 행을 세로 병합한 한 칸에 넣고, 복사할 프롬프트 전문도 한 칸에 통째로 둔다.
- 셀 안에 `|`로 그린 표는 깨져 보이므로 `▶ 소제목`, `• 항목`, `①②` 번호 목록으로 바꾼다.
- 한 행에 한 문항 구조를 지켜야 하는 시트(응답 250행)는 행을 나누지 않는다. 한 행 최대 높이보다 긴 답(250행 중 105행)은 일부만 보이고 전체는 수식 입력줄에서 보이므로 맨 위에 안내 한 줄을 적고, 머리글·질문 열은 틀 고정, 모델 원본의 `**`·`##` 기호는 원 응답 보존을 위해 그대로 둔다.
- 이미지 위 설명 칸은 몇 px만 모자라도 마지막 줄이 그림에 가리므로 여백을 둔다.

## OnlyOffice로 렌더링 확인 (데스크톱 화면 조작 불가일 때)
- 화면을 못 열면 OnlyOffice 변환 엔진으로 PDF를 만들어 이미지로 바꿔 본다(화면 렌더링과 같은 엔진). 글꼴 목록 파일 `AllFonts.js`를 찾아 지정해야 변환이 되는 경우가 있었다.
- xlsx는 PDF가 **첫 시트만** 담기므로 시트별 복사본을 만들어 각각 렌더링하고, 한 페이지에 다 들어와 글자가 작으면 해상도를 올려 칸 경계를 확대한다. hwpx 확인에도 같은 방법 사용 가능(래퍼 스크립트 `tools/oo_convert.sh`).
- 윈도우 엑셀은 맑은 고딕 줄 간격이 더 넓어 다르게 보일 수 있어 아래 여백을 일부러 남긴다. 근사치임을 보고에 밝힌다.
- 한글 파일명에서 OnlyOffice가 죽는 문제는 [[OnlyOffice-한글-파일명-크래시-fontconfig-캐시]] 참고.

## hwp → docx 변환과 docx 양식 채우기 (2026-11-13 보충)
- 바이너리 hwp를 사용자에게 hwpx로 바꿔 달라고 할 필요 없이 **OnlyOffice 변환기로 docx 변환**이 가능했다. 신청서·서약서·동의서·기획서 양식 표가 그대로 살아남음.
- 변환 부작용: 체크박스 `☐`(U+2610)가 대체 글꼴에서 `'`처럼 보임 → 양식의 다른 칸과 같은 `□`(U+25A1)로 바꾸고 체크한 칸만 `■`(U+25A0).
- 변환 docx는 **Word가 거부할 수 있는 구조 오류**(표의 `tblGrid` 없음, 표 속성 안에 문단 속성 혼입)가 있어 겉모양을 유지한 채 구조만 바로잡고 OOXML 스키마 검사를 통과시킴.
- 큰 칸 안에 표를 겹쳐 넣으면 OnlyOffice가 그 칸을 통째로 다음 쪽으로 넘겨 빈 쪽이 생김 → 원본처럼 하나의 표로 두고 문단·표 줄마다 행을 나눠 해결.
- 쪽수 검증은 OnlyOffice(x2t)와 LibreOffice 두 곳에서 렌더링해 쪽수·쪽 나뉘는 위치가 같은지 비교. 원고 조각(470개)을 docx 텍스트와 기계적으로 대조해 누락 0 확인. 이 PC엔 맑은 고딕이 없어 대체 글꼴로만 봤으므로 Word/한글에서 열어 보기는 사용자 체크리스트에 남김.
- 개인정보를 채운 뒤 스크립트로 문서를 재생성하면 입력한 내용이 덮어써지므로 **개인정보는 맨 마지막에 입력**.

## 한컴독스에서 hwpx 실제 확인·서명·PDF (2026-11-20~23 보충)
- OnlyOffice 렌더링만 믿지 말고 **한컴독스(웹 한글)에 올려 쪽수를 직접 센다.** 스크립트로 만든 제안서 표가 '글자처럼 취급' 상태라 쪽 경계에서 잘려 뒷부분이 안 보였다 → 해제 후 재생성(원인·해결은 [[웹한글-표-글자처럼-취급-빈-첫쪽]]). 한컴독스에 올린 옛 버전은 헷갈리니 v3처럼 버전명을 붙이고 이전 것은 지운다.
- 한컴독스 공유 링크를 그대로 열면 "문서를 열 수 없습니다"가 떴다 → 한컴독스 홈에서 문서 카드로 연다.
- **서명 이미지**: 배경을 투명 PNG로 만들어 붙인다. 처음 크기(41×27mm)로 넣으면 표가 다음 쪽으로 밀리므로 **16×10.4mm, 배치 '글 뒤로'**로 줄여 (인) 자리에 올리고, 오른쪽 표 테두리에 걸리면 몇 mm 왼쪽으로 옮긴다.
- **PDF 변환은 편집 화면보다 표가 길어진다**: 화면 5쪽이 PDF에서는 6쪽(서식 1 표가 2쪽으로 밀림) → 내용요약 줄 수와 빈 줄을 줄여 다시 받고 최종 PDF의 쪽수·서명 위치를 눈으로 확인. 접수 양식이 HWP·PDF만 허용하면 PDF로 내고 쪽수 제한(예: A4 3쪽)을 PDF에서 센다.
- 체크 표시 `☑`는 이 글꼴에서 깨져 보임 → `■`로 대체(앞 절 `■` 규칙과 같다).
- **블라인드 심사면 파일명에 이름을 넣지 않는다**(검수에서 지적). 빌드 스크립트의 출력 경로도 함께 고치고, 문서 메타데이터(creator)에 개인정보가 없는지도 본다.
- 편집 중 크롬 확장 연결이 끊기면 한컴독스 서버 연결도 끊겨 있을 수 있어 **문서를 새로 열어 어디까지 저장됐는지부터 확인**하고, 임시 저장이 아닌 저장하기를 눌렀는지 본다.

## hwpx 직접 편집·구형 hwp 텍스트 추출·서명 자동 삽입 (2026-11-23 보충)
- **hwpx 직접 편집**: `Contents/section0.xml`을 lxml로 고치고 **고친 문단의 `linesegarray`는 지운다**(줄 배치가 다시 계산됨). 글자 크기를 바꾸려면 `header.xml`의 `charPr`를 복제해 새 id로 쓴다. zip 재조립 때 `mimetype`을 맨 앞·무압축으로 (위 검증 체크).
- **구형 .hwp(5.0 바이너리)**: 텍스트는 olefile + zlib으로 뽑는다(record tag 67 = PARA_TEXT). 직접 편집은 어려우니 한컴독스에 올려 고치는 편이 낫다.
- **서명 자동 삽입(Claude in Chrome, 탭 간 클립보드 복사는 시스템 클립보드 때문에 실패)**:
  1. 서명이 이미 있는 문서 탭에서 JS로 서명 `<img>`(blob)를 찾아 base64로 바꿔 `localStorage`에 저장 — 같은 출처(webhwp.hancomdocs.com)라 다른 탭에서 읽힌다.
  2. 대상 탭에서 서명 줄 끝에 커서를 두고, JS로 `File`+`DataTransfer`를 만들어 `#ImeWrapper_Elm`에 `ClipboardEvent('paste')`를 보내면 그림이 들어간다.
  3. 개체 속성: 크기 약 18×13.4mm, '글 뒤로', 세로는 **종이 기준**(문단 기준은 음수 값이 안 먹음), 가로는 문단 기준 약 146~149mm.
  4. **표 칸 안에서 서명이 계속 안 보이면** 글 뒤로 대신 **'글자처럼 취급'** 으로 줄 안(이름 바로 뒤)에 넣고 크기만 맞춘다. 서명이 쪽 끝에 걸려 다음 쪽 칸으로 밀리면 '쪽 영역 제한' 해제 후 위치를 다시 잡는다.
  5. 끝나면 `localStorage`의 서명 데이터를 지운다.
- **PDF는 한컴독스에서** 받는다(파일 → 다운로드 → PDF). 이 PC에서 변환하면 지정 글꼴 맑은 고딕이 나눔고딕으로 바뀐다. 받은 PDF의 글꼴 포함 여부까지 확인.
- **긴 주소·긴 칸은 줄이 넘어가 아래 서식을 다음 쪽으로 민다** → 주소 앞쪽 빈칸·상자 안 빈 줄을 줄여 서식당 1쪽(전체 3쪽)에 맞춘다. 칸에 안 들어가는 작품 설명은 칸에는 요약만 넣고 **별첨 PDF(A4 1장)** 로 뺀다(공고가 허용하는 경우).
- **오래 열어 둔 탭은 서버 연결이 끊겨** 거기 입력한 주소가 저장되지 않았다 → 끊긴 탭은 닫고 새로 열어 저장 여부부터 확인.
- 개인정보(생년월일·연락처·이메일·주소)는 사용자 확인 후에만 채운다. 다른 서식의 값을 복사해 넣으려다 권한 검사에 막힌 적이 있어, 사용자가 "같은 걸로 넣어"라고 명시한 뒤 입력했다.

## 서명·그림 삽입 추가 확인 (2026-11-22~23)
- **상충하는 정보**: 위 "서명 이미지" 절은 투명 PNG를 권했지만, 이번엔 **투명(알파) PNG가 한컴독스에서 안 보였고**, 표 칸 안의 '글 뒤로' 그림도 안 보였다 → 흰 배경 원본 PNG를 '글자처럼 취급'(약 14×10.4mm)으로 넣어 해결. 표 밖 문단 위에 올릴 때만 투명 PNG·글 뒤로가 통했을 가능성(Claude 보충, 구분 실험은 안 함).
- 서명 줄을 찾기 검색으로 이동한 뒤엔 **End가 캐럿을 안 옮긴다** → 글자를 직접 클릭해 캐럿을 둔다. 줄 앞 공백이 많으면 XML에서 줄여 한 줄로 맞춘 뒤 이름 바로 뒤에 붙인다.
- 포스터·도안 그림은 도구 모음 '그림' → 대화상자의 file input에 업로드 → 넣기. 9:16 도안은 높이 90.5×너비 50.9mm 정도로 한 쪽에 맞췄다.
- 서식의 빨간 안내 글자는 `charPr`를 복제해 검정으로 바꾼다.
- **Claude in Chrome 도구 제약**: `file_upload`는 세션이 허용한 디렉터리 밖 파일을 거부 → 허용 디렉터리(예: 작업 폴더 하위 `upload_pps/`)로 복사해 올린다. Gmail 초안은 `mail.google.com/mail/u/1/?view=cm&fs=1&to=…`로 열며 **u/0·u/1이 계정 순서**라 개인 계정이 어느 쪽인지 확인(여기선 u/1=개인, u/0=학교).
- OnlyOffice(x2t)는 대체 글꼴(나눔고딕)로 렌더하므로 맑은 고딕 PDF는 만들 수 없다 → PDF는 한컴독스(파일 → PDF로 다운로드).

## 구형 .hwp 공고 양식을 한컴독스에서 직접 채우기 (2026-11-24, FiPA·낚시문화)
- .hwp는 변환(다른 형식으로)이 안 돼서 **한컴독스에 올려 칸마다 붙여넣기**로 채우고, 제출용은 **파일 → 다운로드 → 한글(hwp)** 로 받는다(공고가 hwp를 요구할 때). 칸이 여러 서식·붙임으로 묶인 한 파일이면 붙임별 쪽 범위(예: 7·9·10·11쪽)를 먼저 확인하고, 해당 분야 칸은 ■로 표시.
- 서식의 **안내용 파란 글자**는 붙여넣은 뒤 글자색을 검정으로 바꾸고(기울임도 해제), 칸 선택 → 글자 모양을 칸마다 맞춘다.
- 표가 통째로 2쪽으로 밀리면 표 속성의 **"한 쪽에 다 안 들어가면 다음 쪽으로 나뉨"** 으로 바꿔 최대 쪽수(2쪽) 안에 맞춘다. 반대로 위쪽 표 속성이 "나뉘게"로 이미 돼 있으면 그대로 두고 칸 내용만 채운다.
- 붙여넣기가 안 먹는 칸(작품명 등)은 **직접 타이핑**. 칸 맨 위 제목 줄이 화면에서 안 보이면 문서를 다시 열어 실제 배치를 확인.
- 메뉴를 잘못 열었을 때가 많아 한 단계씩 화면을 확인하며 진행. 개인정보·서명·동의 칸은 비워 두고 사용자 몫으로 남긴다.
