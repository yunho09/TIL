# 공모전 양식 채우기 — hwpx 수정 검증, xlsx 가독성, OnlyOffice 렌더링 확인

한글·엑셀 프로그램 없이 제출 양식(hwpx, xlsx)을 스크립트로 채울 때의 방법과 검증 요령. 핵심: **hwpx는 zip+XML이라 파이썬으로 채울 수 있고**, 직접 열어 보지 못하는 레이아웃은 OnlyOffice 변환 엔진으로 PDF를 뽑아 확인한다. 한글에서의 실제 모양은 끝까지 미검증임을 명시한다.

## hwpx 채우기와 무결성 검증
- 바이너리 hwp는 못 다루므로 사용자가 hwpx/docx로 변환해 줘야 함.
- 채운 방식: `Contents/section0.xml`의 빈 칸에 `【직접 입력】` 표시(개인정보·서명 칸은 임의 기입 금지), 체크박스는 건드리지 않고 지원 형태만 "□ 팀단"→"■ 팀단".
- 안내문("※ … 기재")이 이미 든 칸은 안내문을 지우지 않고 앞에 표시만 넣는다.
- 검증 체크: `zipfile.testzip` 통과 / `mimetype`이 **맨 앞·무압축** / 항목 순서·압축 방식이 원본과 동일 / 바뀐 항목이 `section0.xml` 하나뿐 / 모든 XML이 `xml.etree`로 파싱 / 텍스트 diff가 의도한 칸만 / 동의·미동의 체크박스 원형 유지.
- 스크립트는 `python3 -I`로, 원본 복사본(`_original`) 밖에서 실행해 원본을 보호.
- 한계: 글자가 늘어난 칸의 줄바꿈·서명 줄 정렬은 한글로 열어야 확인 가능 → 체크리스트에 남김.

## xlsx 긴 글 가독성
- 잘림의 주원인은 **한글 폭을 반영하지 않은 행 높이 계산**. 한글 기준으로 다시 계산해야 한다.
- 엑셀 행 높이 상한은 **409pt**. 긴 본문은 여러 행을 세로 병합한 한 칸에 넣고, 복사할 프롬프트 전문도 한 칸에 통째로 둔다.
- 셀 안에 `|`로 그린 표는 깨져 보이므로 `▶ 소제목`, `• 항목`, `①②` 번호 목록으로 바꾼다.
- 한 행에 한 문항 구조를 지켜야 하는 시트(응답 250행)는 행을 나누지 않는다. 한 행 최대 높이보다 긴 답(250행 중 105행)은 일부만 보이고 전체는 수식 입력줄에서 보이므로 맨 위에 안내 한 줄을 적고, 머리글·질문 열은 틀 고정, 모델 원본의 `**`·`##` 기호는 원 응답 보존을 위해 그대로 둔다.
- 이미지 위 설명 칸은 몇 px만 모자라도 마지막 줄이 그림에 가리므로 여백을 둔다.

## OnlyOffice로 렌더링 확인 (데스크톱 화면 조작 불가일 때)
- 화면을 못 열면 OnlyOffice 변환 엔진으로 PDF를 만들어 이미지로 바꿔 본다(화면 렌더링과 같은 엔진). 글꼴 목록 파일 `AllFonts.js`를 찾아 지정해야 변환이 되는 경우가 있었다.
- xlsx는 PDF가 **첫 시트만** 담기므로 시트별 복사본을 만들어 각각 렌더링하고, 한 페이지에 다 들어와 글자가 작으면 해상도를 올려 칸 경계를 확대한다. hwpx 확인에도 같은 방법 사용 가능(래퍼 스크립트 `tools/oo_convert.sh`).
- 윈도우 엑셀은 맑은 고딕 줄 간격이 더 넓어 다르게 보일 수 있어 아래 여백을 일부러 남긴다. 근사치임을 보고에 밝힌다.
- 한글 파일명에서 OnlyOffice가 죽는 문제는 [[OnlyOffice-한글-파일명-크래시-fontconfig-캐시]] 참고.
