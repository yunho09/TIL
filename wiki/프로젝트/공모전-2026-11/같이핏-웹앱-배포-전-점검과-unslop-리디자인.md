# 같이핏(공공데이터 공모전 웹앱) — 배포 전 점검과 unslop 리디자인

한국체육산업개발 공공데이터 공모전용 웹앱 **같이핏**(React+TS+Vite, 정적 앱)을 Vercel에 공개 배포하기까지의 판단과, `unslop` 스킬로 "AI 티"를 줄이는 과정에서 다듬기 모드와 전체 리디자인 모드의 차이를 정리했다. 핵심은 **원본 공공데이터에 개인 실명이 섞여 있어 배포 전에 가렸다는 것**, 그리고 **기획서 원고가 실제 상태(배포 완료)와 어긋난 채 docx로 옮겨질 뻔했다는 것**이다.

## 배포 전 점검
- 공개 배포·커밋은 사용자 승인 후에만 진행. 승인 뒤 Vercel CLI(기존 로그인 사용)로 **빌드 결과물만 담은 배포 폴더**를 올려 `https://gachi-fit.vercel.app`(운영) 배포. 로그인 없이 200 응답과 데이터 파일 정상 수신까지 확인.
- **강사 실명 가리기**: 원본 강좌명에 `*이형석 강사`처럼 실명이 들어 있던 11곳을 데이터 빌드 단계(`maskPersonNames`)에서 `*○○○ 강사`로 치환. "담당강사", "강사/공지사항참조" 같은 **이름이 아닌 말은 그대로** 두고, 이 규칙을 테스트로 고정(테스트 72→74개). 공공데이터 원문이어도 공개 서비스 화면에는 개인 식별 정보가 그대로 노출되므로 배포 전에 결정할 사항.
- 배포 직전마다 빌드 결과물에서 **실명·전화번호·이메일·API 키**가 없는지 다시 훑음(재배포 때마다 반복).
- 기획서의 소스 저장소 칸은 "비공개 보관, 수상 시 원천 소스 제공(참가 서약서 6항)"으로 기재 — 수상 시 소스 제공 의무와 맞춘 것.

## 기획서 원고와 실제의 불일치
- 원고 5장에는 "GitHub Pages 또는 Cloudflare Pages, 11/13~11/26 배포 예정"이 남아 있었으나 실제로는 이미 Vercel 배포 완료. docx 생성을 맡긴 에이전트가 불일치를 짚었고, 원고 9곳을 사실대로 고친 뒤 docx를 재생성했다.
- 교훈: 계획 시점에 쓴 원고는 진행에 따라 낡는다. 문서 변환 전에 원고의 일정·호스팅 같은 **현재 상태 서술을 실제와 대조**한다.
- 원고 숫자 정합: 앱에서 센 아이 강좌는 196개, 조사 문서는 194개 — 강좌명의 "청소년"으로 분류한 2개 차이(자세한 건 [[공모전-2026-11-공고-재확인-차이와-사전조사]]). 앱 정의대로 196개로 통일.

## unslop: 다듬기 모드 vs 전체 모드
- 처음엔 **다듬기(polish) 모드**: 점검 결과 보라 그라데이션·이모지·글로우·반복 애니메이션이 원래 없어 색·글꼴·구성은 유지하고 손질만 했다.
  - 굵기 700 30곳 중 5곳만 600으로 남기고 나머지 500, 4px 격자에서 벗어난 간격 79곳 정렬, 작은 글자 음수 자간 0, 조건 칩 알약→공통 둥글기, 10px→11px, 짧은 문구 끝 마침표 제거(7곳), 강좌 카드의 진한 요일 칸·배지 3개를 조용하게.
- 사용자가 "AI 냄새 뺀 거 맞음?"이라며 다른 모드를 요구 → **전체 리디자인(A안: 수영장 강습 시간표 게시판)**. 먼저 다듬은 버전을 `_backup/`에 백업해 되돌릴 수 있게 했다.
  - 방향 5줄(제품·성격·세계·빛나는 곳·표식)을 먼저 적고 9단계(간격→색→아이콘→문구→글꼴→배치→세부→시각→움직임) 순서로 진행.
  - 바탕은 거의 회색 중성 램프, 청록은 선택·주요 버튼·핵심 숫자에만, 노랑은 아이 강좌 표시에만.
  - 큰 카드 목록 → **표 줄**(시각|강좌|요일|수강료|담기), PC에서 강좌 하나 높이 약 268px→105px. 시각·금액·정원은 IBM Plex Mono 고정폭. 빈 시간 그리드는 개별 둥근 타일 → 요일별 이어진 레인 한 장. 겹침 막대는 아이·나·겹침 3레인.
  - 움직임은 곡선 하나로 통일, 반복 애니메이션 없음, `prefers-reduced-motion` 유지.
- **"말로만 정리"를 피하는 검증**: 고치기 전/후 스크린샷을 같은 화면으로 나란히 붙여 보여 줌(`docs/compare/`). 테스트 74개·타입 검사·빌드는 에이전트 보고를 믿지 않고 직접 재실행.
- 남은 한계: 375px에서 표 한 줄이 4~5줄로 접힘(기준월·이력 같은 메타를 빼지 않아서), 1280×860에서 '빠르게 칠하기' 줄이 첫 화면 아래로 걸침. 사용자가 실제 폰에서 "잘 보여"로 확인(사용자 확인 기준).
