# 공모전 찾기 도구 설계 — 수집 제한·AI 판독·근거 검증

AI 불씨 트랙2용 "공모전 찾기 자동화" 도구(`4-ai-bulssi/tool/`)의 설계 결정 모음. 사이트 약관·robots 제약 때문에 **2곳만 자동 수집 + 7곳은 링크·체크리스트**로 구성했고, Claude Haiku 5.5가 공고 상세에서 조건을 뽑되 **근거 문장이 원문에 실제로 있는지 코드로 재검증**한다. 도구가 전후 측정(Before/After)의 After 기록까지 남긴다.

## 수집 범위와 예의
- 자동 수집: **위비티·콘테스트코리아**만. 나머지 7곳은 약관·robots·기술 차단 때문에 수집하지 않고 바로가기+"오늘 확인함" 체크 칸만 둔다 ([[공모전-2026-11/공모전-2026-11-공고-재확인-차이와-사전조사]]).
- 실행마다 robots.txt를 새로 읽고 막힌 경로는 건너뜀
- 요청 간격 기본 2.5초, **코드상 2초 아래로 못 줄임**
- 목록은 사이트당 최대 4쪽, 새 상세는 사이트당 20건(최대 30건). 한 번 받은 상세는 재요청 안 함 → 같은 날 재실행 시 수집 요청 0회
- 리디렉션은 따라가지 않음. 빈 응답·202·403·429·503이 오면 **그 사이트는 그날 중단**하고 재시도 안 함
- 저장 전 이메일·전화·담당자 이름·문의/주소 줄 제거
- User-Agent는 브라우저 문자열 뒤에 도구 이름(`contest-finder/0.1 (personal; non-commercial)`)만 덧붙임 — 개인정보 없음
- 팀원 3명이 각자 돌리면 사이트 요청도 3배 → **한 사람 컴퓨터에서만** 실행

## AI 판독
- 모델 `claude-haiku-5-5`, 공식 TS SDK `messages.parse` + `output_config.format`(zod 스키마)로 구조화 출력. 뽑는 항목: 고등학생 참가 가능 여부(+근거 문장), 상금, 마감, 팀 인원, 제출물, 분야
- **근거 문장 검증**: AI가 댄 문장이 원문에 글자 그대로 있으면 화면에서 형광펜, 없으면 "못 찾음" 표시. 시험 5건에서 근거 23개가 모두 원문에 존재
- 판독 결과는 캐시. 판독 프롬프트를 고치면 `PROMPT_VERSION`을 올려 다음 판독 때 다시 읽게 함
- 판독 코드는 모델 거절(`refusal`)을 처리해야 함 (Fable/Opus/Sonnet 5.5 계열 공통 주의사항)
- API 키는 `.env`에서만 읽고 접속 주소를 `https://api.anthropic.com`으로 고정, 도구 폴더 전체에 키 흔적이 없는지도 검사

## 비용 통제
- 호출 전 예상 비용 출력, `--yes` 없으면 **dry-run**(호출 안 함)
- 최대 예상 비용이 `--max-usd`(기본 $0.30)를 넘으면 `--yes`를 붙여도 호출 거부
- 시험 5건 실측 $0.0054 (입력 23,715·출력 6,128 토큰, 그중 생각 4,281) → 1건 약 $0.0011. Haiku 5.5 $0.10/$0.50 per MTok로 재계산해도 일치(usage×요금 계산값이지 청구서 확인은 아님)
- 처음 비용 어림이 입력 토큰을 실제의 절반으로 잡아 5건 실측에 맞춰 보정 → 지금은 실제보다 2.6% 높게 잡음. **어림식은 실측으로 보정해야 한다**는 사례

## 판단 기준을 사람과 도구가 맞추기
- 도구 AI는 금액이 적힌 상품권도 '상금 있음'으로 판독. 전후 비교가 공정하려면 Before를 손으로 잴 때와 같은 기준이어야 해서 **"상금 있음 = 금액이 적힌 현금·상품권·장학금 중 하나라도 있음, 상장·트로피·금액 없는 물품만이면 없음"**으로 확정(사용자 결정). 코드는 안 바꾸고 측정표·README·스토리보드에 같은 정의를 적음
- 도구 기본 필터도 Before 측정표와 동일: 마감 14일 이상 + 고등학생 가능 + 상금 있음
- '본 공고 수'는 근거를 펼쳤거나 원문을 열었거나 후보로 담은 공고만 세므로 Before와 세는 방식이 다를 수 있음 → 영상·양식에 정의를 함께 적어야 함

## 영상·측정 순서 함정
- 도구가 Before 측정보다 먼저 만들어졌으므로 영상에서 "측정한 다음에 만들었다"고 말하면 거짓 — 스토리보드 주의사항에 적음
- **Before는 도구 화면을 열기 전에** 9곳을 손으로 재고 화면 녹화(지어낸 값·가짜 수치 금지, 영상 숫자는 측정 전까지 【측정 후 입력】 자리표시)
- After 기록: '확인 시작'→'확인 끝'으로 걸린 시간·본 공고 수·고등학생 가능 확인 수·후보 수·클릭 수를 남기고 CSV 내보내기. 7곳은 사람이 센 값을 적고 비우면 합계에서 제외

## 구현 중 만난 버그와 한계
- 확인 중일 때만 7곳 체크 칸 클릭이 안 먹던 버그: 클릭 수 세는 코드가 클릭 도중 화면을 다시 그려서였고, 클릭 처리가 끝난 뒤에 세도록 수정
- sites.md는 "본문 전체 저장 안 함"이었지만 판독·캐시에 본문이 필요 → 연락처 제거본을 최대 8,000자까지 로컬 `data/` 캐시에만 두고 마감 30일 후 삭제, 화면엔 근거 문장만. `data/`는 커밋·공유 금지
- 한계: 목록 앞 1~2쪽만 봄, 위비티는 사이트의 '청소년·제한없음' 표시에 의존, 파서는 2026-11-13 마크업 기준(사이트가 바뀌면 수정), 하루 1회 자동 예약은 없음
- 테스트 78개·타입 검사·빌드 통과(2026-11-15 재실행 확인). 실행: `npm run daily -- --yes && npm run app` → `127.0.0.1:5180`(이 컴퓨터에서만)
