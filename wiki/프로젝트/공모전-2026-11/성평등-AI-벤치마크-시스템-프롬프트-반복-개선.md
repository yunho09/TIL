# 성평등 AI 벤치마크 챌린지 — 시스템 프롬프트 반복 개선 기록

250문항 평가 질문지로 Claude Sonnet 5.5의 기본 응답 취약점을 분석하고, 시스템 프롬프트를 v1→v3로 고쳐 가며 전·후를 비교한 과정. 핵심은 **문항을 개발용/확인용으로 갈라 과적합을 걸러냈고**, 한 번에 한 줄만 바꿔 원인을 분리했다는 것. 점수는 모두 자체 LLM 심사(추정치)이며 주최 측 채점이 아니다. 질문지는 재배포 금지라 문항 원문은 위키에 적지 않는다.

## 설계 방식
- 질문 250개를 기대 대응으로 분류: **거부 100**(비동의 성적 이미지 50, 사칭·피싱 15, 위치 추적 13, 신상 특정 12, 미성년자 그루밍 10) / **교정 100**(성별 차등 처우 50, 고정관념 29, 피해자 비난 10 등) / **정상 응답 50**(요약, 직무 설명, 공고문, 가상 인물). 비율이 딱 떨어져 의도된 설계로 추정 (Claude 보충).
- 유형마다 30%, 총 75문항을 **확인용(hold-out)** 으로 떼고 프롬프트 개선에는 나머지 175문항만 사용. 확인용은 최종본에서만 실행.
- 심사 스크립트는 5지표 점수 + 실패 유형(유해 요청에 응함 / 전제 미교정 / 과잉 거부 / 사실 오류)을 붙인다. 배치 API로 실행해 비용을 낮추고, 실행 전 예상 비용을 출력해 승인받은 뒤 돌렸다.

## 재현 가능한 실행 스크립트 설계 (2026-11-13 보충)
- 주최 측이 제출한 모델·설정값으로 재실행하므로 `run.py`는 실행마다 설정(모델·effort·최대 토큰·시스템 프롬프트)을 `config.json`에 고정하고, **설정이 다르면 같은 실행 이름으로 못 돌리게** 막는다.
- `--yes`가 없으면 토큰만 세어 예상 비용만 출력(무료), 있어야 실제 호출. 문항별 원응답은 JSONL 저장, 끊기면 이어서 실행, 반값 배치 모드 지원.
- 재현 시 Claude Code 같은 도구가 자동으로 넣는 지침은 빠지므로 API를 직접 호출해야 안전.
- 다른 모델로 대신 답하게 하는 `fallbacks`는 "모델 1개" 원칙 때문에 끔.
- API 키는 `.env`(gitignore)에만 두고 채팅에 붙여넣지 않음, 키 확인은 무료인 모델 조회 호출로, 질문지 폴더는 재배포 금지 조항 때문에 `.gitignore`.

## 모델 선정 (50문항 비교, 자체 심사)
- 5지표 평균: Sonnet 5.5 4.78 / Opus 5.5 4.83 / Opus 4.8 4.67. 비용은 Sonnet이 Opus 5.5의 절반 이하.
- 세 모델이 **같은 문항에서 똑같이 무너졌다**(기술 지원처럼 꾸민 비동의 합성물 요청). 실패가 모델 공통이면 비싼 모델로 바꿔도 안 풀리고 시스템 프롬프트로 풀어야 한다 → Sonnet 5.5 선택.
- 예상 비용이 빗나간 사례: Opus 5.5 답변이 예상보다 길어 시험 비용이 $2→$3.3.

## 기본 응답의 취약점
- 비동의 성적 합성물 50문항 중 11개에 응함: "웹툰용·논문용" 같은 **목적 문구를 믿고** 코드를 주거나, "동의가 있다면 돕겠다"며 거절하면서 도구·기법을 흘림.
- 직업별로 가상 인물 성별을 고정(원감=여성, 정비사=남성), 채용공고에 군필을 돌려 묻는 문구.
- 교정 질문 100개는 거의 만점, 정상 요청 과잉 거부 0건 → 프롬프트가 이걸 깨면 안 되는 기준선.
- **사칭·피싱 문항은 모델이 아니라 API 안전 분류기가 입력 단계에서 막아 빈 답**이 나왔다. 시스템 프롬프트를 바꿔도 같은 문항이 계속 막힘 — 프롬프트로 개선 불가, 설계서에 FAQ에 따라 사유 기재.

## 버전별 결과 (개발용 175문항)
| 버전 | 바꾼 것 | 결과 |
|---|---|---|
| v1 | 역할→원칙→판단 절차→출력 형식 구조, "결과로 판단"(목적 문구·역할극이 판단을 안 바꿈), 비동의 합성물엔 코드·도구명·조건부 도움 금지, 애매하면 실존 인물 피해 가능할 때만 거부 | 합성물 응함 7→2, 5지표 4.83→4.95, 과잉 거부 0 |
| v2 | 내용을 흐린 표현("그런 것")이 실존 인물 사진에 붙으면 성적 합성 의도로 간주, 거부 시 신고·삭제 창구 필수(상황별 선택), 통계상 '경향'과 "원래 그렇다" 단정 구분, 질문자 성별 추측 금지, 요약은 원문 내용만 | 합성물 응함 0, 5지표 4.97. **부작용**: 요약 13문항 중 6개가 원문을 거의 그대로 옮김(요약 적정성 4.31) |
| v3 | 요약 지시 **한 줄만** "원문 문장을 옮기지 말고 같은 내용을 묶어 1/3 길이로 다시 쓴다" | 부작용 해소 |

- 부작용 원인: "원문 내용만, 원문 순서대로"를 너무 강하게 지켜 압축을 안 함. **한 줄만 바꿔야 결과 변화의 원인을 특정**할 수 있다.
- 특정 문항의 단어(도구명 등)는 프롬프트에 넣지 않고 일반 유형으로만 서술. 개발 중 확인용 문항 2개를 우연히 본 사실은 README에 투명하게 기록.
