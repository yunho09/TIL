# 공모전 제출 운영 — 복수 출품 메일 규정과 커밋 해시 관리

현대 차량용 앱 공모전 제출 마감 당일에 겪은 운영 문제들의 정리다. 복수 작품을 한 팀이 낼 때 메일 규정의 함정, 공개 저장소 전환 전 개인정보 점검, 기획서-앱 불일치 점검 방법을 남긴다.

## 복수 출품과 메일 규정
- 공식 공고·FAQ·참가 규정에는 **작품 수 제한도, 복수 출품 허용도 문구가 없다**. 금지는 아니지만 "된다"고 확정할 근거도 없다 → 사무국 답변(문의 기록)으로 확인해야 한다. (세션에서 "가능"이라는 앞선 단정은 공식 근거 없이 계획을 사실처럼 받아들인 실수였다.)
- 위험 규정: "여러 번 제출하면 **마감 전 마지막 제출본을 최종**으로 심사", 양식 안내의 "같은 발신자가 마감 전 최종 발송한 제출물로 심사". 한 사람이 3통을 보내면 2·3번째를 1번째의 수정본으로 오해해 마지막 작품만 남을 수 있다.
- 메일 하나에 3작품을 합치는 것도 공식 근거 없음. 제목에 작품명 칸이 없고("팀명_대표자명") 1통 = 접수 1건 전제라 **작품마다 따로 보내는 쪽이 안전**.
- 완화책:
  1. 제목 끝에 작품명(`…_대방어_남우현_쉼표`), 최초 제출에는 `[수정제출]` 절대 금지
  2. **본문 첫 줄 안내**: "서로 다른 작품 3개를 각각 출품합니다. 이 메일은 「○○」 출품이며 다른 두 메일의 수정본이 아닙니다."
  3. 메일마다 그 작품 양식 1개만 첨부, 참조에 팀원 전원
  4. 발신자 = 양식의 대표자가 되도록 (대표자가 다르면 어긋남). 더 확실하게는 작품마다 대표·발신자를 다르게 하는 방법이 있으나 서명 양식을 다 고쳐야 한다.
- 수정 제출 때는 `[수정제출] [차량용 앱 개발 공모전] 팀명_대표_작품명`처럼 작품명까지 넣는다.
- 고등학생 참가: 원본 양식에는 보호자 동의서 등 관련 문구가 없고 참가 부문은 대학(원)생/일반 둘뿐 (사무국 답장 원문은 기록 없음 → 확인 필요).

## GitHub Public 전환 전 점검
- 점검 항목: 키·비밀번호·Client ID가 기록 전체에 있는지, `local.properties`·서명 키 미커밋, 팀원 실명, **커밋 작성자 이메일**.
- 커밋 4개가 개인 Gmail로 되어 있었다 → `<ID>+<user>@users.noreply.github.com`으로 작성자를 다시 쓰고 `main`에 force push 후 Public 전환. 코드 diff 0줄이지만 **모든 커밋 해시가 바뀐다.** 이 저장소의 `user.email`도 noreply로 설정.
- 남는 위험: GitHub는 옛 커밋을 **전체 해시를 아는 사람에게는** 계속 보여 준다. 완전 삭제는 GitHub Support에 캐시된 커밋 제거 요청.
- 원본 양식이 "링크에 계정정보·개발자 실명이 드러나지 않게" 하라고 해도, 저장소를 내는 이상 계정명은 노출된다.
- 가산점 조건: 11/16까지 Public → 11/23까지 유지 (비공개로 되돌리면 가산점 없음).

## 최종 커밋 해시 연쇄 관리
- 해시는 **기획서 7번, 메일 본문, 공유 문서**에 박히므로 저장소를 커밋할 때마다 세 곳을 다시 고쳐야 하고, 이미 팀원에게 보낸 양식도 재배포가 필요하다 (이번에 해시가 4번 바뀜).
- 규칙: 제출 메일이 나갈 때까지 저장소는 **동결**하고, 미룬 변경(스크립트 등)은 제출 후 커밋. 영상·APK 같은 산출물은 모두 확정한 뒤 마지막에 한 번만 커밋.
- 팀원에 알릴 때는 바뀐 줄만 "이 두 줄만 교체" 형태의 짧은 수정 메시지로.

## 기획서와 앱 내용 불일치 점검
- 기획서가 앱보다 앞서가기 쉽다. 음성 문구·화면·설정값을 앱 코드에서 뽑아 **문장 단위로 대조**한다. 이번에 15곳이 달랐다 (자동 차종 인식 → 설정에서 선택, 공조 약풍 → 22℃·외기 유입만, 정체 감지 → 앱은 정체를 모름, 백색소음 로컬 파일 → 브라운 노이즈 직접 생성, 백그라운드 동작 → 앱이 떠 있을 때만).
- 아직 앱에 없는 기능은 삭제 대신 **"다음 단계/계획"으로 표시**. 실측하지 않은 성능 수치(CPU·RAM)는 **"목표"** 라고 명시. 출처 확인 못 한 통계는 "추정"으로.
- 서명 확인: 서명이 연한 회색 글자처럼 보이면 손글씨로 다시 받고, 작성일과 서명일자가 서로 다르지 않게 맞춘다.
- docx 수정은 XML을 풀어 고치고 XSD 검증 + PDF 렌더로 눈 확인 ([[공모전-양식-채움-검증-hwpx-xlsx-OnlyOffice-렌더링]]).
- 시연 영상: 자막을 `.srt` 별도 파일로만 두면 플레이어가 자동 로드하지 못한다(파일명 불일치, ffmpeg 없음) → 영상에 직접 입히는 편이 안전. 화면 끊김은 녹화가 아니라 에뮬레이터 렌더링이 원인이었다 ([[쉼표-Pleos-에뮬레이터-CLI-설치와-SDK-실측]]).
