# BeforeAI "AI 작업 승인 플랫폼" 프론트 설계 결정

직원이 프롬프트를 쓰면 AI가 작업 단위 Plan으로 나누고 위험도·승인권자를 보여 주며, 권한 있는 사람이 **Plan 해시에 서명**해 승인해야만 실행되는 서비스(해커톤 출품)의 프론트 작업에서 내린 결정과 근거. React 19 + TS + Vite + Tailwind v4 + TanStack Query, API 명세 모양을 따르는 목 API(`mockFetch`, localStorage 저장)로 백엔드 없이 전체 시연이 가능하게 만들었다. 서버 붙이기는 [[BeforeAI-FE/실서버-연동-계약-불일치-CORS-내부망]].

## 구조 용어
- **실행기 → 웹쉘 통합**: 옛 명세의 실행기(Plan 해시·서명을 재검증하고 통과하면 실행)는 "금고 앞 경비원", 웹쉘은 "금고 안 작업자"였는데 새 명세에서는 **웹쉘이 검증과 실행을 모두** 한다. 웹 서비스가 뚫려 Plan을 바꾸거나 승인을 지어내도 내부에서 걸러 낸다는 원칙은 동일. 목 구현은 복호화·해시 재계산·서명/키 소유자·nonce·필수 승인자·금지 규칙·세션 고정을 검사.
- 실제 구현은 JCS + SHA-256 + Ed25519, HPKE와 기기 키 저장은 문서화된 목.

## 승인 문서(전자결재) 설계 — 나중에 도입 (사용자 확정: 요청 전엔 만들지 않음)
- 흐름: 승인 상세에서 "결재 문서 미리보기"(A4 모양 화면) → 승인(서명) 시 결재란에 도장 → 승인 후 PDF 내려받기. 미리보기는 PDF 파일이 아니라 PDF처럼 만든 화면(스크롤·확대·도장 효과를 넣기 쉬움), 실제 PDF는 내려받을 때 생성.
- **서명 대상은 계속 Plan 해시**. PDF에 서명하는 구조로 바꾸면 "승인한 것 = 실행되는 것"이라는 강점이 약해짐. AI 설명은 참고로만 표시, "전자서명법 준수" 같은 법적 효력 표현 금지("승인 기록 문서" 정도).
- **프롬프트 하나당 문서 하나**(승인자·작업별로 쪼개면 감사 때 흐름을 못 봄). 모두 같은 문서를 보고 내가 승인할 작업만 강조, 결재란은 승인자별 칸, 담당 작업을 모두 승인하면 도장.
- PDF는 필요한 승인이 끝난 뒤부터 열리고 실행 전/후에 따라 "실행 전" 표시나 실행 결과 포함. 파일을 미리 저장하지 않고 누를 때 현재 기록으로 생성. 거부·취소도 사유와 함께 받게 하는 안을 추천(미확정). 문서번호 형식은 명세에 없어 프론트에서 만들거나 백엔드 요청 필요.
- **Plan 버전(v1/v2)**: 승인이 시작된 뒤 요청자가 Plan을 수정·삭제하면 서명 대상 해시가 바뀌므로 새 판(v2)을 만들고 도장을 다시 받는다. 판을 안 나누면 "승인한 적 없는 내용이 승인된 것처럼" 남는다(계약서 내용 변조 비유). 상태 변경·도장·실행 결과 수신은 판을 올리지 않고, 이전 판은 "대체됨"으로 열람만. 바뀐 작업만 재승인인지 전원인지는 현재 동작 확인 필요(미확정).

## 진행 트리·감사 로그 내보내기 (노션 확정 기능)
- 진행 상황 트리: `GET /requests/{id}/progress`, SSE `/progress/stream`(`node.updated`·`node.added`·`tree.replaced`·`heartbeat`, `Last-Event-ID`). 화려한 색 대신 "지금" 한 문장·흐르는 경로·웹쉘 검증 관문처럼 **기능으로 이목을 끄는** 방향. 서버가 주지 않는 필드는 기본값으로 낮추되 거짓 "통과"는 표시하지 않음.
- 감사 로그 내보내기(CSV·XLSX): CSV는 BOM, XLSX는 `fflate`(목 전용), 수식 주입 방지로 `= + - @` 및 앞쪽 공백/제어문자 뒤 접두사까지 차단, 10만 건 제한, 요청자 본인만, 1시간 만료, 내부망 전용.
- 시연 임팩트용으로 고른 것: 변조 시연 페이지(Plan을 바꾸면 웹쉘이 거부)와 도장 효과.

## 디자인 방향의 변천 (사용자 피드백 반영)
- 너무 빽빽 → "안에가 너무 복잡" → 화면마다 **한 가지 주인공**, 나머지는 접기, 큰 글자. 예상 변경은 코드 diff가 아니라 말로 풀어 "어디가 뭐가 된다"로 설명, "누가 영향받나요" 카드를 상세 화면에서 집중해 보여 줌.
- "AI 티 난다" 피드백 → 실제 사이트(GitHub Actions·Linear) 참고한 "정리된 문서 도구": 흰 바탕, 옅은 사이드바, 1px 선, 파란 포인트 하나(`#0b5cd5`), 상태는 기호+색 글자, 트리 노드는 납작하게 왼쪽 상태 선. 도장 잉크색(`#c8321e`)은 도장에만.
- 로그인: 첫 버전(좌 소개 + 우 폼)이 좋다는 판단, 단 "너무 심심함" → 왼쪽에 업무 기안 문서 + 결재란 도장, 움직임 제거, 사선 목재 도장 이미지(미리 렌더한 webp 46KB, `three`는 번들에 안 넣음), "너무 고퀄 아니어도 돼".
- 내부망/외부망 표시는 크게 쓰지 않고 줄임(개발 도구에서 전환).
- 공통: 반응형은 나중, 날짜는 "오늘 14:30/어제/11월 3일", 사이드바 개수는 요청 단위로 집계("외 N건").

## 작업 중 만난 함정
- **`.omc/` 같은 상태 파일이 Vite/Tailwind watcher에 소스로 잡혀 전체 새로고침 37회** → 입력 중인 폼이 지워지고 로그인 테스트 실패. `.gitignore` + `server.watch.ignored: ['**/.omc/**']`로 해결.
- `<main>`에 `relative`가 없으면 `absolute` 스크린리더 전용(`sr-only`) 요소가 문서를 늘려 이중 스크롤바가 생김.
- Playwright 영상 녹화는 ffmpeg 버전 불일치로 실패 → CDP `Page.startScreencast` 프레임 + gstreamer(`multifilesrc ! jpegdec ! videoconvert ! video/x-raw,format=I420,colorimetry=bt709 ! x264enc ! h264parse ! mp4mux`)로 MP4. `colorimetry=bt709`를 빼면 대비가 늘어나 색이 틀어짐.
- 여러 에이전트가 같은 트리를 동시에 고치면 HMR 때문에 회귀 테스트가 흔들림 → 조용한 트리에서 돌리기. 변이 검사는 통과하는 기준선에서만 유효. 에이전트는 대기 메시지를 늦게 처리해 보고가 이미 바뀐 지시를 가리킬 수 있어 트리로 확인.
- zsh: `$a`가 단어 분리되지 않음(`bash -c` 사용), `pkill -f`가 자기 셸을 죽임(`[x]` 괄호 패턴).
- 개발 서버·크롬·에이전트 여러 개가 겹치면 가용 메모리가 2.6GB(30GB 중)까지 떨어져 하니스가 백그라운드 서버를 강제 중지 — 다시 띄우기 전에 쓰지 않는 프로그램부터 닫기.
