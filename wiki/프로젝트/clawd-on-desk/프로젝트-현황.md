# clawd-on-desk — 프로젝트 현황

`clawd-on-desk`는 Electron 기반 데스크톱 펫 앱으로, `rullerzhou-afk/clawd-on-desk` 저장소에 포크 PR로 기여하는 오픈소스 프로젝트다. 로컬에는 별도 `wmctrl` 감시자를 두어 설치된 펫이 항상 떠 있게 관리한다.

## PR #980 — 리눅스 워크스페이스 전환 시 펫이 사라지는 문제 수정 (#979 관련)

- **메인테이너 요청 3가지:** ① 최신 `main` 반영 + main의 Windows 활성화 코드(`prepareActivation()`, `show:false`, `guardAlwaysOnTop` 등) 손실 없이 보존, ② 플랫폼 플래그(Windows/macOS/Linux)를 테스트에서 서로 배타적으로 분리, ③ 실제 GNOME 환경 스모크 테스트.
- **처리:** `main`을 force-push 없이 머지(`ab3c9ec2`)해 main의 `prepareActivation()`과 새 Linux 호출을 모두 `showInactive()` 앞에 배치, 플랫폼별 테스트 분리 및 메서드 부재/예외 케이스 테스트 추가(`aa7fbfc0`), GNOME에서 워크스페이스 전환·클릭/드래그·숨기기/보이기·미니 모드 복귀·재시작 스모크 테스트 통과 확인(수정 전 `main`으로도 돌려 #979 증상 재현 확인).
- **독립 코드 리뷰(별도 에이전트, 사람이 아닌 리뷰 전용 에이전트) 결과:** APPROVE. LOW 이슈 5건 중 실제로 반영한 것:
  - 헬퍼 주석이 사실과 다름 — "Linux엔 동등한 호출이 없다"는 다른 파일(`roam-fence-picker.js`)에 이미 있어 틀렸고, "macOS Spaces처럼 따라간다"도 과장(macOS `reapplyMacVisibility()`는 펫 창 2개 외에 버블/HUD/퀀텀링까지 고정함). "X11/XWayland에서만" 문구도 명확히 함.
  - 리눅스 테스트 제목이 실상과 다름 — 리눅스는 `show:false`가 아니라 기본 `show:true`로 생성됨(Windows에만 `show:false` 적용).
  - fake(메서드 없음/예외 던짐) 테스트가 실제로 fake가 적용됐는지 검증하지 않던 문제.
  → 위 3건은 `41dfe837`로 반영. 포커스 규칙 미검증, `guardAlwaysOnTop` 미검증 등은 이 PR 범위 밖(기존 main의 결함)이라 보류.
- **결정 근거:** 스모크 테스트를 실제로 통과한 커밋(`aa7fbfc0`)은 그대로 두고 리뷰 반영은 별도 커밋으로 분리 — PR 히스토리에서 "스모크 테스트한 코드 = 지금 PR 헤드"가 유지되도록.

## 스모크 테스트에서 발견해 PR 댓글에 남긴 것
- **입력용 히트 창(hit window)은 원래도 모든 워크스페이스에 떠 있었다.** WM이 관리하지 않는 override-redirect 창이라, 실제로 전환 시 사라지던 건 그림(render) 창뿐이었다. 두 창을 동일하게 다루려고 히트 창에도 호출을 남겼지만, 메인테이너가 원하면 뺄 수 있다고 열어둠.
- **포커스 부작용 (이 시점엔 미해결, 이후 `WM_HINTS`로 수정 — 아래 2차 리뷰 대응 절):** 펫이 모든 워크스페이스에 고정되면 워크스페이스 전환 시 키보드 포커스가 펫 창으로 넘어간다. 전환 직후 타이핑이 안 먹히면 이 때문. 메인테이너에게 머지 전 수정할지 별도 이슈로 뺄지 결정을 넘김. 기술적 원인은 [[Electron-워크스페이스-고정-창-포커스탈취]] 참고.

## PR #980 2차 리뷰 대응 — 포커스 부작용 수정 (2026-10-02·10-09 메인테이너 댓글)
- 포커스 부작용이 남은 유일한 머지 차단 사유였고, 고친 뒤 같은 환경에서 재테스트해 달라는 요청. main 399커밋 앞선 상태를 충돌 없이 머지.
- **수정(`1efdb7d1`):** 렌더 창에 X11 `WM_HINTS input=False`를 쓰는 Linux 전용 koffi/XCB 모듈(`src/linux-x11-input-hint.js`), `main.js`에서 주입해 `createRenderWindow`에서 적용. 창 생성 옵션·창 타입은 그대로라 메인테이너가 우려한 쌓임 순서/위치 클램핑은 불변. 원리·검증은 [[Electron-워크스페이스-고정-창-포커스탈취]].
- **검증:** 자동 A/B(main·수정 전·수정 후), 사용자 수동 확인, 전체 13,040개 중 실패 2개(main과 동일한 기존 실패), 변이 테스트 19개 전부 포착. (중간에 "14개"→"13개"로 정정한 모듈 변이 수 기록이 있음.)
- **독립 리뷰 APPROVE → 마지막 커밋 `22e65af2`에 반영:** InputHint 와이어 리터럴 고정, 실 libxcb 바인딩 테스트 강화, "보이기 전에 힌트를 쓴다"는 부정확한 문구 정정, 스킵 조건 정확화, `displayName` 연결 테스트, 오류 메시지에 has_error 코드 포함, AGENTS.md에 계약 한 줄.
- **미수정 한계:** 펫이 막 켜질 때 한 번 포커스를 잡는 현상(main도 동일). 해결 방법을 댓글에 적고 이 PR에 넣을지 메인테이너에게 질문.
- **운영 교훈:** 수동 확인 중에는 선택지 질문 UI 등으로 테스트용 펫에 말풍선을 띄우지 않는다(포커스를 가져가 측정을 오염). 자동 A/B 중에는 화면이 저절로 전환되므로 키보드를 쉰다. 수동 확인은 한 번에 한 단계씩.

## 후속: 리눅스 하드웨어 가속 끄기 스위치 (#66, 2026-10-21 준비, PR 미개설)
- 배경: #66 리눅스에서 투명 창 때문에 데스크톱 전체가 버벅임(제보자 GNOME X11+RTX 2070은 `--disable-gpu`가 효과). 오너가 Windows 전용 "하드웨어 가속 끄기" 스위치 PR #1211을 열어 둔 상태(미머지, v1.4.0에도 불포함).
- 수정(브랜치 `feat/linux-disable-hw-accel`, #1211 위에 쌓음, 6파일 +25/−16): `src/main.js` 조건 `isWin`→`(isWin || isLinux)`(앱 ready 전 실행 유지), 설정 행 표시를 `!IS_MAC`으로, 7개 언어 문구에서 "Windows 전용" 제거(6개는 AI 번역이라 PR에 밝힘), 테스트 추가. 전체 13,281개 중 실패 2개는 #1211 기준과 동일한 Electron SVG 감사 테스트.
- **GPU를 꺼도 투명 창은 유지된다:** 투명은 합성기 유무가 결정하고 GPU와 무관. 최소 프로브(Electron 41, frameless transparent, `disableHardwareAcceleration()`)로 XWayland는 창 Depth 32, `xwd` 픽셀이 그린 부분만 불투명이고 나머지 알파 0임을 확인했고, 네이티브 Wayland는 버퍼가 ARGB8888이고 opaque region이 해제됨을 프로토콜 로그로 확인(픽셀 캡처는 불가). 펫은 기본적으로 XWayland로 재실행되므로 실사용 경로는 X11. Electron v9 문서도 리눅스 투명 창에 `--disable-gpu`를 권장했고 electron#15947/#25153이 같은 우회책.
- 미확인: 이 PC(Intel Arc+XWayland)에서 gnome-shell CPU가 실제로 줄어드는지(GPU를 끄면 Xwayland/펫 CPU가 오를 수도), 실제 펫의 투명. 그래서 PR은 `Refs #66`+Draft, 드래그 끊김은 이 스위치로 해결되지 않음. 기준 브랜치는 #1211 머지 후 rebase 또는 `claude/fix-issue-1183-kezhp8`. 선별 맥락은 [[오픈소스-기여-후보-선별-기준과-AI정책-함정]].
