# Zaemit(재밋) 사이트 제작 트러블슈팅

[[Zaemit-공모전/Zaemit-MCP-연동]]으로 인증을 마친 뒤, 재밋 MCP 툴 호출만으로 실제 사이트(홈/게시판/접수폼 3페이지)를 다듬으면서 확인된 함정과 검수 방법을 모은다. 사이트는 로컬 코드가 없고 전부 `tool_invoke` 호출로만 수정하므로, 이 함정들은 재밋으로 사이트를 만드는 다른 작업에도 그대로 재현될 가능성이 높다.

## 게시판 임베드(`board_embed`)의 `data-limit`이 안 먹는 원인

재밋 게시판 프런트 스크립트 `wv-board.js`는 `data-limit`/`data-detail-page` 속성을 **`.wv-board` 루트 엘리먼트에서만** 읽는다. 그런데 `board_embed`로 발행된 마크업에서는 이 두 속성이 루트가 아니라 **제목을 감싼 안쪽 `div`**에 붙어 있었다 — 그래서 limit을 아무리 바꿔 저장해도 항상 게시글 전체(9건)가 그대로 노출됐다.

**해결**: 섹션을 지웠다 새로 만드는 대신, 저장된 블록 마크업에서 두 속성을 `.wv-board` 루트로 옮기는 것만으로 해결됨. 최근 N건으로 줄어들면 검색창·글쓰기 버튼 등 툴바도 함께 자동으로 사라진다(툴바 유무는 limit 설정에 종속).

## 검수는 curl이 아니라 실제 브라우저 렌더로

게시판·접수 폼처럼 재밋이 JS로 그리는 컴포넌트는 정적 HTML을 그대로 받아오는 `curl`/fetch로는 내용이 비어 보인다. 레이아웃 높이, 요소 겹침, 가로 스크롤 여부, 클릭 후 페이지 이동 같은 것은 실제로 브라우저를 띄워 렌더된 화면과 `document.documentElement.scrollWidth` 등의 값으로 확인해야 신뢰할 수 있다.

## 툴 인자의 한글은 리터럴로 — `\uXXXX` 이스케이프 조립 금지

재밋 MCP 툴(`tool_invoke` 등) 호출 인자에 한글 문자열을 넣을 때, 유니코드 이스케이프(`가` 형태)를 코드로 조립해서 보내면 음절이 깨져서 들어간다. 한글은 항상 리터럴 문자로 그대로 써야 한다.

## `overflow:hidden`만으로는 절대위치 장식 요소가 안 잘릴 수 있다

CTA 섹션에 `position:absolute; right:-5%` 로 배치된 장식 원(525px)이 부모 밖으로 삐져나와 문서 전체 폭을 2000px로 늘리고 있었다(뷰포트 1920px, 가로 스크롤 발생). 부모에 `overflow:hidden`만 줘서는 클리핑이 적용되지 않았고, **부모에 `position:relative`를 함께 지정해야** 그 안의 절대위치 자식이 실제로 잘렸다(`overflow:hidden`은 stacking/positioning context가 성립한 조상에서만 자식을 자른다). 적용 후 문서 폭이 뷰포트와 같아져 세 페이지 모두 가로 스크롤이 사라짐.

## 외부 이미지 URL은 만료된다 — `image_import`로 사이트에 저장

Unsplash 등 외부 이미지 URL을 히어로·CASE 섹션 배경으로 그대로 링크하면 나중에 만료되어 깨질 수 있다. 재밋 `image_import` 툴로 사이트 자체에 저장해두면 만료 걱정이 없다. 다만 외부에서 고른 이미지는 사람이 직접 눈으로 확인해야 한다 — 실제로 처음 고른 리눅스 데스크톱 배경 사진 한 장에 **"Activate Windows" 워터마크**가 찍혀 있었는데, 발행 후 육안 검수에서야 발견되어 교체했다. 스크린샷 캡처 없이 후보 이미지를 브라우저에 여러 장 나란히 띄워 직접 비교하는 방식으로 골랐다.

## 반투명 카드 + 밝은 배경 사진 = 가독성 결함

`rgba(255,255,255,0.08)` 같은 "유리(glass)" 스타일 카드를 밝은 배경 사진(키보드, 커피 등) 위에 얹으면 글자가 묻힌다. 재현되는 처방은 배경을 어둡게 깔고 카드를 불투명 다크로 바꾸는 것 — 이 사이트에서 서로 다른 두 섹션(BUILT 카드, 협업 제안 3단계 카드)에 동일한 원인·동일한 해결이 반복됐다.

## 재밋 AI 품질 게이트(2026-09-16 도입)가 저장 시점에 마크업을 직접 고친다

이 날부터 페이지 저장 시 서버가 마크업 품질을 자동 검사·수정하기 시작했다. 응답의 `fixes` 배열로 무엇을 고쳤는지 알려준다. 확인된 두 가지:

- **`main_added`** — 본문 전체를 `<main>`으로 감싼다. 그 결과 `page_sections`가 **count:1**로 붕괴해 섹션 번호로 부분 수정을 할 수 없게 된다. 다만 `page_patchSection`을 `section:"1"` + 유일한 find 문자열로 호출하면 여전히 부분 수정은 가능하다.
- **`h1_added_from_page_title`** — 화면에 **보이는 중복 `<h1 data-wv-ai-quality="page-title">`을 페이지 상단에 실제로 주입**한다. 판정 기준은 기존 h1이 "숨겨져 있다"는 것인데, 실제 트리거는 **`-webkit-text-fill-color:transparent`인 그라디언트 텍스트**였다. `color`만 지정해서는 통과하지 못했고 **단색(`fill-color` 미사용)으로 바꿔야** 주입이 멈췄다. 이 주입은 저장된 HTML에 영구 반영되므로 재발행해도 남는다.

**복구 방법**: 이미 주입·붕괴가 일어났다면 `page_revisions`로 사고 전 리비전을 찾아 `page_rollback`으로 되돌린 뒤, **원인이 된 그라디언트 텍스트를 단색으로 바꾸는 패치를 같은 저장에 함께 포함**시켜야 한다(색만 따로 나중에 고치면 그 사이에 다시 주입된다). h1이 아예 없던 페이지(서브페이지 등)는 대비되는 제목 태그를 `h1`으로 미리 승격해두면 주입을 예방할 수 있고, 부수 효과로 `indexable`이 `false`→`true`로 바뀌기도 했다(검색 노출 개선).

## `page_update`의 css/js 인자는 블록 조립 페이지에서 거부된다

재밋 페이지가 블록(섹션) 조립 방식일 때 `page_update`에 `css`/`js` 인자를 실어 보내면 거부된다. 전역 스타일/스크립트를 넣을 수 있는 경로는 두 가지뿐이다 — ① 개별 섹션 HTML 안에 `<style>`/`<script>` 태그를 직접 심거나, ② 헤더/푸터 컴포넌트의 `js` 슬롯을 쓰는 것(아래 항목).

## 섹션 스크립트의 `document.querySelector*`는 `__zsScopeRoot.querySelector*`로 자동 치환된다

섹션 안에 넣은 `<script>`가 저장되면 서버가 `document.querySelectorAll` 등의 호출을 **자동으로 `__zsScopeRoot.querySelectorAll`로 치환**한다(섹션 스타일도 `:where([data-zs-scope])`로 자동 스코프되고 `@keyframes` 이름도 네임스페이스된다). 그래서 셀렉터 자체는 맞는데 스크립트가 **자신이 속한 섹션 밖의 요소를 하나도 못 찾는** 증상이 난다 — 처음엔 "DOM이 아직 준비 안 됐다"는 타이밍 문제로 오진하기 쉽지만, 실제 원인은 스코프다. 우회법은 `document.body`처럼 스코프 밖을 가리키는 참조를 쓰거나, 애초에 스코프 치환이 적용되지 않는 헤더/푸터 컴포넌트 `js` 슬롯으로 코드를 옮기는 것이다.

## 헤더/푸터 컴포넌트의 `js` 슬롯 = 전 페이지 공용 엔진 자리

`component_get`/`component_update`로 다루는 헤더·푸터 컴포넌트는 모든 페이지에 자동 삽입되고, 섹션 스크립트와 달리 **`__zsScopeRoot` 스코프 치환을 받지 않는다**(본문 끝에 그대로 실행됨). 그래서 여러 페이지에 걸쳐 재사용할 JS/CSS 엔진(스크롤 이펙트, 공용 인덱스 번호, 접근성 가드 등)을 둘 자리로 이 슬롯이 적합하다 — 한 곳만 고치면 전 페이지에 동시 반영된다. 단, 전체 내용을 통째로 교체하는 방식이라 큰 엔진을 수정할 땐 매번 전체를 다시 보내야 한다(`component_get`으로 현재본을 받아 병합 후 재전송). **문법 오류 하나가 전 페이지의 효과를 동시에 죽일 수 있으므로, 저장 직후 반드시 콘솔 에러를 확인한다.**

## 밝은 장면 밴드는 진입·이탈 양쪽 다 페이드가 필요하다

어두운 섹션들 사이에 밝은(예: 광원이 있는) 장면 밴드를 끼워 넣을 때, 한쪽(예: 하단) 페이드만 넣으면 반대쪽(상단) 경계에서 밝기가 계단처럼 뚝 끊긴다. 위아래 양쪽에 그라디언트 페이드를 주고, 광원 자체도 밴드 경계보다 안쪽(예: 하단 중앙)에 두면 경계부가 자연스럽게 어두워져 앞뒤 섹션과 이어진다.

## 브라우저 팬이 숨김 상태면 rAF·CSS 애니메이션이 멈추고 스크린샷도 못 믿는다

검수용 브라우저 팬이 숨김(hidden) 상태가 되는 경우가 잦았는데, 그 원인·우회법·검증 시 오진 사례는 [[브라우저-팬-숨김-상태-rAF-정지-테스트-우회]]에 별도로 정리했다.

## 인스타그램 게시물 링크는 레퍼런스로 못 받아올 수 있다

사용자가 레퍼런스로 인스타그램 게시물 URL을 준 경우, 인앱 브라우저 접근 차단·`curl`(크롤러 UA 포함) og 태그 없음·서버측 크로미움 렌더도 로그인 벽·`/embed/captioned/` 엔드포인트는 JS 셸만 반환, 네 경로 모두 막힌 사례가 있었다(캡션 텍스트만 확보 가능). 반면 다른 인스타 게시물은 `og:image` 썸네일 확보에는 성공한 적도 있어 게시물마다 다르다. 여러 레퍼런스가 서로 다른 스타일 방향이었던 전례가 있으므로, 못 본 채로 추측 구현하면 방향을 잘못 잡고 헛도는 리스크가 크다 — 실제로 볼 수 없으면 스크린샷을 요청하는 편이 안전하다.

## 스크롤 스토리는 효과보다 분량이 우선일 수 있다

"화려하게 해달라"는 요청이 실제로는 **효과 종류가 아니라 스크롤로 넘길 장면(뷰포트 수) 자체가 부족하다**는 뜻이었던 사례가 있었다. 참고 사이트(toss.im 60뷰포트, 10to100 23뷰포트) 대비 이 사이트 홈이 7~9뷰포트에 불과해 몇 번 굴리면 끝났다. 효과를 더 얹기 전에 실제 참고 사이트의 문서 높이(뷰포트 수)부터 비교해볼 가치가 있다. 핀 고정 스크롤 장면 자체의 구현 기법은 [[토스식-핀고정-스크롤-장면]] 참고. 무한 마퀴에 스크롤 반응 드래그를 더할 때의 함정은 [[무한-마퀴-드래그-클리핑-컨테이너-대신-트랙에-적용]] 참고.

## 페이지 생성 시점의 내부 설명값은 MCP로 수정 불가

재밋 AI 품질 게이트가 "페이지 설명이 짧다"고 지적할 때, 이 설명값은 **페이지를 처음 만든 시점에 저장된 내부 값**이라 이후 본문을 아무리 늘려도, 설명 자동 생성 도구를 돌려도 바뀌지 않았다 — 이 값을 직접 수정하는 도구가 재밋 MCP에 없다. 다만 실제 검색 결과·공유 카드(OGP)에 나가는 설명은 본문에서 별도로 뽑혀 나가는 값이라 이미 정상일 수 있으므로, 이 경고가 실제 노출 품질에 영향을 주는지는 공개 페이지의 메타 태그를 직접 확인해서 판단해야 한다. 재밋 편집기(웹 UI)에서 직접 고치면 지울 수 있지만, "수정은 MCP로만" 원칙 하에서는 손댈 수 없는 영역이다.

## `data-zs-role` 값에 따라 플랫폼 전역 CSS 규칙이 다르게 적용된다

블록 안의 요소가 갖는 `data-zs-role`(예: `"label"`, `"text"`, `"button"`)은 플랫폼이 전역으로 깔아둔 CSS 규칙의 타깃이 된다. 시각적으로 같아 보이는 요소라도 역할을 바꾸면(예: 번호 텍스트를 `"label"`로 지정) 의도치 않게 다른 전역 규칙(글자 크기 등)을 맞고 크기가 달라질 수 있다. 역할을 바꾸기 전/후로 실제 사이트에서 글자 크기·굵기·색·박스 크기를 비교해 완전히 동일한지 확인해야 한다.
