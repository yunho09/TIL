# haru(하루) — 프로젝트 현황

**하루**는 GNOME(Ubuntu, Wayland)용 개인 일정·할 일 앱이다. GTK4 + libadwaita(Python, `/usr/bin/python3`)로 가볍게 만들고, 일정 저장소는 GNOME에 이미 있는 Evolution Data Server(EDS)를 그대로 써서 구글 캘린더·구글 할 일과 자동 동기화된다(폰의 삼성 캘린더는 구글을 거쳐 보임). 레포는 public: `yunho09/haru` (코드 `/data/project/haru`).

## 구조 (2026-10-22 분리)
- `haru.py`는 진입점만, 앱 코드는 `haruapp/`의 역할별 모듈 10개 (core: GTK 없는 순수 로직, store: EDS 접근, window, weekview, dialogs, widgets, diary, app, log)
- 테스트: 단위 51~52개(GitHub Actions ubuntu-24.04에서 자동 실행), 실제 캘린더용은 `HARU_EDS_TESTS=1`로 옵트인(로컬·구글 각 7개). 테스트 일정은 `haru-test` 접두사로 만들고 지움
- 오류 로그 `~/.local/state/haru/haru.log`, 앱 메뉴 등록은 `.desktop`
- 밤 10시 systemd 사용자 타이머가 `--remind`를 실행해 그날 일기를 안 올렸으면 알림(누르면 `--diary`로 메모칸 열림)

## 기능 요약
- 월/주 보기(주 보기는 cairo로 그린 15분 단위 시간표), 하루 종일 기본, 알림, 반복 일정(매일·평일·매주·2주·매월·매년+종료일), 반복 일정 "이 일정만/모든 반복"
- 드래그: 월 보기는 막대 가운데=이동, 양 끝=기간 조절, 빈 칸=새 일정 / 주 보기는 이동·아래 끝 길이 조절·빈 시간대 생성. 막대 색은 원래 캘린더 색 유지(강조선만). 놓는 순간 낙관적 UI로 먼저 반영하고 저장은 뒤에서
- Ctrl+Z 되돌리기(최근 30개, 스냅샷 기반 `Store.restore`), 마감일 있는 할 일을 칸에 표시(○/✓, 클릭=완료 토글, 끌면 마감일 변경)
- 사이드바: 날짜별 할 일(구글 할 일에 저장), 날짜별 메모, 노션 일기 업로드

## 결정과 근거
- 공휴일만 빨간 날: 국군의날 같은 기념일은 제외
- 노션 업로드는 **버튼으로만** (자동 업로드는 사용자가 거부), 밤 알림은 알리기만
- "모든 반복" 수정에서는 날짜 이동 금지: 구글 주간 규칙은 `BYDAY`가 붙어 있어 DTSTART만 옮기면 규칙이 깨짐 (시간·제목은 가능)
- 매월 31일 반복은 30일까지인 달을 건너뜀(구글 캘린더와 동일)
- 구글이 만든 복잡한 규칙("5번만", "매월 둘째 화요일")은 "사용자 지정(그대로 유지)"으로 표시하고 건드리지 않음. `repeat_index`는 프리셋으로 표현 못 하는 규칙(`BYMONTHDAY=-1` 등)을 None으로 돌려줘야 규칙이 조용히 바뀌지 않음
- 평일 반복을 주말 시작 일정에 걸면 구글과 EDS가 어긋나 막고 안내

## 노션 일기 연동
- 내부 통합 "하루"(API 토큰, 설정 `~/.config/haru/notion.json` 권한 600). **통합은 데이터베이스마다 "연결"을 따로 추가해야** 접근됨(⋯ → 연결)
- 올리는 곳은 사이드바 **🎒 일기** DB, 제목은 `YYYY-MM-DD`. 한 번 엉뚱한 DB(장윤호 페이지 안의 "📕 일기")에 올렸는데, 그 DB는 사용자가 보는 일기 표의 뷰가 붙은 컨테이너였음 → **📕 일기 DB는 지우면 안 됨** ("빈 DB"로 오판했던 것)
- 내용은 "📒 하루 기록" 콜아웃 하나에만 담고, 재업로드 시 **새 콜아웃을 먼저 붙인 뒤 옛것을 삭제**(중간 실패해도 내용 유지, 직접 쓴 글은 보존). 429/502/503 재시도, 텍스트는 2000자 단위로 분할
- 일기 내용: 할 일(체크 상태 포함), 일정(공휴일·생일 제외), 그날 커밋(`/data/project` 아래 레포, stash 제외), 메모
- 코드 리뷰 교훈: 같은 날짜 페이지를 "전부 지우고 덮어쓰기" 하면 직접 쓴 내용을 날리므로 자기가 쓴 블록만 식별해 교체해야 함
