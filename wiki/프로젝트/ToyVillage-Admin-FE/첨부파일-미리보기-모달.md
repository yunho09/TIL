# ToyVillage-Admin-FE 첨부파일 미리보기 모달

첨부 칩의 파일명을 누르면 이미지·PDF는 모달로 미리보고, 다운로드 아이콘은 그대로 바로 내려받게 만든 기능(`src/shared/ui/AttachmentPreviewDialog.tsx`). 백엔드 신규 API 없이 기존 파일 서버(CDN)에서 원본을 받아 프론트에서만 처리한다. 이슈 #186 → PR #188(공지·업무·업무보고 상세), 이슈 #189 → PR #190(자료실·관찰 상세), 이슈 #191 → PR #194(그리지 못하는 이미지 안내). 하네스 게이트 구조는 [[ToyVillage-Admin-FE/하네스-시스템]], 저장소 전반 기록은 [[ToyVillage-Admin-FE/프로젝트-현황]] 참고.

## Figma와 그 빈틈

- Figma(yot)의 `첨부파일 미리보기` 섹션 `2435:24589`: 이미지 프레임 `2435:24590`, PDF 프레임 `2435:24615`. 배경은 **자료실 상세** 화면.
- 모달 폭 1200, 뷰어 1120×640 회색, 헤더에 파일명·다운로드·닫기(X). PDF는 한 쪽씩 보이고 모달 아래에 `‹ 1 / 3 ›` 이동 버튼이 붙는다(그래서 PDF 모달 높이 818 > 이미지 762).
- **Figma에 없던 것**: 어디를 눌러야 모달이 열리는지, 이미지·PDF가 아닌 파일(hwp·xlsx)을 눌렀을 때 동작, 로딩·실패 문구. 다른 상세 화면의 설명은 아직 "다운로드 버튼으로 내려받아요"로 되어 있다.
- 이 빈틈은 사용자가 정하지 않아 추천안으로 채우고 spec에 "결정 사항"으로 기록했다: **파일명 클릭=미리보기, 그 외 형식=파일명 클릭 시 바로 다운로드, 로딩/실패 문구는 뷰어 안에 표시**.

## 백엔드 API가 필요한가 → 아니오

- 조회 응답의 `files`가 이미 `{ fileName, fileKey }`를 준다(`entities/task/api/types.ts`, `entities/task-report/api/types.ts`).
- 다운로드는 API 서버가 아니라 `VITE_FILE_BASE_URL/{fileKey}`에서 `fetch`로 원본 Blob을 받는다(`src/shared/api/fileStorage.ts`). 미리보기도 같은 Blob을 쓴다.
- 이미지는 Blob URL을 `<img>`에 넣으면 되고, `‹ 1 / 3 ›` 페이지 이동을 직접 그리려면 **`pdfjs-dist`**(프론트 라이브러리)가 필요하다. 브라우저 기본 PDF 뷰어를 끼우면 이 UI를 못 만든다.
- 파일 서버 쪽 확인 사항(API 아님, **미검증**): CDN의 PDF `Content-Type`(다르면 확장자로 Blob 타입을 다시 붙여 해결 가능), 최대 50MB 파일도 미리보기에 원본 전체를 받는다는 용량 문제(썸네일이 필요하면 그때 백엔드 작업), CORS(다운로드가 `fetch`로 이미 되고 있으면 허용된 것). 스테이징에서 PDF가 실제로 내려오는지는 확인 안 했다.

## 구현 결정과 근거

- **형식 판별은 한 곳**: `fileAttachment.ts`의 `previewKind(fileName)` — `jpg/jpeg/png/gif/webp`→`'image'`, `pdf`→`'pdf'`, 그 외→`null`(미리보기 없이 다운로드). 칩·목록·모달이 모두 이 함수를 써서 기준이 어긋나지 않게 했다.
- **파일 받기**: 저장소 규칙대로 TanStack Query `useQuery`. `gcTime: 0`(닫으면 캐시에 안 남김, 50MB 메모리 상주 방지), `retry: false`(실패 시 바로 실패 문구). 이미 받아 둔 파일이 있으면 모달의 다운로드는 재요청하지 않는다.
- **PDF**: pdf.js는 PDF를 열 때만 동적 import(첫 화면 번들 불변, 별도 청크). 현재 쪽을 높이 600px 기준 `<canvas>`에 그리고 쪽 이동 시 이전 렌더 작업을 취소. 첫 쪽에서 `‹`, 마지막 쪽에서 `›` 비활성.
- **pdfjs-dist v6 함정**: 문서 해제 API가 `loadingTask.destroy()`로 바뀌어 있었다(구 API 그대로 쓰면 안 맞음).
- **StrictMode 정리 시점**: 개발 모드에서 컴포넌트를 뗐다 바로 다시 붙이므로, 정리를 즉시 하면 문서가 먼저 파괴된다 → 정리 시점을 한 박자 늦췄다.
- **접근성**: 열리면 초점이 닫기 버튼으로, Tab은 모달 안에서만 순환, 뒤 화면은 `inert`. 닫기 버튼·Esc·바깥 어두운 영역 클릭 모두 닫히고 초점은 누른 파일명 버튼으로 복귀.
  - e2e에서 발견한 버그: 바깥 영역 클릭으로 닫을 때 `mousedown` 기본 동작이 초점을 다시 가져가 복귀가 안 됨 → 코드에서 mousedown 기본 동작을 막아 해결.
- **이미지 크기 방침 변경**: Figma는 이미지를 잘라 영역을 꽉 채우는 방식이지만, 원본이 잘리지 않도록 "작으면 원본 크기, 크면 비율 유지하며 축소"로 바꿨다(의도적 이탈, spec 기록). 테스트는 1×1 가짜 PNG라 실제 사진이 얼마나 크게 보이는지는 육안 확인 전.
- **칩 구조**: `AttachmentChip`은 원래 칩 전체가 다운로드 버튼 하나였다. 선택 prop `onPreview`를 넘기고 파일이 이미지·PDF일 때만 **미리보기(아이콘+파일명) / 다운로드(아이콘) 두 버튼**으로 나뉜다. 안 넘기는 기존 사용처는 무변경. `AttachmentList`(업무·업무보고 첨부자료 카드)는 그 두 화면만 쓰므로 한 커밋으로 둘 다 적용됐다. 미리보기 불가 형식의 파일명 버튼은 옆 다운로드 버튼과 중복 낭독되지 않게 스크린리더·키보드에서 숨겼다.
- **아이콘**: Figma 아이콘 3개(`close-line.svg`, `chevron-left-rounded.svg`(오른쪽은 180° 회전), `download-large.svg` 32px)를 새로 넣음. 기존 `close.svg`·`download.svg`는 모양/크기/색이 달라 재사용하지 않았다. 색 토큰은 신규 0개(기존 `textStrong`·`background` 등과 같은 값).

## 동결(frozen) e2e를 고쳐야 했던 사례

- 관찰 상세에 미리보기를 붙이자 기존 e2e **S16(키보드 조작)** 이 깨졌다. 칩이 두 버튼이 되어 Tab 순서가 `⋮ → 다운로드`에서 `⋮ → 미리보기 → 다운로드`로 바뀐 것. 시나리오 문장("키보드로 다운로드 버튼을 실행할 수 있다")은 그대로 맞아서 **테스트에서 Tab을 한 번 더 누르게만 고치고 재freeze**했다. freeze된 테스트는 임의로 못 고치므로 사용자에게 선택지(테스트 수정+재freeze / 관찰 상세 제외)를 물었고, 사용자가 "칩 누르면 미리보기, 다운로드 아이콘 누르면 다운로드"로 정리해 전자로 진행.
- 시나리오를 추가(S9·S10, S11)하면 게이트가 재승인을 요구하고 `e2eHash`가 초기화되므로, 구현 뒤 e2e에 시나리오를 추가하고 다시 freeze하는 순서를 매번 밟았다. 재승인은 사람이 `yarn harness:approve attachment-preview --by yunho09 --scenarios S1,...`로 실행.
- 관련 e2e에서 남은 실패는 `individual-detail` S30(키보드 조작) 하나. **변경을 모두 뺀 develop 상태에서도 똑같이 실패**해 기존 실패로 판정했다(변경 제거 후 재실행으로 대조).

## 이슈 #191 — 자료실 "회의사진" 미리보기에서 사진이 깨진 아이콘으로 보임

- **원인은 코드가 아니라 파일 형식**: 받아온 파일의 앞부분에 `ftypheic`가 있어 **아이폰 HEIC 사진인데 이름만 `.jpg`**(`IMG_1435.jpg`, 약 950KB). 크롬은 HEIC를 그리지 못해 `<img>`가 깨진 아이콘만 띄운다. 서버 응답은 정상이고 다운로드된 파일도 HEIC.
- 진단 요령: 미리보기가 안 뜨면 확장자를 믿지 말고 받은 Blob의 앞 바이트(매직 넘버/`ftyp` 브랜드)를 확인한다. 이미 요청이 성공해도 디코딩이 실패할 수 있으므로 "로딩 실패"와 "그리기 실패"는 다른 상태다.
- 수정: `<img>`가 그리지 못하면(HEIC뿐 아니라 깨진 이미지 전부) 깨진 아이콘 대신 "미리보기를 지원하지 않는 형식입니다. 다운로드해서 확인해 주세요."를 표시, 모달의 다운로드는 유지. 시나리오 S11 추가(가짜 HEIC로 문구 표시·깨진 이미지 없음·다운로드 동작 검증).
- **사진 자체를 보이게 하는 건 미해결**: HEIC→JPG 변환이 별도로 필요(브라우저 변환 라이브러리 또는 업로드 시 변환 — 후자는 백엔드 협의). 사용자에게 제안만 했고 진행 여부는 결정 전.

## 커밋·PR 작업 방식 메모

- PR #188 커밋을 3개→9개로 쪼갤 때 순서는 명세 → 의존성 → 아이콘·형식 판별 → 모달 본체 → 화면 연결(목록 → 칩 → 공지) → 테스트(앞 커밋이 뒤 커밋이 쓰는 코드를 먼저 넣도록). 최종 트리는 쪼개기 전과 동일함을 확인하고 force push했지만, **중간 커밋을 개별로 빌드해 보지는 않았다**(마지막 커밋 기준 검증만).
- 이슈 → `origin/develop`에서 `#이슈번호/설명` 브랜치 → spec·시나리오 → 재승인 → 구현 → e2e freeze → 커밋 → PR 순서. 앞 PR이 이미 머지돼 있으면 새 브랜치는 `origin/develop`에서 직접 만든다. PR 제목은 브랜치명, 본문은 템플릿 + `Close #이슈`, 리뷰어에게 항목에 Figma에 없어 임의로 정한 부분을 적었다.
