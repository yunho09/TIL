# 공지사항 날짜에 시간이 붙어 나오는 문제 (#287 / PR #288)

서버가 공지 날짜를 `2026-10-29T10:32:33.344078`처럼 시간까지 붙여 내려주기 시작해서 화면에 `2026.10.29T10:32:33.344078`로 표시된 버그. 공용 `formatIsoDate`가 앞 10자리만 쓰도록 고쳐 해결했다.

## 원인
- `src/shared/lib/calendarDate.ts`의 `formatIsoDate`는 입력이 `YYYY-MM-DD`라고 전제하고 `-`만 `.`으로 바꿨다. 시간이 붙은 값은 자르지 않고 그대로 통과.
- 공지 목록과 `NoticeDetailPage` 모두 같은 함수를 써서 같이 영향받음.

## 해결과 판단
- `formatIsoDate`가 **앞 10자리만** 쓰도록 변경 → 날짜만 오는 값은 결과 동일, 시간 붙은 값은 잘림.
- 목록 **검색 대상**에서도 시간을 뺐다(요청 밖 수정). 안 빼면 화면에 없는 `10:32` 같은 시간으로 공지가 검색되기 때문.
- `notice.date` **원본은 시간 포함 그대로** 둔다 → 같은 날 올라온 공지가 시간순으로 정렬됨. 표시 단계에서만 자르는 게 포인트.
- 기존 공지 e2e는 동결(frozen)이라 건드리지 않고 `tests/e2e/notice-date-format.spec.ts`를 새 파일로 추가(목록·상세·검색).

## 공용 함수를 고칠 때의 영향 범위
- 같은 함수를 직원 계정 표, 먹이 급여, 업무일지도 사용.
- 업무일지 목록: `createdAt`에 시간이 오면 같이 잘림(의도된 효과).
- 먹이 급여: 시간을 따로 받아 표시해서 영향 없음.
- **미수정 잠재 문제:** `staffAccountApi.ts`는 `createAt`이 날짜 형식만 통과하도록 검증한다. 서버가 여기도 시간을 붙이면 잘못된 응답으로 처리될 수 있음.

## 남은 열린 문제
- **검색 형식 불일치(CodeRabbit Minor):** 화면은 `2026.10.29`인데 검색 대상은 `2026-10-29`라 화면 형식으로 검색하면 안 찾아짐. 이 PR 이전부터 있던 동작이라 별도로 둠(한 줄 수정).
- **불안정(flaky) 테스트 2개:** `feed-detail` S7(이력 행 3개 기대인데 2개), `feed-list` S3(5층 탭 전환 후 4층 열 잔존)가 develop CI에서도 재시도로 통과하는 패턴. 이번 변경과 무관, 원인 미확인 → 팀 규칙상 별도 이슈 대상.
