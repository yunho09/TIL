# 팀 작업 규칙 하네스 문서 (#235)

각자 AI 메모리에만 있던 커밋·PR·브랜치 규칙 10개를 `harness/shared/team-rules.md` 한 곳에 모은 작업(이슈 #235, PR #236). [[하네스-점검-결과와-개선-방향]]의 F4 처방(팀 규칙이 하네스에 없음)을 실행한 것이다. 근거: AI 정정 원인 1위, 팀 전체 49건.

## 구성
- `harness/shared/team-rules.md` 신규, `harness/README.md` 공통 규칙 줄·`CLAUDE.md`·`AGENTS.md`에 링크 한 줄(Claude·Codex 모두 읽게 함).
- 규칙 2·7(PR·이슈 양식)은 `.github/`의 템플릿을 가리키는 것으로 충분.
- 규칙 3은 `develop` 실제 이력의 type 7개(`feat·fix·test·docs·chore·refactor·style`)+명사형. Co-Authored-By는 [[Claude-Code-AI-표기-attribution-끄기]]로 차단(develop 최근 300커밋엔 원래 0건).
- 커밋은 규칙 1대로 성격별 분리(문서 / Claude 설정), CodeRabbit 지적마다 커밋 하나+해시만 답글.

## 규칙 9: e2e 격리 포트 5199의 범위
- 이유: `playwright.config.ts`의 `reuseExistingServer: !CI` 때문에 5173에 떠 있는 dev 서버를 재사용하면 요청이 스테이징으로 샌다 ([[Playwright-reuseExistingServer-실서버-유출]]). `yarn verify:e2e`도 내부에서 Playwright를 그대로 실행하므로 같은 환경변수를 붙여야 한다.
- **mock e2e에만 해당**: 이 서버는 API 주소를 존재하지 않는 `https://api.e2e.invalid`로 고정하고 `page.route()`가 응답을 가로채므로 실서버 CORS 검사가 일어나지 않는다 → 백엔드에 5199 CORS를 요청할 필요 없음.
- 실서버 검증(`yarn verify:api:real`, `playwright.real-api.config.ts`)은 스테이징 CORS가 열린 **5173**으로 돌린다. 여기에 5199를 붙이면 CORS에 막힐 수 있다.

## 규칙 10: 스테이징 500 판별
- 스테이징(`api-stag.toyvillage.kr`)은 **없는 경로에도 404 대신 500**(`내부 서버 오류가 발생했습니다.`)을 준다. 그래서 500만으로는 "API는 있는데 고장"과 "아직 미배포"를 구분 못 한다.
- 절차: 같은 정상 토큰으로 ① 문제 API ② 없는 경로(`GET /definitely-not-real`) ③ 있는 경로(`GET /dashboard/count`)를 비교.
  - ③이 200이 아니면 비교 자체를 믿지 말고 토큰·서버 상태부터 확인.
  - ①②가 모두 500이면 **미배포로 추정**하고 백엔드에 확인(확정 아님).
  - 값을 바꿨더니 400·404면 경로가 있을 가능성이 높다(확정이 필요하면 백엔드에 확인).
- **토큰이 없거나 잘못되면 경로 유무와 상관없이 빈 본문 403**이 먼저 온다 → "같은 토큰으로"가 필수.
- 2026-10-07 재확인: 로그인 토큰으로 없는 경로 둘 다 500, `/dashboard/count` 200, 토큰 없이는 403. 서버가 404를 주게 바뀌면 필요 없어지는 임시 규칙(백엔드에 전달됨).
- 확인용 호출도 서버엔 500 오류 로그로 남으므로 한두 번만 보낸다.

## Postman으로 재현하기
- 토큰: 브라우저 개발자도구 Application → Local Storage → `accessToken` 복사(추천). Postman에서 별도 로그인(`POST /app/auth/login`, 응답 `access_token`)하면 리프레시 토큰이 일회용이라 브라우저 세션이 끊길 수 있다.
- Bearer Token으로 위 ①②③ 요청. Postman은 브라우저가 아니라 CORS 제한이 없다.
- **함정: URL 끝에 줄바꿈(`↵`)이 같이 붙여넣어지면** 서버는 `/app/auth/login\n`이라는 다른 경로로 받아 빈 본문 403을 준다(정상 주소는 틀린 계정에 401+본문). 403·500이 나오면 서버를 의심하기 전에 주소부터 확인. 주소창에서 `End`→`Backspace`로 지우거나 직접 타이핑.

## CodeRabbit 리뷰에서 나온 교훈
- 판정 문구는 단정하지 말고 낮춘다("서버 전체 문제"→"비교 결과를 믿지 말고 확인", "경로 존재"→"가능성이 높다"). 표현 수준 지적이 반복되면 더 고치지 않고 넘기는 것을 권장.
- 외부 도구 지적은 설치된 도구로 직접 확인한 뒤 반영(`sessionUrl`은 실제 설정 항목이었음).
