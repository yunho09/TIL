# 악성 PR 가정 적대적 리뷰 3라운드 교훈 (PR Lens)

PR 작성자가 악의적이라고 가정하고 검증 에이전트로 리뷰를 3번 돌렸고, 매번 더 깊은 우회로가 나왔다. 핵심 교훈은 **"Claude에게 안 보여주고 건너뛰는 규칙이 있는 한 그 규칙을 노리는 공격이 계속 나온다"**였고, 그래서 설계 원칙을 바꿨다. 앱 개요는 [[프로젝트-현황]].

## 원칙 변경
- **완전히 건너뛰기(⚫)는 lock 파일·`.snap` 스냅샷·이미지/폰트/미디어뿐.** 나머지(공백 변경, 생성 폴더, 실행 파일, 위험한 위치로의 이름 변경)는 우선순위만 낮춰 Claude에게 보내거나 🟣 "확인 필요"로 표시.
- **이전 판정 상속은 위치까지 같을 때만**(주변 코드 줄·함수명까지 포함한 `anchorKey`).
- **diff를 해석 못 하면 조용히 버리지 말고 🟣로.**
- 마지막 라운드 뒤에는 "열린 리뷰를 또 돌리지 않고 지적된 재현 사례가 막혔는지만 확인"하고 마무리 — 리뷰가 매번 더 깊은 공격을 찾는 구조라 끝이 없기 때문.

## 1차(심각 2)
- **개발 서버가 모든 네트워크에 열림 + 인증 없음** → 같은 와이파이의 누군가가 내 GitHub 권한으로 비공개 PR diff를 읽고 내 Claude 사용량을 쓸 수 있음, 악성 사이트 링크로 분석 자동 시작도 가능. 대응: `127.0.0.1` 바인드, 모든 라우트(`proxy.ts`)에 Host 허용 목록(DNS 리바인딩 방어), API에 Origin/JSON 가드, `X-Frame-Options: DENY`+CSP `frame-ancestors 'none'`.
- **"공백만 바뀜" 판정이 줄 순서 변경까지 공백 변경으로 처리** → `if (!권한) { return 거부 }`의 return을 밖으로 빼거나 `권한확인(); 전부삭제();` 순서를 바꾸는 변경이 숨음. 대응: 줄 순서를 지키며 비교.
- 중간: 압축 폭탄(300MB tar가 수백 GB로) → 풀기 전 크기 사전 검사, 이상한 이름의 심볼릭 링크 잔존, 증분 리뷰에서 🔴가 필터에 가려짐, 3000개 초과 파일이 무표시로 잘림 → 경고.
- 튼튼하다고 확인된 것: 레포에 악성 설정·지시문을 심어도 Claude가 레포 밖 읽기/쓰기/명령 실행 불가, XSS·토큰 노출·캐시 경로 조작 없음.

## 2~3차에서 나온 것
- **위치를 옮긴 변경이 이전 판정을 상속**: 안 쓰는 함수에서 `verify(t)` 삭제(⚪) 뒤 실제 쓰는 함수에서 같은 줄을 지우면 같은 변경으로 취급 → 내용만 비교하던 지문에 위치를 더한 `anchorKey`로 해결. 내용 지문(`fingerprint`)은 eval 정답용으로 따로 유지.
- **diff 헤더에 보이지 않는 U+2028이 있으면 변경이 통째로 사라짐**(어느 목록에도 없고 경고도 없음) → 해석 불가는 🟣.
- **"줄 끝 공백만 바뀜"도 위험**: Makefile `BUILD_DIR = build ` 뒤 공백 하나가 `rm -rf build /*`가 되고, heredoc 끝 `EOF`에 공백을 붙이면 아래 서명 검증이 무력화됨.
- **줄 끝 `\r` 하나만 덧붙여도 같은 위치로 취급**돼 이전 판정을 상속(`cd ./build\r`은 셸에서 이동 실패 → 다음 명령이 엉뚱한 폴더에서 실행) → 앵커 본문에 CR/`\ No newline` 표시를 포함.
- **이름을 lock 파일로 바꾸면 건너뜀**: `.github/workflows/security.yml`→`yarn.lock`으로 이름만 바꾸면 보안 워크플로가 ⚫로 빠짐 → 이름 변경은 "예전 이름도 lock/snap이었을 때만" 건너뛰고, 확장자가 바뀌거나 동작에 영향을 줄 수 있는 0변경 이름 변경은 🟣.
- 실행 파일 교체(`gradle-wrapper.jar`), `vendor/`·`dist/` 안의 손으로 쓴 코드도 숨는 경로였음 → 생성 폴더는 힌트(generatedPath)만 주고 숨기지 않음.
- 인프라: 종료 시 Claude 자식 프로세스 정리(프로세스 그룹 kill+시그널 핸들러), 빠르게 모드에도 비용 상한, 모드가 같은 결과끼리만 상속(깊게 보기 요청이 실제론 빠르게로 돌았던 결과는 상속 금지), tar 목록 사전 검사는 `--numeric-owner`로 하고 실패 시 닫힘, 심볼릭/비정규 파일은 `find`로 삭제, 프로세스 간 레포 잠금, 자식에게 넘기는 환경변수를 **허용 목록**으로(`CLAUDE*`는 인증 관련만 허용, `GITHUB_TOKEN`/`GH_TOKEN` 제거).
- 프롬프트의 구조 태그에는 요청마다 다른 **nonce**를 넣어 PR 본문이 태그를 위조하지 못하게 함.

## 출시 후 추가 수정 (PR #1)
- **외부 링크로 열면 바로 유료 분석+공격자 레포 다운로드**: 브라우저 헤더 판정은 애매해 `Sec-Fetch-Site === "same-origin"`이고 dest가 `document`/`empty`(또는 없음)일 때만 자동 시작, 그 외엔 "분석 시작" 버튼.
- **PR이 `.ignore`/`.rgignore`를 넣어 깊게 보기의 Grep/Glob에서 파일을 숨김**: ripgrep은 git 레포가 아니면 `.gitignore`는 무시하지만 `.ignore`·`.rgignore`는 따름(실험 확인) → 체크아웃 직후 `find -name .ignore -o -name .rgignore -delete`.

## 검증 팁
- 각 수정은 **옛 코드에서 먼저 실패하는 단위 테스트**를 확인한 뒤 적용(작업자가 이를 지켰다고 보고).
- 검증 에이전트에게 고칠 위치·방법까지 짚게 하면 마지막 작은 우회는 직접 바로 고치는 편이 빠름.
- 크롬 확장이 교차 사이트 테스트 중 멈춘 건 렌더 루프가 아니라 도구 플레이크였음(검증 에이전트가 구분).
