# PR Lens 프로젝트 현황

PR 링크를 넣으면 "먼저 볼 곳 / 건너뛸 곳"을 골라 주는 **혼자 쓰는 로컬 웹앱 코드리뷰 가이드**. 분석은 Claude Code 구독의 `claude -p`로 하고(API 키 없음), `http://127.0.0.1:3000`에서만 열린다. 경로 `/data/project/pr-lens`, GitHub `yunho09/pr-lens`(public, main, 작업은 브랜치→PR→squash merge).

## 결정과 근거
- 형태는 **웹앱 / 나 혼자 쓰는 도구 / Claude Code 구독**으로 정함. 확장 후보(크롬 확장·CLI·GitHub Action)는 같은 분석 엔진(`src/lib`)을 재사용할 수 있지만 아직 미선택. Action은 API 키가 필요.
- 스택: Next.js 16.4.2(Cache Components라 `runtime` export 금지, `middleware` 대신 `src/proxy.ts`, 동적 읽기는 `connection()`+Suspense), React 19, Tailwind 4, zod v4, vitest.
- 커밋 제목은 한국어 서술형, 끝에 Co-Authored-By. 레포 설명·토픽(`code-review`, `claude`, `nextjs`, `pull-request`) 설정, `.cache/`는 올리지 않음.

## 기능
- **분류**: 🔴 꼭 볼 곳 / 🟡 볼 곳 / ⚪ 훑어도 됨 / ⚫ 건너뜀 / 🟣 확인 필요(분석 불가).
- **추천 동선 + 간단 설명**: 맨 위 패널에 읽을 순서, 카드마다 "이 부분은 → 왜 봐야 하나 → 확인할 질문 → 같이 볼 곳(diff 밖 호출부·테스트, GitHub 링크)".
- **깊게 보기**: Claude가 체크아웃한 레포를 읽기 전용(`Read,Grep,Glob`)으로 열어 호출부·정의를 확인. 실측 hono#5547 약 54초·$0.22·파일 3번 열람, zustand#3569 빠르게 모드 15초·$0.07. 비용은 구독 사용량에서 나감. 격리 방식은 [[claude-p-헤드리스-호출과-restricted-읽기-격리]].
- **증분 리뷰**: 새 커밋이 오면 바뀐 부분만 재분석. 이전 판정은 `anchorKey`(경로+섹션+주변 3줄+변경 구간+CR/개행 정보의 sha1)가 같을 때만 상속. 🔴는 "새 변경만 보기" 필터에 가려지지 않음. 저장 형식 `CACHE_VERSION=3`(버전이 오르면 옛 결과는 버리고 한 번 재분석, "봤음" 표시도 초기화).
- **정확도 측정(SZZ-lite)**: `eval:collect`로 "버그를 고친 PR→그 버그를 만든 PR" 쌍을 자동 수집해 정답 생성, `eval:run`으로 🔴가 실제 버그를 잡았는지 측정. 매 케이스마다 "이전 분석 재사용 없이 전부 분석했는지"를 검사(증분 기능이 수치를 부풀리는 것 방지). 결과(hono): 빠르게 3건 버그 100% 포착·🔴 비율 41%, 깊게 1건 100% 포착·🔴 비율 22%(같은 PR 빠르게 모드는 33%). 건수가 적고 hono는 모델이 이미 알 수 있어 **통계적 의미는 없음** — 덜 알려진 레포로 늘려야 함.

## 운영
- 로그인 시 자동 실행: `~/.config/systemd/user/pr-lens.service`(`graphical-session.target`, `next start -H 127.0.0.1 -p 3000`, `Restart=on-failure`). 끄기 `systemctl --user disable --now pr-lens`, 로그 `journalctl --user -u pr-lens`.
- 업데이트: `pr-lens-update`(`git pull --ff-only` → package-lock이 바뀐 때만 `npm ci` → build → 서비스 재시작).
- 캐시: 리뷰 `.cache/reviews/…json`(`PR_LENS_CACHE_DIR`로 변경), 체크아웃 `~/.cache/pr-lens/repos`(5개 유지, `*.inuse-{pid}` 잠금).
- 주소창에 `/review/…`를 직접 치면 "분석 시작" 버튼을 한 번 눌러야 함. 홈 입력칸에 링크를 붙이거나 최근 목록을 누르면 자동 시작.
- 개발 중 함정: `.cache/repos`의 남의 코드까지 lint가 훑어 ~800 오류 → eslint `ignores`에 `.cache/**`, tsconfig `exclude`에 `.cache`. Turbopack dev 캐시가 옛 `globals.css`를 낸 적 있음. `npm`이 SIGTERM을 하위로 안 넘김.
- 병렬 에이전트 운영(백엔드·UI·정확도 측정·로직 수정 등)은 파일 소유 범위를 먼저 나눠야 서로 덮어쓰지 않음. 한 에이전트가 분담 전에 UI 파일을 건드려 둔 것을 다른 에이전트가 발견해 이어서 작업한 사례 있음.
