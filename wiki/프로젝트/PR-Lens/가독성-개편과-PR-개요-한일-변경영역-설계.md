# PR Lens 가독성 개편과 "이 PR은" 개요(한 일 + 변경 영역) 설계

PR Lens 화면이 보기 힘들다는 요청으로 폭·글꼴·대비를 고치고, PR 전체가 무엇을 한 작업인지 보여 주는 **개요**(한 일 + 변경 영역)를 추가한 작업의 결정과 근거. 리뷰어 에이전트의 재검토 2회에서 나온 함정과, 새로고침(F5)이 유료 분석을 시작하던 기존 버그의 원인·수정도 정리한다. 결과는 PR #2(`ui/readability`)로 올렸고 머지 여부는 미확정.

## 가독성 개편 (1920px 기준)
- **코드 폭** 791px → 1142px. 1600px 이상에서는 카드를 2열(왼쪽 설명 / 오른쪽 코드)로, 설명 열은 sticky. 1599px 이하는 1열.
- sticky가 먹으려면 카드에 `overflow: hidden` 대신 **`overflow: clip`**을 써야 함(둥근 모서리는 유지하면서 스크롤 컨테이너가 안 생김).
- **사이드바** 항목 높이 ~200px → 50~70px(제목+파일명만, 2줄 clamp). 파일명은 말줄임하되 `:줄번호`는 유지, 전체 경로는 `title`/`sr-only`.
- **글꼴** 본문 Pretendard, 코드 D2Coding. 코드류 `.font-mono`는 **합자(ligature) 끔** — `!=` 같은 기호가 붙어 보이지 않게.
- **대비**: 흐린 글자 토큰을 올려 WCAG 4.5:1 이상(dark `--ink-subtle` 3.77→5.63 등). diff 거터 줄번호도 4.5:1 이상으로.
- 설명 문장의 백틱은 `.inline-code`로 렌더. 신뢰할 수 없는 텍스트(PR 제목·Claude 응답)는 React 텍스트로만 렌더하고 `dangerouslySetInnerHTML`은 쓰지 않음.
- 함정: `smooth` 스크롤을 JS에서 명시하면 CSS `prefers-reduced-motion` 규칙이 못 덮음 → `scrollToCard`에서 `matchMedia`로 확인. Turbopack dev가 옛 `globals.css`를 내면 `.next/dev/cache/turbopack` 삭제(프로덕션 빌드와 무관).
- 긴 diff 카드만 sticky/높이 제한을 걸고(`data-tall-hunk`, 40줄 이상) 짧은 hunk는 정적으로 — 안 그러면 짧은 diff 옆에서 중첩 스크롤러가 생겨 "코드 접기" 버튼이 잘림.

## 개요 기능
- **한 일**: Claude가 hunk를 목적별 최대 8묶음으로 묶고(제목 30자·설명 200자 상한), 묶음마다 🔴🟡⚪🟣 개수. 누르면 그 묶음 첫 카드로 이동. 분류에서 빠진 조각은 마지막 "그 밖의 변경"에 모음. 8개 상한에는 이 묶음도 포함.
- **변경 영역**: 폴더별 +/− 막대·파일 수·위험 개수. **AI 없이 계산**하므로 옛 캐시에도 바로 나옴. 행이 너무 많으면 "그 외 N개 영역"으로 합치되, 유지 우선순위는 `🔴 있음 → 🟡/🟣 있음 → 줄 수`(작은 `.github/`·`auth/` 변경이 안 사라지게).
- 스키마: `changes`는 CLI JSON 스키마에서는 필수지만 zod에서는 `.catch([])`(`.default([])`는 null·문자열·필드 누락 시 던져서 유료 분석 결과를 통째로 날림). `CACHE_VERSION`은 3 그대로 — 옛 캐시는 `changes: undefined`로 "한 일" 대신 안내 문구.
- 부분 재분석(증분)에서 Claude가 새 hunk 묶음만 주면 상속된 hunk가 "그 밖의 변경"으로 쏠림 → 지난 묶음에 id를 되돌려 넣음(이전 "그 밖의 변경"은 따로 복원하지 않고 새 catch-all에 합침).
- 실측: yunho09/pr-lens#1 빠른 모드 1회 ≈ $0.26·74초, hunk 10개가 2묶음으로 빠짐없이 분류. ToyVillage #284는 예전 캐시라 "한 일"이 안 나오고, 다시 분석하려면 ≈$0.99.

## 리뷰에서 나온 교훈
- **분석 못 한 코드가 깨끗해 보이면 안 됨**: fallback(응답이 건너뛴 hunk)·예산 초과로 빠진 hunk·분석 불가 파일이 개요에서 표시 없음/⚪로 보였음 → 🟣 개수 + "분석하지 못한 코드 N개, 직접 확인하세요" 줄. **숫자와 점프 대상이 일치해야 함**(fallback 카드도 🟣 섹션에 행으로 나열하고 `attentionCount`에 포함).
- **점프 후 포커스**: 스크롤만 하고 포커스를 안 옮기면 Enter 뒤 Tab에서 페이지가 맨 위로 튐 → 점프 시 카드로 `focus({preventScroll: true})`. 단 `tabIndex={-1}`을 JSX에 상시 두면 마우스 클릭 후 ←/→가 diff 가로 스크롤을 못 함(실측 `scrollLeft` 0→0) → 포커스 직전에만 `tabindex`를 달고 blur·pointerdown에서 제거(→ 0→200).
- 카드 `article`에는 `aria-labelledby`(제목 h3 id)로 접근 가능한 이름을 줌.
- 적색/녹색 막대는 색약 검사(deutan ΔE 2.2/5.5)에 실패 — 추가분이 항상 먼저, 2px 간격, 숫자 병기로 색에 의존하지 않게 함.
- 리뷰어가 짚은 항목도 재현 후 반영 여부를 판단함(예: "전체 경로가 title뿐"은 일반 영역 행에서는 사실이 아니었음 — CSS truncate라 접근성 이름에는 전체가 있음).

## F5가 유료 분석을 시작하던 문제
- README는 "새로고침은 자동 시작 안 함"이라 했지만 실제 크롬 F5는 앱 내 이동처럼 `Sec-Fetch-Site: same-origin` 요청을 보내 → 캐시 없는 PR에서 F5 한 번에 유료 분석이 시작될 수 있었음([[악성-PR-가정-적대적-리뷰-3라운드-교훈]]의 `Sec-Fetch-Site` 방어의 구멍).
- 서버는 요청 헤더만으로 새로고침을 구별 못 함 → 페이지가 브라우저 탐색 정보(navigation type)로 판별해 reload면 캐시만 읽음. 앱 내 뒤로/앞으로는 앱 내 이동으로 취급(자동 시작 유지).
- 부작용: reload한 PR의 첫 화면에 갔다가 같은 PR로 돌아오면 캐시 없을 때 "분석 시작"을 한 번 눌러야 함(비용 안전 쪽 선택).
- 미확인: 깊게 보기 + 새 프롬프트, 일부만 바뀐 재분석은 실제 Claude로 안 돌려 봄. 🟣 표시는 가짜 데이터로만 확인.
