# JKYMHS-Backend 프로젝트 현황

**라면 실험실** 백엔드(Spring Boot + Gradle, 경로 `/data/project/JKYMHS-Backend`). ERD는 `tbl_` 접두사 9개 테이블이며, 도메인형 패키지 구조로 `domain/user/entity`까지 폴더만 만든 초기 상태(2026-10-09 기준). 엔티티 이름 규칙과 확정/미결 결정을 정리한다.

## ERD 테이블 → 엔티티 매핑
- `tbl_` 접두사는 테이블명에만 쓰고 클래스명엔 붙이지 않는다 (`TblUser` ❌).

| 테이블 | 엔티티 | 패키지 |
|---|---|---|
| `tbl_user` | `User` | `domain.user.entity` |
| `tbl_email_verification` | `EmailVerification` | `domain.auth.entity` |
| `tbl_refresh_token` | `RefreshToken` | `domain.auth.entity` |
| `tbl_ramen` | `Ramen` | `domain.ramen.entity` |
| `tbl_topping` | `Topping` | `domain.ramen.entity` |
| `tbl_experiment` | `Experiment` | `domain.experiment.entity` |
| `tbl_experiment_photo` | `ExperimentPhoto` | `domain.experiment.entity` |
| `tbl_review` | `Review` | `domain.review.entity` |
| `tbl_bookmark` | `Bookmark` | `domain.bookmark.entity` |

- **`User` 이름 충돌 주의**: Spring Security에도 `org.springframework.security.core.userdetails.User`가 있다. `UserDetailsService` 구현 시 import하지 말고 FQN(`...userdetails.User.builder()`)으로 쓰거나 `CustomUserDetails`를 따로 만든다. `Member`로 피하는 방법도 있으나 ERD가 `tbl_user`라 `User` 유지를 권장.

## 확정된 결정 (2026-09-14)
- `tbl_user.password`는 `VARCHAR(60)` 유지 → `SecurityConfig`에서 `DelegatingPasswordEncoder`(`{bcrypt}` 접두사로 68자) 대신 순수 `BCryptPasswordEncoder` 사용.
- 이메일 인증은 **가입 전**에 끝낸다 → `tbl_user.email_verified` 컬럼 불필요, "미인증 로그인 차단" 규칙 폐기. 대신 **가입 API에서 해당 이메일의 인증 레코드가 verified이고 만료 전인지 반드시 재검증**(안 하면 인증 우회 가능).
- 패키지는 도메인 기반 `domain.<feature>/{controller,service,repository,entity,dto,exception}` + `global/` ([[도메인형-패키지-구조]]).

## 미결
- 이메일 인증 / 리프레시 토큰 저장소: Redis vs 테이블
- 토핑: 콤마 문자열 vs 조인 테이블
- `tbl_ramen`/`tbl_topping` 관리용 `role` 컬럼이 ERD에 없음
- 회원 탈퇴 시 FK·S3 정리 정책
- `image_url`과 `s3_key` 중복

## 최근 상태 (2026-11-03)
- 인증 #2~#6을 스택 PR(#7~#12)로 올려 133개 테스트 통과, 후속 #13(쿠키·`code`·CORS)은 로컬 커밋 상태이며 모두 미머지. 위 ERD 표(`tbl_` 9개)와 달리 노션 ERD는 현재 24 MySQL + 8 Redis 엔티티이고, 구글 로그인은 `users.google_sub`/`google_email` 두 컬럼, 온보딩은 `users.onboarding_status`(`NOT_STARTED`/`SKIPPED`/`DONE`)로 구현됐다. 상세는 [[JKYMHS-Backend/인증-API-구현과-PR-리뷰-결정사항]].

## 최근 상태 (2026-11-10)

## 상충하는 정보: 이 레포는 "라면 실험실"인가 "어디갈래"인가
- 위 위쪽 내용(`tbl_` 9개 테이블·"라면 실험실")은 2026-10-09 기준 옛 메모다. 2026-10-22~11-01 세션에서 사용자가 붙여넣은 프로젝트 문서는 이 레포를 **어디갈래**(사용자 취향+여행 조건→AI가 TourAPI 관광지·축제 코스를 일차별로 생성→일정 저장→구글 캘린더 업로드)의 백엔드로 정의했고, 예전 "라면 실험실" 메모는 삭제됐다. 노션 아카이브에도 "라면 실험실 ERD 9테이블/API 10개" 기록이 남아 있어 한때 혼선이 있었다. 현재 기준은 어디갈래(API 51개).
- **기준 문서 순서**: 프로젝트 문서 → API 명세서(Request/Response/Exception/설계 메모) → 기능 명세서(FUNC-001~006) → ERD. 노션 "🧳 여기갈래 기획" 페이지(9월 초안)는 **옛 문서**로 보고 로드맵·포폴 지표 참고용으로만 쓴다(캐시 Caffeine vs 상세 명세 Redis, 로그인 구글만 vs 이메일+구글, API 7개 vs 51개, 추천 동기 5초 vs 202+폴링 등이 다름). 포폴 방식은 "기능 완성→개선 전 측정→커밋→개선→측정→커밋"(EXPLAIN·p6spy·k6)이라 처음부터 최적화하지 않고 before 버전을 먼저 커밋한다.
- **ERD**는 ERDCloud 공유 링크(Meteor SPA라 `curl`로는 내용이 안 받아져 Chrome으로 열어 페이지 데이터를 직접 읽음, JS 도구 출력이 ~1000자에서 잘려 나눠 덤프). 구성: MySQL 24개(회원 `users`·`refresh_tokens`·`user_consents`·`google_calendar_links`, 취향, 탐색 `contents` 등, AI 추천, 일정 `schedules`·`schedule_items`, 캘린더·배치) + 문서용 `redis_*` 8개(엔티티 만들지 않음). 문서끼리 다른 점: ERD에 Redis 표가 있음(원 문서는 "ERD는 RDB만"), `recommendation_requests.result_json`과 Redis `rec:result:*`가 결과를 이중 보관, `auth:link`가 ERD Redis 표에 없음(Redis 키 설계 문서가 기준), UNIQUE가 주석에만 있어 `@UniqueConstraint`로 직접, `users`에 탈퇴 컬럼이 없음. 설계 포인트: `schedule_items.snapshot_*`(원본 변경·삭제에도 저장 일정 유지), `behavior_events.schedule_id` 등 **의도적 FK 없음**(원본 삭제 후에도 기록 유지), `schedules.version` 낙관적 락 → [[낙관적-락-version-스테일-수정-방지와-PUT-전환]].
- **API 명세서 ↔ 에러 코드 DB 충돌**(명세서가 10/06 수정으로 더 최신·상세해 명세서 기준 권장): 인증코드 만료 410(명세) vs 400, 로그인 잠금 423 vs 429, 비밀번호 영문+숫자 8~20자 vs 정확히 6자. 에러 코드 DB에 `METHOD_NOT_ALLOWED`(405)·`SERVICE_UNAVAILABLE`(503, Redis 장애) 추가 필요.

## 초기 세팅 결정과 이유 (2026-10-22 세션)
- 스택: Spring Boot 4.1.1, Java 21(toolchain, 기본 java는 17), Gradle 9.8.2 wrapper, 의존성 web·validation·JPA·MySQL·Redis·Lombok(Security는 로그인 작업 때 추가). 패키지 `com.jkymhs.backend`.
- **Spring Initializr에 `bootVersion`을 직접 지정하면 500**이 났다(Initializr 쪽 문제로 추정, 기본값이 이미 4.1.1이라 파라미터를 빼고 생성). 한글 설명도 뺐다.
- `application.yml`: `${DB_HOST:localhost}` 형식(환경변수 있으면 그 값, 없으면 로컬 기본값 → 배포는 환경변수만 바꾸고 비밀번호를 코드에 안 넣음), `open-in-view: false`(응답이 끝날 때까지 DB 연결을 붙잡지 않음, 서비스 밖 지연 로딩은 에러가 나지만 실수를 일찍 잡아 정석), `serverTimezone=Asia/Seoul`+MySQL `TZ`(하루 10회 KST 자정 초기화 같은 규칙 때문에 처음부터 KST), `utf8mb4`(한글·이모지), `ddl-auto: update`(로컬 개발용, 실제 설계는 ERD 기준).
- **`application.yml` 값·구역 보충 (2026-11-11)**: `${이름:기본값}`은 환경변수가 있으면 그 값·없으면 기본값이고 `${GOOGLE_CLIENT_ID:}`는 빈 문자열 기본값, `${JWT_SECRET}`은 기본값 없음(없으면 기동 실패). **`ddl-auto`** 값: `update`(없는 테이블·컬럼만 추가, 있는 컬럼은 안 지움)·`validate`(엔티티와 테이블이 다르면 기동 실패)·`create`(매번 지우고 새로 생성, 데이터 소멸)·`none`. 로컬은 `update`, 실서비스 DB는 `JPA_DDL_AUTO`로 `validate`/`none` 권장. `google:`(client-id·client-secret·token-uri·user-info-uri)은 기본값을 빈칸으로 둬 **구글 설정이 없어도 서버는 뜨고 구글 로그인만 실패**(`JWT_SECRET`과 반대 — 없어도 다른 기능은 도는 값이라서). `jwt:`·`google:`은 Spring 자체 설정이 아니라 직접 만든 설정이라 `spring:` 밖 최상위에 두고 `@ConfigurationProperties(prefix=…)` record(`JwtProperties`, `GoogleOAuthProperties`)로 읽으며 yml의 `client-id`(케밥)가 Java `clientId`(카멜)에 자동 연결된다. `show-sql`·`format_sql`은 개발 중 실제 쿼리 확인용.
- `compose.yaml`(MySQL 8.4·Redis 7.4): `docker compose up -d`/`ps`/`down`(데이터는 `mysql-data` 볼륨에 남음)/`down -v`(볼륨까지 삭제). DB 없이 서버를 켜면 `Communications link failure`. 꺼진 `spring-practice-mysql` 컨테이너도 3306을 써서 동시에 켜면 충돌.
- Git: `main`과 같은 지점에서 `develop`을 만들어 GitHub **기본 브랜치**로(PR 대상이 자동으로 develop이 되어 main 실수 머지를 줄임), 기능은 `이슈번호-타입-설명`(예: `1-chore-common-base`) 브랜치에서 develop으로 PR. 커밋은 **제목 한 줄만**(본문·Co-Authored-By 없음) — 이미 푸시한 커밋의 메시지를 고쳐 `--force-with-lease`로 덮었다(아무도 clone하지 않았을 때만 부담이 없음). 이슈 #1~#6을 `bium-be` 형식으로 만들고 담당자 `yunho09`, 이슈 생성 스크립트를 zsh로 돌리면 배열이 1-indexed라 실패해 bash로 재실행.
- 사용자는 백엔드 입문 중이라 **코드는 직접 치고 Claude는 방향·리뷰**를 맡는 방식, 설명은 항목별·자바 코드로(JS 비유 요청 철회). 공통 기반 구현은 [[JPA-Auditing-동작-원리와-EnableJpaAuditing-분리-이유]], [[Redis-장애-503-타임아웃-실측과-WebMvcTest-테스트-함정]], IntelliJ 환경 문제는 [[IntelliJ-심볼릭-링크-중복-루트로-New-Java-Class-안-뜸]].
- 개발 순서 계획(auth 8개 API): 공통 기반 → `users` → Security·JWT → 이메일 인증 → 가입·로그인 → 토큰 → 구글. `link` API가 없으면 `LINK_REQUIRED` 사용자가 로그인할 방법이 없어 8번째로 포함했고, 구글 `SIGNED_UP`은 필수 약관 동의 전까지 다른 API가 403이라 `PATCH /members/me/consents`가 필요하다(P1 범위 미정이었음).
