# JKYMHS-Backend 프로젝트 현황

**라면 실험실** 백엔드(Spring Boot + Gradle, 경로 `/data/project/JKYMHS-Backend`). ERD는 `tbl_` 접두사 9개 테이블이며, 도메인형 패키지 구조로 `domain/user/entity`까지 폴더만 만든 초기 상태(2026-10-09 기준). 엔티티 이름 규칙과 확정/미결 결정을 정리한다.

## ERD 테이블 → 엔티티 매핑
- `tbl_` 접두사는 테이블명에만 쓰고 클래스명엔 붙이지 않는다 (`TblUser` ❌).

| 테이블 | 엔티티 | 패키지 |
|---|---|---|
| `tbl_user` | `User` | `domain.user.entity` |
| `tbl_email_verification` | `EmailVerification` | `domain.auth.entity` |
| `tbl_refresh_token` | `RefreshToken` | `domain.auth.entity` |
| `tbl_ramen` | `Ramen` | `domain.ramen.entity` |
| `tbl_topping` | `Topping` | `domain.ramen.entity` |
| `tbl_experiment` | `Experiment` | `domain.experiment.entity` |
| `tbl_experiment_photo` | `ExperimentPhoto` | `domain.experiment.entity` |
| `tbl_review` | `Review` | `domain.review.entity` |
| `tbl_bookmark` | `Bookmark` | `domain.bookmark.entity` |

- **`User` 이름 충돌 주의**: Spring Security에도 `org.springframework.security.core.userdetails.User`가 있다. `UserDetailsService` 구현 시 import하지 말고 FQN(`...userdetails.User.builder()`)으로 쓰거나 `CustomUserDetails`를 따로 만든다. `Member`로 피하는 방법도 있으나 ERD가 `tbl_user`라 `User` 유지를 권장.

## 확정된 결정 (2026-09-14)
- `tbl_user.password`는 `VARCHAR(60)` 유지 → `SecurityConfig`에서 `DelegatingPasswordEncoder`(`{bcrypt}` 접두사로 68자) 대신 순수 `BCryptPasswordEncoder` 사용.
- 이메일 인증은 **가입 전**에 끝낸다 → `tbl_user.email_verified` 컬럼 불필요, "미인증 로그인 차단" 규칙 폐기. 대신 **가입 API에서 해당 이메일의 인증 레코드가 verified이고 만료 전인지 반드시 재검증**(안 하면 인증 우회 가능).
- 패키지는 도메인 기반 `domain.<feature>/{controller,service,repository,entity,dto,exception}` + `global/` ([[도메인형-패키지-구조]]).

## 미결
- 이메일 인증 / 리프레시 토큰 저장소: Redis vs 테이블
- 토핑: 콤마 문자열 vs 조인 테이블
- `tbl_ramen`/`tbl_topping` 관리용 `role` 컬럼이 ERD에 없음
- 회원 탈퇴 시 FK·S3 정리 정책
- `image_url`과 `s3_key` 중복

## 최근 상태 (2026-11-03)
- 인증 #2~#6을 스택 PR(#7~#12)로 올려 133개 테스트 통과, 후속 #13(쿠키·`code`·CORS)은 로컬 커밋 상태이며 모두 미머지. 위 ERD 표(`tbl_` 9개)와 달리 노션 ERD는 현재 24 MySQL + 8 Redis 엔티티이고, 구글 로그인은 `users.google_sub`/`google_email` 두 컬럼, 온보딩은 `users.onboarding_status`(`NOT_STARTED`/`SKIPPED`/`DONE`)로 구현됐다. 상세는 [[JKYMHS-Backend/인증-API-구현과-PR-리뷰-결정사항]].
