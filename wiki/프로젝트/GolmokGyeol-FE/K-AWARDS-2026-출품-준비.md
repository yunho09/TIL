# 골목결 K-AWARDS 2026 출품 준비 — 서버 없이 "구운 결과" 데모와 소개서 수치 함정

[[GolmokGyeol-FE/프로젝트-현황]]의 골목결을 K-AWARDS 2026 고등부 AI 서비스 혁신 부문에 팀으로 내기 위한 준비 기록. 백엔드 데이터가 사라진 상태에서 **서버 없이 7월 실제 검색 결과를 저장해 정적 데모**로 낸 방법과, 별도 리뷰로 드러난 **소개서 수치·표현의 과장 지점**이 핵심이다.

## 대회 요건 (2026-11-03 확인)
- 고등부는 **AI 서비스 혁신**과 AI 콘텐츠뿐(공공·ESG는 대학부). 마감 **11/9(월) 23:59**, 발표 11/20, 시상 12/22. 무료, 팀 최대 4인 권장·대표 1인 접수.
- 제출: 신청서 + 포트폴리오 PDF·디자인 시안·시연 영상 등. **사용한 AI 도구와 범위, 직접 한 부분을 구분해 기재**해야 함.
- 심사: 기획·창의성 30 / AI 활용 적합성 25 / 구현·디자인 25 / 실용성·전달력 20.
- 서버·URL은 FAQ상 "있다면" 넣는 선택 사항. 다만 부문 정의가 "작동형 프로토타입"이라 URL이 유리. 신청 폼 필수칸 여부는 로그인 뒤라 미확인. 해커톤 출품작 재출품 가능 여부는 공지에 없음(운영사무국 문의 필요).

## 방법 선택: 실제 결과 미리 굽기
| 방법 | 평가 |
|---|---|
| 전체 서버 배포 (Postgres+pgvector, Redis, FastAPI 2개, API 키 2개) | 7일엔 과하고 운영비 |
| **실제 결과 미리 굽기** | 실제 엔진 결과를 JSON으로 FE에 넣고 정적 배포. 준비한 검색어만 동작하므로 그 점을 밝혀야 함 |
| 완전 목 서버 | 가장 빠르나 AI가 안 돌고 가짜 데이터. 검색 근거 문장이 어긋나 "이 문장 때문에 여기 있어요"가 설득력을 잃음 |

- **백엔드 `data/`**(`stores.csv`, `reviews.ckpt.json`(코드가 실제 읽는 이름), `snippets.jsonl`, `embeddings.npy`)는 `.gitignore`라 레포에 없고 팀원도 보관하지 않아 소실. 재수집하려면 공공데이터·네이버·Voyage·Anthropic 키 4개 필요(후기 수집 전체 약 40분 예상).
- **대안 데이터 원천: 브라우저 localStorage 캐시.** 앱이 검색 결과를 `golmokgyeol-search-cache-v1` 키로 저장하므로, 7월에 쓰던 Chrome의 `localhost:5173`에서 이 키만 읽어 실제 응답을 복원했다(프로필 폴더 통째 복사는 권한에서 막힘 → 키 하나로 범위를 좁히고 사용자 허락 후 진행). 결과: **둔산동 검색어 8개, 가게 412곳**.
- FE는 `src/api/golmok.ts`를 고쳐 서버 없이 도는 **정적 모드**(구운 JSON)를 추가. 로컬 브랜치 `feat/k-awards-static-demo`(미커밋). 구운 데모 스크립트는 `scripts/bake-from-cache.mjs`.
- 알려진 한계: 캐시 구조상 "비슷한 집"은 따로 처리 필요, 데모는 **5개 동·검색어 8개만** 동작, 준비 안 된 검색어는 안내 문구. `public/demo`는 git 제외라 레포만으로는 데모 재빌드 불가. 샘플 데이터를 `public/demo`에 둔 채 배포하면 안 됨.
- 시연 영상(59초, 무음+자막)은 서두에 "저장된 결과 재생"임을 밝힘.

## 배포: Vercel
- Cloudflare도 가능했으나 Vercel을 택함. 둘 다 **로그인은 사용자가 직접**: `npx vercel login`(device 코드 승인) 후 배포.
- 로그인 없이 되는 **익명 임시 배포는 60분 뒤 사라지고 접속도 403**이라 팀원 공유용으로 못 씀.
- 결과: `https://golmokgyeol-demo.vercel.app` (영상·소개서 PDF를 `/files/`에 포함). 공개 URL은 링크를 아는 누구나 접근 가능하고 가게명·주소·블로그 발췌문(가게당 3개, 출처 링크)이 노출되므로 **검색엔진 수집을 막아 둠**, 대회 후 내릴 수 있음.

## 소개서 수치·표현 점검에서 나온 함정 (별도 리뷰어가 코드와 대조)
옛 `PITCH.md`·발표 자료의 표현이 코드 실제와 달라, 소개서에서 아래처럼 고쳤다. 심사 질의에서도 같은 점을 조심할 것.

| 전에 쓴 표현 | 실제 |
|---|---|
| 실제 시스템에 넣고 셌다 (99.5%·96.1%·93.1%·14.5배) | `scripts/exposure.py`는 점수 규칙을 옮긴 **오프라인 복제**. 파서·업종 필터가 없고 실제 경로는 카테고리로 거름. 7월 측정값을 문서에서 옮긴 것이라 이번에 재측정 못 함 |
| 후기 N건 | 가게별 블로그 검색 **상위 50건 중 필터 통과 수**(데모 최대 48) |
| 후기 문장 67,540개, 문장마다 임베딩, 원문 그대로 | 블로그 검색 API가 주는 **발췌문 통째**(데모 텍스트의 81%가 "..."로 끝남) |
| 축을 검증한다 | 재기만 하고 **실패해도 그 축을 그대로 사용**(예외일 때만 fallback) |
| 기존 방식과 비교 | 같은 결과를 후기 수로 정렬해 본 비교 |
| 협찬·비음식 제거 | 제목+발췌문 키워드 검사뿐이라 샘플에서 꽃집 글이 술집 검색에 걸림 |

- 같은 "후기 적음"도 기준이 둘: 소개서는 ≤15건, 백엔드는 ≤5건(다이아몬드)/20슬롯 예약.
- 임베딩 모델은 옛 발표(Gemini)와 달리 코드 기준 **Voyage**.
- 출처 못 찾은 수치(폐업률 45.2%, 폐업 47,820건, 네이버 노출 수치)는 소개서에서 제거 — 팀 문서도 네이버 알고리즘은 주장하지 않는다고 함.
- 리뷰어 코드 지적(참고): `bake-from-cache.mjs`의 가드가 `ai.mock_main` 결과(`s_` ID)를 실제로 오인할 수 있음, `useTasteStore`의 `taste`가 영속화 안 돼 URL 편집 시 [0,0]으로 초기화(선재 문제).

## 신청 폼 실제 구조와 제출 (2026-11-11 갱신)
- 사이트에 **내려받는 신청서 양식 파일은 없다.** 로그인 후 신청 페이지의 칸을 직접 채우는 방식이라, 미리 쓴 신청서 `.md`는 업로드용이 아니라 칸에 붙여 넣을 문안 모음이었다.
- 확인된 칸: 참가자 정보(`이름 / 학교 / 학년` 한 줄씩), 작품 한 줄 소개, **AI 활용 및 제작 내용(1,000자 제한, 작성안 731자)**, 작품 확인 URL, 작품 자료 첨부.
- **첨부는 파일 1개만 가능** → 소개서 PDF + 시연 영상을 ZIP 하나(3.6MB)로 묶어 제출.
- AI 활용 칸 구성 결정: `[서비스 안의 AI]`(Voyage voyage-3 임베딩·MAX pooling, Claude Haiku 4.5의 질의 분류·취향 축 제안, "LLM이 가게를 평가하거나 근거를 지어내지 않는다") / `[제작 내용]`(기획·프론트엔드·백엔드·AI 엔진 역할을 **이름 없이** 기재) / `[제작에 쓴 AI 도구]`(Codex, Claude, Claude Code). 처음엔 "사람이 직접 한 부분"을 사람별로 썼으나 사용자 지시로 이름·"사람이 했다" 표현을 빼고 "제작 내용"으로 바꿈. 대회가 요구하는 "직접 한 부분 구분"은 소개서 PDF 11쪽 역할표가 보완.
- 팀 역할(기획/프론트·시연/백엔드·AI 엔진/발표·디자인)은 팀원 답 없이 사용자가 "적당히" 나누라고 해서 Claude가 정한 것 — 제출 전 팀원 확인 필요하다고 안내함.
- **제출 완료.** 결과 발표 11/20, 시상 12/22.
