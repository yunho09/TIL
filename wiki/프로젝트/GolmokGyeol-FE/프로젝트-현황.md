# 골목결(GolmokGyeol-FE) — 취향 지도 서비스 개념과 로컬 실행

별점·인기 순위 대신 **"내가 오늘 앉고 싶은 자리"** 기준으로 동네 식당을 찾게 해 주는 웹 서비스(2026-DSM-8 팀, 2026-07-13~15 대회 3일 제작). 핵심 개념은 지도가 **위치 지도가 아니라 키워드(분위기) 기반 "취향 지도"**라는 점이다. 프로젝트를 모르는 사람에게 설명할 때의 요점과, 백엔드 없이 로컬에서 띄우는 방법을 정리했다.

## 설명할 때 가장 먼저 짚을 것: 지도는 위치 지도가 아니다
- 가로·세로축이 위치가 아니라 **키워드**(예: 조용히↔왁자지껄, 오래 머물기↔후딱 한 끼).
- 지도에서 가까운 두 가게 = 거리가 가까운 게 아니라 **분위기가 비슷한 가게**.
- 축은 **검색할 때마다 바뀐다**. 예: "삼겹살" → "무한리필↔단품 주문", "노포↔트렌디". 후기 내용에서 찾아낸다.
- 길찾기를 누를 때만 실제 위치를 네이버 지도로 보여 준다.

## 사용 흐름
1. 동네 선택(대전 은행동·둔산동 등) → 2. 자연어 검색("혼자 조용히 밥 먹기 좋은 곳"; "맛집"처럼 막연하면 "혼자? 친구랑?" 되묻기) → 3. 취향 지도에 결과가 점으로 펼쳐짐 → 4. 주황색 "내 취향" 점을 끌면 근처(분위기 비슷한) 5곳 추천 → 5. 가게 상세(실제 후기 문장, 자주 나오는 말, 길찾기, 비슷한 가게).

## 만든 이유·차별점
- 대회 주제 "로컬 상권 활성화". 은행동 직접 집계: 후기 있는 식당 412곳 중 202곳이 후기 15건 이하 → 후기 수 순위로는 묻힘. 새 가게 홍보가 아니라 **묻혀 있던 가게에 손님이 닿게** 하는 것이 출발점.
- 순위가 하나가 아니라 **사람마다 점 위치가 달라 추천이 달라짐**.
- **추천 이유로 실제 후기 문장을 요약·가공 없이 그대로** 보여 줌.
- 후기 적은 가게를 숨기지 않음: 후기 충분=원, 적음=마름모, 기록 없음=별 + "후기 정보 적음" 표시.
- 별점·매칭률·순위 숫자를 보여 주지 않고 취향 가까운 순으로만 나열.
- 규모: 대전 5개 동 식당 4,488곳, 네이버 블로그 후기 문장 67,368개. 스택은 React 19·Vite·TypeScript·Emotion·zustand, 지도는 SVG.

## 로컬 실행 (2026-10-21 기준)
- 프론트는 `npm run dev`로 바로 뜨지만 검색·지도는 **백엔드 필요**. 설정의 서버 주소(`10.217.46.220:8000`)는 대회 때 팀원 노트북 주소라 지금은 응답 없음.
- 실제 백엔드는 GitHub 비공개 레포(2026-DSM-8/backend)이고 식당·후기 데이터는 레포에 없어 팀원에게 받아야 하며, Docker·uv도 필요 → 직접 띄우기 어려움.
- 대안: **목 서버**. 가짜 식당 32곳(13곳은 "후기 적음", 6개 동 모두 같은 목록에 주소만 다름)을 주는 `mock-server/server.mjs`를 프로젝트 폴더에 추가(git 제외, 프로젝트 코드는 미수정). 동 목록·검색·지도 드래그·상세·비슷한 가게·막연한 검색 되묻기 응답까지 터미널에서 확인(화면 클릭 점검은 안 함).
- 실행(프로젝트 폴더에서 터미널 두 개):
  ```
  node mock-server/server.mjs                                   # 포트 8790
  VITE_API_BASE=http://localhost:8790 npx vite --port 5180
  ```
  → http://localhost:5180. 종료는 두 프로세스 중지(포트 8790·5180 해제 확인).
- `VITE_API_BASE`로 API 주소를 덮어쓸 수 있다는 점이 목 서버 연결의 열쇠.
