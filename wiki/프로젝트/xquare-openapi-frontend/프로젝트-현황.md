# xquare-openapi-frontend 프로젝트 현황

team-xquare의 DSM Open API 문서 사이트 프론트엔드(Next.js 16.4 + React 19 + Emotion). Figma "4. 문서 Overview" 화면을 퍼블리싱해 PR #5로 머지했고(이슈 #3), 내용이 백엔드 API 명세와 어긋나는 부분은 이슈 #4로 미뤄 둔 상태다.

## 스택·컨벤션
- Next.js 16.4(Turbopack), React 19.3, TypeScript, Emotion(`@emotion/styled`, 자체 `EmotionRegistry`), React Compiler. `next.config.ts`에 `cacheComponents`·`partialPrefetching`·`experimental.agentFeedback` 사용.
- 컴포넌트는 `이름.tsx` + `이름-style.ts` 두 파일, `memo(Component)`, 색은 `Xquare_colors`(`src/styles/colors.ts`)에서 import.
- 스타일 전용 props는 HTML 속성과 안 겹치는 이름(`isCode`, `labelWidth`, `cellWidth`, `isHighlighted`)을 써서 DOM으로 새지 않게 한다.
- Emotion styled는 서버 컴포넌트에서 못 쓰므로 `page.tsx`에 `"use client"`가 필요(컴포넌트 barrel이 사이드바·Emotion을 끌어옴).
- 폰트: Pretendard는 `next/font/local`, 코드블록용 Roboto Mono는 `next/font/google`(`--font-roboto-mono`). 빌드 시 인터넷이 필요하다는 점이 유일한 주의점.
- Figma에 변수/토큰이 없어 색이 하드코딩이었다. 기존 `gray`와 값이 달라 Figma 회색 5종(50/200/400/600/900)을 `slate` 그룹으로 따로 추가했다.

## 문서 공통 컴포넌트 (`src/components/docs/`)
- `DocBadge`, `DocSection`(제목+설명+본문, `DocSectionNote` 포함), `CodeBlock`(`highlightLines`로 특정 줄만 보라색), `InfoList`(키-값 목록, `isCode`면 모노 폰트), `DocTable`(열별 `variant`: default/strong/muted/code/accent), `StepCards`, `NoticeCallout`.
- 엔드포인트 상세·활용신청 같은 다른 문서 화면에서 반복될 패턴이라 페이지에 박지 않고 분리했다.
- 페이지 텍스트는 전부 `src/app/overview-content.ts`에 모아 두었다. "[확정 필요]"가 많은 문서라 명세가 바뀌면 이 파일만 고치면 된다. `page.tsx`는 조합만 한다.

## Figma와 다르게 한 것
- 본문 폰트는 Gothic A1이 아니라 프로젝트 공통 Pretendard → 상단 설명이 Figma에선 두 줄, 구현에선 한 줄.
- 메타 정보 제목 아래 간격 24px → 다른 섹션과 같은 20px로 통일.
- 범위 밖으로 둔 차이: 사이드바 너비(Figma 300px, 코드 `SIDEBAR_WIDTH` 280px), 사이드바 검색창·하단 XQUARE 배지 미구현.

## Overview 내용 vs API 명세 (이슈 #4로 이월)
기준 명세는 `team-xquare/xquare-openapi-backend`의 `docs/openapi.yaml`·`docs/api-spec-notes.md`(2026-10-14, 백엔드 구현은 아직 없음). Figma Overview는 기준일 2026-08-26의 옛 내용이고, 같은 파일의 「엔드포인트 본문」 프레임(2026-09-12)은 명세와 맞는다. 코드는 Figma를 그대로 옮긴 거라 같은 오류를 갖는다.
- 로그인은 `email`이 아니라 **`username`**+`password`, 응답은 감싸는 구조 없이 `{ accessToken, refreshToken }`. 재발급은 `POST /auth/reissue`.
- 학생 조회 쿼리는 `?grade=2&classNum=3`(숫자, 이름은 `classNum`), 토큰 만료 시간은 **미정**(`expiresIn` 필드도 없음).
- OTP 인증은 로그인이 아니라 **회원가입** 단계, `EMAIL_NOT_VERIFIED`도 회원가입 오류. 토큰 오류는 `INVALID_TOKEN`(401)로 `INVALID_CREDENTIALS`(로그인 실패)와 분리, `FORBIDDEN`(403) 누락.
- 응답 형식은 이미 통일: 성공=데이터 그대로, 실패=`{ code, message }`, 목록=`{ content, page, size, totalCount, totalPage }`. 엔드포인트는 38개 전부 확정, 구분 8개(자습 감독 포함). 사이드바 ENDPOINT 메뉴에는 자습 감독·공지가 없다.
- 접근 권한: ALL은 인증 API 5개+급식 조회 2개, USER는 급식을 뺀 모든 조회, ADMIN은 등록·수정·삭제.
- Figma의 "응답 형식 B" 예시는 키 없는 배열+쉼표 누락으로 JSON 문법 자체가 틀림(CodeRabbit도 지적).
- 예시 데이터에 실명처럼 보이는 이름·생일이 들어 있어 명세의 "김준서"로 바꾸는 게 좋음.
- **결정**: 이번 PR(#5)은 Figma 그대로 퍼블리싱하는 범위로 두고, 내용 수정은 Figma가 고쳐진 뒤 `overview-content.ts`만 고치는 #4(`[FIX]`, 라벨 DOCS)에서 처리. CodeRabbit 지적에도 같은 이유로 코드 수정 없이 답글만 남겼다. Figma 수정은 노드 ID별 프롬프트로 정리해 디자이너/Figma MCP 세션에 전달하는 방식.

## AGENTS.md 자동 블록
- `AGENTS.md`의 "This is NOT the Next.js you know"는 AI 코딩 도구가 코드 짜기 전에 `node_modules/next/dist/docs/`를 먼저 읽게 하는 안내.
- `next.config.ts`에 `experimental.agentFeedback`이 켜져 있으면 `next dev` 실행 때 "Report Next.js feedback" 블록이 **자동으로 추가**된다(Next.js 문제를 만나면 익명 피드백으로 보내라는 안내, 코드·경로·개인정보는 제외).
- 빼고 PR을 올려도 누구의 `next dev`에서든 다시 생겨 "수정됨"으로 떠 있다가 언젠가 다른 PR에 섞이므로, 별도 `chore:` 커밋으로 넣기로 했다. 끄고 싶으면 파일이 아니라 `agentFeedback` 옵션을 끄는 팀 결정이 필요.

## API 테스트 페이지 퍼블리싱 (이슈 #10 → PR #11, 2026-10-27)
Figma `API 테스트 · 콘솔`을 `/api-test`로 퍼블리싱(요청 바, 인증·요청 카드, 응답 카드, 호출 히스토리). 파일은 `src/app/api-test/{page.tsx,page-style.ts}` + 더미 데이터 `src/app/api-test-content.ts`(`notice-content.ts`와 같은 방식). 커밋은 더미 데이터 / 헤더·요청 바 / 인증·요청 카드 / 응답·히스토리로 4개.
- **동작 범위**: 입력·탭 전환·Body JSON 미리보기(비밀번호는 `••••`)·응답/cURL 복사까지. `보내기`의 실제 요청, 응답·히스토리는 더미(API 연동 때 구현). 시안엔 Body 탭만 그려져 있어 Params(URL 쿼리)·Headers·cURL 탭 내용은 임의로 정했다.
- **시안과 다르게**: 파란색 `#2563EB` 대신 가장 가까운 토큰 `blue[400]`(`#256EF4`), 코드 블록 폰트는 Overview와 같은 고정폭. 1024px 이하에서 두 열이 한 열로 쌓임.
- **알려진 한계**: 시안 사이드바에 API 테스트 메뉴가 없어 주소로만 접근되고, 이때 사이드바는 일치 메뉴가 없으면 Overview를 기본 선택으로 보여 Overview가 활성처럼 보인다. 안내 문구의 "키는 브라우저에만 저장"은 실제로는 state뿐이라 새로고침하면 사라짐.
- **Figma 함정**: 레이어 안에 높이 1px짜리 숨은 프레임이 있고 화면엔 안 보이는 "주요 공지사항" 목록이 들어 있었다 → 퍼블리싱에서 제외.
- **리뷰 반영 사항(일반화 가능)**: ① cURL 복사 문자열 — URL·헤더를 큰따옴표에 그대로 넣으면 `$(…)`·`"`·백틱이 셸에서 치환/깨짐, 모든 보간 값을 작은따옴표 + `'`→`'\''` 헬퍼로 감싼다([[curl-API-호출-예시-쉘-인용-규칙]]). ② `role="tab"`을 쓰려면 `tabpanel`·`aria-controls`/`aria-labelledby`·roving `tabIndex`·방향키까지 필요, 아니면 role을 빼고 `aria-pressed` 버튼이 더 싸다. ③ 테스트 대상 API의 자격증명 입력에 `autoComplete="current-password"`/`username`을 주면 이 사이트 로그인 정보가 자동완성되므로 `off`/`new-password`. ④ `navigator.clipboard.writeText`는 `void`만 하지 말고 `.catch`(권한 거부·비보안 컨텍스트).

## admin 일정·로그인·403 퍼블리싱 (이슈 #40·#41 → PR #44·#45, 2026-11-11 머지)
`apps/admin`(Next 16.4, dev 포트 3001)에 일정(`/schedule`·`/new`·`/[id]/edit`), 관리자 로그인(`/login`), 권한 없음(`/forbidden`)을 퍼블리싱했다. 공지 화면 구조(`notice/`)와 스타일을 그대로 재사용. 로그인·재발급 연동 #42는 백엔드 명세(엔드포인트·서버 주소·토큰 저장 방식)가 없어 대기. 브랜치 `feature/#N`, 커밋은 화면 단위로 분리.
- **사이드바 숨김**: `AppLayout`이 `FULL_SCREEN_PATHS = ["/login","/forbidden"]`에 `usePathname()`이 일치하면 `Sidebar`만 빼고 `Page`는 같은 위치에 둬 상태 보존을 깨지 않는다(`data-full-screen` 속성+CSS 선택자, prop 누수 없음).
- **`cacheComponents` 함정**: 숨겨진 라우트도 state가 유지돼 폼 입력·모달이 남으므로 `useLayoutEffect` cleanup으로 초기화·모달 닫기. 동적 edit 라우트는 `generateStaticParams`+`Suspense`+async 컴포넌트의 `notFound()`.
- **Emotion prop 누수**: `styled.span<{ width: number }>`의 `width`는 `@emotion/is-prop-valid`가 통과시켜 `<span width="140">`이 DOM에 나온다(경고 없음). `shouldForwardProp`으로 막거나 `data-*` 속성을 쓴다. `source`처럼 목록에 없는 이름은 안 새지만 허용 목록에 의존해 취약.
- **표 높이**: `border-collapse`에서 `height`는 아래 테두리 1px을 포함하므로 Figma 48+1/56+1은 th 49·td 57px. 공지·일정 둘 다 맞췄다. 폼 버튼 위 간격은 20→30px.
- **flex 비율 함정**: 소개 영역이 995px로 나온 건 padding이 `flex-basis: 0` 비율 계산에 섞여서. `flex: 0 0 calc(100% * 1000 / 1728)`로 직접 지정.
- **날짜 입력**: 브라우저 기본 `type="date"`라 `2026. 09. 05.` 형식·"연도. 월. 일." 플레이스홀더가 Figma와 다름(직접 만든 선택기 필요).
- **환경변수**: 403 화면 "Open API 문서로" 링크는 `NEXT_PUBLIC_OPEN_API_DOCS_URL`을 빌드 시점에 인라인한다. `??`는 빈 문자열을 못 걸러 `href=""`(403 페이지 자신)이 되므로 `||`. 이후 **`next build`에서 값이 없거나 비면 에러로 멈추게** 해 배포가 로컬 주소를 가리키지 않게 했고, `next dev`는 `http://localhost:3000` 기본값. 팀 영향: 로컬 `npm run build`도 `NEXT_PUBLIC_OPEN_API_DOCS_URL=http://localhost:3000 npm run build`처럼 값을 줘야 한다.
- **사이드바**: `position: fixed`라 풀페이지 캡처에서 첫 화면 높이까지만 그려졌다. 사이드바와 본문을 나란히 두고 사이드바를 본문 높이만큼 늘리고 메뉴만 sticky로(공통 컴포넌트라 담당자 확인 요청).
- **시간표 카드(컴시간)**: 일정 화면에서 나이스 요소를 빼고 읽기 전용 시간표 표(학년·반·주 선택, 오늘 열 강조, 바뀐 수업 `변경` 배지, 빈 칸 `—`)로 교체. 날짜 계산은 UTC만 써서 시간대·hydration 문제 없음. 리뷰 반영: 요일 머리 칸에서 `월09-14`처럼 붙어 읽히던 것을 텍스트 공백으로 분리(시각 간격은 margin 조정), 선택한 주가 목록에 없을 때 지난 주 대신 기본 주로 폴백. `ColorGroup`이 인덱스 시그니처라 쓰던 색 토큰(`blue`)을 지운 뒤 `tsc`가 못 잡으므로 grep으로 잔재 확인.
- **알려진 차이**: Pretendard vs Gothic A1(버튼 폭 5~14px·머리말 3px), 로그인 버튼은 user 앱처럼 입력 전 비활성(Figma는 활성), `/forbidden`은 일반 페이지라 HTTP 200(권한 확인은 #42), `#C4B5FD`는 색 토큰에 없어 해당 레이아웃 파일에만, `나이스에서 불러오기`·`자습감독에서 관리`(`/supervisor` 404) 미구현.
- **검증 방법**: `npm run build` 후 `next start -p 포트`, Chrome에 1728px iframe을 넣고 `getBoundingClientRect`를 Figma 좌표와 비교. 브랜치를 바꾸면 `.next/types/validator.ts`가 사라진 페이지를 참조해 `tsc`가 실패하므로 build를 먼저. 다른 브랜치는 임시 worktree에 빌드해 포트를 분리. `pkill -f "next start …"`는 자기 셸까지 죽일 수 있어(exit 144) `ss -ltnp`로 PID를 찾아 kill.
- **리뷰어 에이전트·CodeRabbit**: 별도 리뷰어가 낸 접근성 지적(저대비 텍스트, 포커스 링, 활성처럼 보이는 무동작 버튼) 중 실제 버그만 고침. CodeRabbit은 고친 스레드는 해결 처리, 의도적으로 둔 것(Figma 문구 "5회 실패하면 계정이 잠깁니다."는 #42 연동 때 필요, JSDoc 대신 한국어 한 줄 주석 관행, 공지 수정은 같은 스타일이라 한 PR)은 이유를 남기고, 무관한 항목은 답글 없이 닫았다. 요약에만 있는 경고는 스레드로 못 닫는다.

## 공지 상세·API 테스트 GET 전환·비밀번호 찾기·admin 공지 (이슈 #8 → PR #9, 이슈 #22~24 → PR #25~27, 2026-10-22~11-01)
Next 개념 자체는 [[Next-16-App-Router-동적-라우트-서버-클라이언트-cacheComponents]] 참고. 여기엔 이 레포 결정만.
- **공지 상세 `/notice/[id]` (PR #9)**: 공지 더미 데이터를 `notice-content.ts`로 분리(목록·상세 공유, `all-content.ts`와 같은 규칙), `createdAt`/`updatedAt`(목록은 `slice(0,10)`), 서버 `page.tsx`+클라이언트 `notice-detail.tsx`+`page-style.ts`. 커밋 4개(refactor 데이터 분리 → 컴포넌트 → 페이지 → 목록 링크), 각 커밋에서 `tsc` 통과하도록 순서. 시안과 의도적으로 다르게: Gothic A1 대신 Pretendard, 회색 `#6B7280`→`gray[600]`, `#E5E7EB`→`slate[200]`, 사이드바 280/300px·여백·헤더 사용자 이름은 공통 부분이라 그대로. `/notice/999`는 404 화면이지만 HTTP 200.
- **API 테스트 → `GET /students` (#22/PR #25)**: Figma가 Body 탭에 둔 `grade`·`classNum`을 GET 쿼리라서 **Params 탭**으로(팀 결정). 입력칸 값을 따로 저장하지 않고 URL에서 바로 읽어 URL과 어긋나지 않게 했고, `parseUrl`은 잘못된 URL이면 `null`(입력칸 비활성+안내). Body는 GET일 때 막고 본문이 있을 때만 `Content-Type`. 리뷰에서 `new URL().toString()`으로 URL을 통째로 다시 만들면 한글이 `%ED…`로 바뀌고 `+`·끝 `/`가 붙는 버그를 잡아 `setQueryParam`(해당 키 부분만 문자열 치환, 9케이스 단독 시험)으로 교체. 요청 줄 미리보기는 서버로 가는 형태라 인코딩된 채 둠. 히스토리 GET 칩 색은 Figma 첫 줄 보라(옛 POST 색 잔재로 판단)를 파랑으로 통일.
- **비밀번호 찾기 `/forgot-password` (#23/PR #26)**: Figma 프레임 이름과 내용이 어긋남(3=학번·이름, 4=새 비밀번호, 완료 화면 없음) → 내용대로 이메일+인증코드 → 학번·이름 → 새 비밀번호 3단계, 변경 후 `/login`. 회원가입 `signup-validation`·`VerifyInputWrap`을 가져다 씀(같은 계정 비밀번호 규칙이라 공유가 맞지만, 회원가입에만 생기는 규칙이 몰래 들어올 결합 위험 → PR 본문에 알림, API 연동 뒤 `components/auth/`로 이전+`useAuthSteps` 훅 추출 예정). `FULL_SCREEN_PATHS`에 추가해 사이드바 숨김, 비활성 `PasswordHelpButton`을 `PasswordHelpLink`(링크는 인라인이라 `display:block` 필요)로 교체. 회원가입과 동일한 미해결: 2단계에 나갈 길 없음, 인증코드 발송 뒤 이메일 잠겨 오타 수정 불가(재전송/이메일 변경은 연동 때).
- **admin 공지 목록·등록·수정 (#24/PR #27)**: admin엔 색 토큰·공통 컴포넌트가 없어 **공통 패키지 없이 user `Xquare_colors`에서 필요한 것만 같은 이름으로 복사**(나중에 합치기 쉽게; 리뷰는 `packages/`로 빼라고 했으나 팀 결정 유지). 등록·수정이 `notice-form.tsx` 하나(`notice` 주면 수정), 저장은 제목·본문 있고 **trim 기준** 변경 있을 때만. 삭제 모달은 Figma에 공지용이 없어 디자인시스템 `Modal/Danger` 형태로 직접(디자이너 확인 필요), 네이티브 `<dialog>`·`취소`에 autoFocus·`returnValue==="confirm"`일 때만 삭제. 리뷰 반영: 뒤로→앞으로 시 backdrop 없는 모달(위 Next 페이지 §5), 삭제 후 포커스 상실→검색창으로, aria 라벨·`title`·모달 색 토큰화. 더미 5건이라 "전체 5건·1페이지"(시안 42건), 목록 삭제는 로컬 state라 수정 화면엔 남음(연동 전 한계). 새 빌드 직후 첫 실행에서 React #419가 12회 중 2회 나왔으나 재현 안 됨.
- **리뷰 판정 방식**: 리뷰어 에이전트·CodeRabbit 지적을 코드·Figma와 대조해 10개 중 3개만 고칠 가치(나머지는 이미 정한 사항·기존 코드와 동일·더미 데이터 한계), 회원가입과 같은 문제를 한 화면만 고치면 둘이 달라지므로 같이 정하기로 미룸. CodeRabbit 무료 리뷰는 시간당 1회.
- **운영 메모**: 세 브랜치를 보려면 로컬 전용 `preview/1101`(push 안 함)에 합쳐 user 3100·admin 3101로 `next start`(3000은 다른 프로젝트). 메모리 부족 시 Claude Code가 백그라운드 dev 서버를 자동 종료함(코드 문제 아님, `CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP=1`로 끔). 머지된 본인 브랜치는 내용이 develop에 들어갔는지 확인 후 로컬·원격 삭제, 팀원 브랜치는 건드리지 않음.
