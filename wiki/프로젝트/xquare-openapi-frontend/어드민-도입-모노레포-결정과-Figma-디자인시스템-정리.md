# 어드민 도입: 모노레포 결정과 Figma 디자인시스템 정리

xquare-openapi-frontend에 admin 앱을 추가하기로 하고, 모노레포로 가되 공통화 범위는 좁게 잡기로 했다. admin 시안에 코드가 아직 없는 시점을 이용해 Figma에 공통 디자인 시스템 페이지를 먼저 만들고, admin 화면 27개를 user 기준으로 맞춘 뒤 팀 결정 사항을 반영했다. 모노레포 세팅 방법은 [[Next-Turborepo-npm-workspaces-모노레포-세팅]].

## 모노레포로 가는 이유
- admin 화면이 user와 같은 생김새(보라 `#0B001A` 사이드바, 흰 콘텐츠, 보라 메인 버튼)이고, 사이드바 프레임 이름까지 같아 user 화면 복사본으로 보임.
- **다루는 데이터가 같다**(급식·일정·동아리·교직원·자습감독·학생·공지·활용신청 = user 사이드바 카테고리). 같은 백엔드라 API 타입·요청 코드 공유 이득이 디자인 시스템보다 큼.
- develop 기준 TS 약 4,500줄이라 지금 옮기는 게 가장 쌈.
- 같은 Next 앱에 `/admin` 경로를 넣는 안은 관리자 코드가 공개 사이트와 같이 배포되고 루트 layout이 user 사이드바를 감싸고 있어 기각. 레포 분리+npm 배포 디자인 시스템도 팀 규모 대비 버전 관리 부담이 커서 기각.

## "전부 공통" 대신 좁은 범위
- 공통 후보: 색·폰트 토큰, EmotionRegistry, Modal, Button, Input, 사이드바 **틀**. 규칙: **두 앱에서 실제로 쓰게 될 때 `packages/ui`로 올린다.**
- 한쪽만 쓰는 것: admin(표, 페이지 이동, Select/날짜/Textarea 폼, 통계 카드, 삭제 모달) / user(`code-block`, `step-cards`, `doc-table`).
- 사이드바는 overview·notice·ENDPOINT 처리가 코드에 박혀 있어 바깥 틀만 분리해야 함. 로그인 화면은 디자인이 달라 `AuthLayout`을 그대로 못 쓴다 → 결정: user 로그인 레이아웃 + "관리자" 표시만 추가(계정·도메인이 따로라 완전 동일은 혼동 우려).
- 배포: 앱 두 개 따로(admin 도메인·접근 제어 별도). xquare 배포 플랫폼이 하위 폴더 빌드를 지원하는지는 **미확인**. 관련 [[Cloudflare-Workers-Builds-모노레포-앱별-Worker]].
- 시기: 열린 브랜치를 develop에 먼저 머지한 뒤 한 번에 이동.

## 디자인 시스템 방향
- 시작 시점 user 쪽도 정리 안 돼 있었음: 발행된 XQUARE 라이브러리 없음, 버튼·입력 컴포넌트 없음, 색이 보라/파랑으로 섞임(모달 확인 버튼 `blue[500]` 등). 결정: **메인 색은 보라**, 파랑은 GET 표시 같은 정보성만.
- 순서: ① Figma 디자인 시스템 페이지(색 변수+Button/Input/Select/Textarea/표/모달/사이드바/페이지 이동) → ② admin 27개 화면 교체 → ③ 코드는 `packages/ui`, user 앱은 점진 이전.
- 완료분: admin 사이드바 27개를 Sidebar 컴포넌트 인스턴스로 교체(선택 메뉴 한 개만 흰색 → 공지·활용신청 동시 선택 모순 해소, 한 곳 수정으로 전체 반영). admin 본문 입력칸·버튼·표의 컴포넌트화는 **남음**.

## Figma ↔ 코드 불일치와 정리
- 색 이름: 코드 `colors.ts` 기준으로 맞춤 — purple/400 `#8A38F5`, purple/500 `#9650FA`(XQUARE 라이브러리는 400/500이 반대). 사이드바 너비는 코드대로 **280px**(Figma 300px → 280px로 수정).
- 코드에서 할 일: `colors.ts`에 red[100] `#FFEDED` 추가, 신청 완료 페이지에 만료일 표시, 키 재발급 시 만료일 재계산.
- admin 색은 Tailwind 기본색(`#7C3AED`, `#111827`)이었음 → XQUARE 변수(`#8A38F5`, `#1E2124`)로 1,743곳 교체. 버튼 높이 43/45px → 44px, 36/38px → 36px (원인: 1px 테두리가 높이 계산에 들어감. 디자인 시스템 Secondary 버튼도 같은 문제라 수정).
- admin 용어를 user API 문서에 맞춤: 동아리실→**사용 교실**, 담당 학급→**담당 학년·반**, 동아리 담당→**담당 선생님**, 일정 출처→"학교 입력", API 이름은 코드 엔드포인트 목록(월간 급식 정보 조회·학교 통합 일정 조회·동아리 정보 조회). 예시 데이터: 로그인 사용자 홍길동(교무부 부장), 개발 키 접두사 `xq_test_`, XQUARE 동아리 사용 교실 세미나 2-3.
- 반 → 학과: 1·2반 소프트웨어개발과, 3반 임베디드소프트웨어과, 4반 인공지능소프트웨어과(사용자 확인).

## 팀 결정 사항(반영 완료)
- 급식 조식·중식·석식 **한 끼 없는 날 허용**(필수 표시 제거). 나이스에서 불러온 급식도 **수정 가능**. 공지 수정해도 **작성자 고정**.
- API 키 **만료 1년**, 재발급하면 재발급일부터 새로 1년. 팀장 학생 삭제 시 "팀장이 비게 됩니다" **경고**.
- admin 403 화면 불필요 → "삭제 예정" 섹션으로 이동. 운영계정은 신청 화면이 없어 user 429의 "운영계정 전환 신청" 버튼을 "이용 조건 보기"로 변경.
- 학과는 학생 수정의 '자동 계산' 칸에만 표시(목록 필터는 반 필터로 충분).

## 남은 것
- 500 오류 문의처 "[확정 필요]"(실제 연락처 필요), 폰트를 Pretendard로 교체(플러그인으로 불가, 텍스트 스타일 11개만 바꾸면 반영; 현재 user·admin 본문 모두 Gothic A1 직접 지정).
- user 안에서 섞인 표현: API 이름(마이페이지 vs API 문서), 팀장/동아리 부장, "Welcome, Back"(코드에도 동일해 유지).
- 사이드바 보라 글자 대비 약 3.9:1(4.5:1 미만)이나 user 규칙과 같아 유지.

## 디자인 시스템 페이지 구성 (Figma `open-api` 파일 `design system` 페이지)
- 변수 65개: `XQUARE Primitives`(기본 색 26) / `XQUARE Semantic`(용도별 27: 배경·글자·테두리·버튼·상태) / `XQUARE Layout`(간격·모서리 12). 텍스트 스타일 11개(임시로 Noto Sans KR), 모달 그림자 1개.
- 컴포넌트 13종: Button(12가지), Badge, Input, Select, Textarea, 화살표 아이콘, Table Cell, Pagination(Item), Modal, Page Header, Sidebar(Item). 안내 프레임 Guide·Foundations 포함.
- 글 줄이기: Page Header 설명·입력칸 안내 문구는 기본 꺼짐, 상태는 Badge로 표시.

## Figma 작업 팁 (Claude 세션에서 확인)
- 플러그인 API로는 **댓글을 읽을 수 없고**(브라우저로 댓글 패널 확인), 설치되지 않은 폰트(Pretendard)는 불러올 수 없다.
- 댓글은 로그인된 Chrome(Claude in Chrome)에서 댓글 API로 가져오고, 해결 처리 요청도 같은 경로로 가능(200 응답 후 목록 재조회로 해결 시각 확인). 내장 브라우저는 Figma 로그인이 없어 못 읽음.
- 값 일괄 변경(예: Tailwind 색 1,743곳 → 변수)은 화면 전체를 스크립트로 순회하고, 높이 변경은 테두리 포함 여부를 먼저 확인한다. 같은 노드를 같은 방식으로 고친 화면은 스크린샷을 생략해도 되지만 그 사실을 밝힌다.
- 화면 간 모순은 문구·수치(높이, 색)를 스크립트로 일괄 비교해 찾고, 묶음별로(기획 결정 / 예시 데이터 / 용어 / 시각 스타일 / 정리) 나눠 처리하면 편하다.
