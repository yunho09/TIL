# DSM Open API 데이터 수집 루트

DSM Open API(급식·일정·교직원·자습감독·동아리·학생)에 들어갈 데이터를 **어디서 받을지** 정리한 것. 필드는 백엔드 `docs/openapi.yaml` 기준이고, 나이스 Open API는 DSM 코드(`G10` / `7430310`)로 직접 호출해 확인했다. 핵심: 나이스 Open API엔 학생·교직원 개인정보가 없어서 사람 관련 데이터는 결국 선생님께 받아야 하고, 학생 관련 루트는 **개인정보 결정이 먼저** 나야 정해진다.

## 나이스 Open API로 자동 수집 가능한 것
- 인증키 없이 호출하면 **5건까지만** 응답 → [open.neis.go.kr](https://open.neis.go.kr)에서 무료 키 발급 필요.
- **급식** `mealServiceDietInfo`: 조·중·석식 메뉴(알레르기 번호 포함), 칼로리, 영양정보, 원산지. 현 스키마엔 메뉴만 있어 나머지를 내려줄지 결정 필요. 늦게 올라오거나 틀리면 관리자 급식 등록·수정 API로 직접 입력.
- **학사일정** `SchoolSchedule`: 학년별 해당 여부(`ONE_GRADE_EVENT_YN` 등)도 옴. `source=NEIS`. 나이스에 없는 학교 자체 행사는 `source=SCHOOL`로 관리자 입력.
- **시간표** `hisTimetable`: 반·교시별 **과목명만** 있고 담당 교사 이름은 없음. 명세는 컴시간 기준인데 나이스도 가능 → 택일 필요(나이스 추천이나 변경 반영이 컴시간보다 늦는지 확인 필요).
- **반·학과** `classInfo`: **담임 정보 없음**, 1학년은 학과가 "공통과정".
- **학교 기본정보** `schoolInfo`: 주소·전화·홈페이지.
- 학번·생일 같은 학적은 업무포털 나이스에만 있고 교사만 접근 → "나이스에 있다"도 결국 선생님께 요청.

## 선생님께 받아야 하는 것
| 데이터 | 담당 | 같이 확인할 것 |
|---|---|---|
| 교직원(이름·과목·교무실·부서·부장·담임) | 교무부 | 명세 enum이 과목 5개·부서 3개뿐이라 전체 목록 필요, 행정실·사감·보건·상담 포함 여부, 다과목 교사(현재 과목 1개만) |
| 자습감독 배정표(날짜·층·교사) | 배정표 담당 교사 | 발행 주기·형식(엑셀/한글/종이), 변경 공유 방식, 층 목록, **하루 여러 타임이면 스키마에 시간대 필드 없음**, 주말·잔류 포함 여부 |
| 동아리 공식 목록(이름·지도교사·교실) | 동아리 담당 교사 | 전공/자율 포함 여부, `ClubRoom` enum이 비어 있음, 중복 가입, 변경 시즌 |
| 학교 자체 일정 | 교무부 | 누가 알려줄지 미정 |

## 학생(설문·본인 입력)
- 동아리 구성원·부장·로고: 부장 대상 구글폼(학번 목록·로고 파일) → 교사 공식 명단과 대조. 로고 업로드 API는 명세에 없음.
- 이메일(`@dsm.hs.kr`): 회원가입 OTP로 이미 수집.
- 생년월일: 설문이면 동의서 필수.

## 루트 확정 / 미정 구분
- **확정**: 급식·학사일정·반학과(나이스), 공지(관리자 작성), 가입 학생의 학번·이름·이메일(회원가입), 교직원/자습감독/동아리 공식정보(출처는 학교뿐 — 담당 교사만 찾으면 됨).
- **미정과 추천**:
  - 전교생 명단: 교무부 명렬표 vs 가입자만 → **가입자만으로 시작**(명렬표는 개인정보 승인 선행).
  - 생년월일: **필드 제거** 추천(받을 이유 약하고 동의 부담만 큼).
  - 미가입 학생 이메일: 받지 않음.
  - 동아리 구성원·부장: 교사 공식 명단 있으면 그것, 없으면 부장 설문 후 교사 확인.
  - 동아리 로고: 부장 설문으로 파일 수집(업로드 API가 없으므로).
  - 시간표: 나이스 `hisTimetable`.
  - 급식 수동 보정: 일단 우리가 하고 영양 교사 연락처 확보.

## 개인정보 쟁점 (선생님과 가장 먼저)
- 현 명세의 학생 조회 API가 `USER` 권한 → **가입자 누구나 전교생의 이름·생일·이메일·동아리 조회 가능**. 가장 걸리는 지점.
- 학교 개인정보 보호 담당자 승인 가능성 큼. 동의서에 수집 항목·목적·보유 기간 필요, Open API로 타 서비스에 나가므로 **제3자 제공 동의**도 필요할 수 있음.
- 만 14세 이상은 법적으로 본인 동의로 충분하나 학교 방침상 학부모 동의를 요구할 수 있음. 미동의 학생 처리 방식 결정 필요.
- 추천: 생년월일 제거 또는 ADMIN 전용, 학생 데이터는 "가입한 본인 + 동의한 학생"부터. 교직원은 이름·과목·부서 정도로 덜 민감하나 동의는 받고 개인 연락처는 넣지 않기.

## 갱신 주기
- 매년 3월: 학번 전체 변경·졸업생 삭제·신입생 추가·담임/부서 변경. 동아리 변경 시즌: 구성원. 매달(수시): 자습감독. 나이스 데이터(급식·일정·시간표): 동기화 주기 결정 필요.
- 교사들은 엑셀로 줄 가능성이 큰데 명세에 **일괄 업로드 API가 없음**.

## 백엔드에 요청할 것
- 나이스 인증키 발급, 엑셀 일괄 업로드 API, 자습감독 시간대 필드, enum 값 채우기(과목·부서·동아리 교실·층), 학생 조회 응답 범위·권한 재검토, 급식 응답에 알레르기·칼로리 포함 여부, 동아리 로고 업로드 API.

## 학사 일정 출처 결정 (2026-11-11)
- 충돌: 백엔드 명세는 나이스 동기화(`source=NEIS`) 기준, 위 수집 계획은 "학사일정 파일 등록" 기준이었다.
- **결정: 나이스 동기화 + 직접 입력(`SCHOOL`)으로 먼저 가고, 파일 등록은 나이스에 빠진 일정이 많을 때 나중에 붙인다.**
- 근거: 둘 다 쓰면 ① 중간고사 같은 일정이 양쪽에 중복돼 "날짜·제목 같으면 건너뛰기" 규칙이 필요하고(나이스 일정은 지워도 다음 동기화 때 되살아남), ② 나이스 일정에서 수정·삭제를 누르면 409가 나므로 UI에서 막아야 하며, ③ 백엔드가 동기화와 파일 파서를 둘 다 만들어야 한다. 나이스 클라이언트는 급식 PR #24에 이미 있어 재사용 가능.
- 규칙: 나이스 일정은 수정·삭제 불가(읽기 전용), 학교가 넣은 일정만 수정·삭제 가능. 목록 응답에 출처(`NEIS`/`SCHOOL`)를 반드시 포함.
- admin 일정 화면(Figma 반영): 날짜 옆 출처 칸을 디자인 시스템 Badge(Neutral→나이스, Brand→학교)로 표시, 나이스 행은 수정·삭제 대신 회색 "읽기 전용", 안내 문구 추가. 코드는 일정 연동 때 출처 값에 맞춰 반영 예정.

## 팀 정리 수집 방법 (2026-11-10, 바뀔 수 있음)
팀이 항목별로 정리한 방법. 위 "추천"보다 우선하는 팀 쪽 결론이지만 **확정 전 메모**다.
- **학생**: 명단은 사감쌤·본부 교무실 쌤, 생년월일은 백엔드 팀원(성준)에게, 이메일은 가입자 것만, 조회 권한은 가입한 학생 전원.
- **동아리**: 구성원·부장은 동아리 쪽 담당 학생에게 문의(안 되면 직접 입력), 로고는 직접 수집, 담당 선생님은 직접 입력.
- **일정·급식**: 시간표는 컴시간 API(자동), 학사 일정은 학사일정 파일로 넣기, 그 외 일정은 직접 입력, 급식은 어드민에서 수동 보정.
- **교직원**: 명단은 담당 교사·행정실에서 받기, 자습감독은 선생님이 엑셀 입력 → PiCK 자동 크롤링.
- **아직 미정**: 항목별 기한, 급식 원본 데이터 출처, 자습감독 흐름(엑셀 입력이 크롤링을 시작하는 건지 둘 중 하나만 쓰는 건지).

## 상충하는 정보 (2026-11-11)
- **시간표 출처**: 위 "미정과 추천"은 나이스 `hisTimetable`, 팀 정리는 **컴시간 API**. Figma 일정 화면도 나이스를 빼고 컴시간 시간표 표로 바뀌어 admin 일정 화면에 반영했다(→ 컴시간이 현재 방향).
- **학사 일정 출처**: "학사 일정 출처 결정" 절은 나이스 동기화(`NEIS`/`SCHOOL` 출처 구분)였지만, Figma 일정 화면에서 나이스 부분(출처 선택·열·배지·`나이스에서 불러오기` 버튼)이 사라졌고 팀 정리는 "학사일정 파일로 넣기". 화면에는 학교 입력 일정만 남았다. 학사 일정을 받는 방식이 확정되면 디자인 쪽에 버튼·출처 표시를 되살릴지 물어야 한다. 위 절의 "admin 일정 화면(Figma 반영)" 설명은 이 변경 이전 상태다.
