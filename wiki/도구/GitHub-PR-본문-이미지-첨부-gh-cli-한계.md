`gh` CLI(및 GitHub REST API의 PR 본문 수정 엔드포인트)로는 PR/이슈 본문에 이미지 파일을 직접 업로드할 방법이 없다. 이미지는 반드시 `https://github.com/user-attachments/assets/...` 형태의 CDN 주소를 발급받아 마크다운으로 넣어야 하는데, 이 주소는 브라우저의 GitHub 웹 에디터(이슈/PR/댓글 편집창)에 실제로 파일을 드래그하거나 붙여넣어야만 발급된다.

## 우회 방법

1. 브라우저에서 아무 PR·이슈·댓글의 편집창을 열고 이미지를 업로드한다 — 붙여넣는 순간 GitHub가 파일을 업로드하고 `user-attachments` 주소를 마크다운에 자동 삽입한다.
2. **이 편집 내용을 저장하지 않고 취소(원래 내용으로 되돌리기)한다.** 목적은 댓글을 새로 남기는 게 아니라 주소만 얻는 것이다 — 업로드된 이미지 자체는 편집을 취소해도 CDN에는 남아 인증 없이 계속 접근 가능하다(재사용 전 curl 등으로 200 확인 권장).
3. 얻은 주소를 `gh pr edit <PR> --body "..."` 또는 `gh api`로 원하는 본문 텍스트의 자리(예: `<!-- 결과 화면 캡처 -->` 같은 placeholder)에 넣는다.

## 주의점

- 브라우저 자동화(Claude in Chrome 등)로 이 과정을 수행할 때, 업로드 대상으로 연 편집창이 **기존 댓글의 수정 모드**였다면 실수로 저장을 눌러 기존 댓글 내용을 바꿔버릴 위험이 있다 — 반드시 원래 내용 그대로 복원했는지, 새 댓글이 실제로 등록되지 않았는지 확인한 뒤 탭을 닫을 것.
- 여러 PR에 같은 방식으로 이미지를 넣어야 하면, 업로드 자체는 한 번의 브라우저 세션에서 몰아서 하고 주소만 모아 각 PR에 `gh`로 나눠 넣는 편이 브라우저 조작 횟수를 줄인다.
