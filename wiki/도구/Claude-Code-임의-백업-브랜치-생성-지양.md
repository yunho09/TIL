# Claude Code 임의 백업 브랜치 생성 지양

Claude Code가 커밋 히스토리를 재배열(rebase, 커밋 분리 등)하기 전에 안전망 삼아 스스로 `backup/*` 브랜치를 만드는 경우가 있는데, 사용자와 사전 협의 없이 만들면 "왜 네 맘대로 브랜치를 만드냐"는 반발을 살 수 있다. 브랜치 생성 자체는 되돌리기 쉬운 작업이지만, 저장소에 사용자가 요청하지 않은 흔적을 남긴다는 점에서 사용자 동의 없는 부수 효과로 받아들여진다.

## 결정

- 커밋 재배열처럼 되돌리기 어려운 작업 전에 안전망이 필요하면, 브랜치/태그를 만들기 전에 먼저 사용자에게 "안전을 위해 `backup/...` 브랜치를 만들어도 될지" 확인한다.
- 이미 만든 백업 브랜치를 사용자가 지우라고 하면 즉시 지운다(로컬에만 있고 원격에 push되지 않았다면 `git branch -D`로 충분).
