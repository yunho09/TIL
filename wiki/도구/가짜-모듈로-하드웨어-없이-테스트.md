# 가짜 모듈로 하드웨어 없이 테스트하기

하드웨어 전용 라이브러리(`gpiozero` 등)를 import 하는 코드는 개발 PC에서 `ModuleNotFoundError`로 죽는다. **`sys.modules`에 껍데기 모듈을 미리 등록해 두면** 실제 모듈을 찾지 않고 그걸 쓰게 되어, 하드웨어 없이 로직을 검증할 수 있다.

## 원리

파이썬은 `import X`를 만나면 **`sys.modules` 딕셔너리를 먼저 확인**한다. 거기 이미 있으면 디스크를 뒤지지 않고 그대로 쓴다. 이 성질을 이용한다.

```python
import sys, types

fake = types.ModuleType("gpiozero")          # 빈 모듈을 만들고

class PWMLED:                                 # 같은 이름/인터페이스만 흉내
    def __init__(self, pin, **kw):
        self.pin, self.value = pin, 0.0
    def off(self):   self.value = 0.0
    def close(self): pass

fake.PWMLED = PWMLED
sys.modules["gpiozero"] = fake                # ← 진짜보다 먼저 등록

import lightRun                               # 이제 진짜를 찾지 않는다
```

**대상 모듈을 import 하기 전에** 등록해야 한다. 순서가 바뀌면 소용없다.

가짜 객체는 값을 실제 핀 대신 파이썬 변수에 저장할 뿐이므로, **그 값을 읽어 로직이 맞는지 확인**할 수 있다.

## GUI까지 검증하려면 offscreen

Qt는 `QT_QPA_PLATFORM=offscreen`으로 창을 띄우지 않고도 위젯을 만든다. 그러면 버튼과 슬라이더를 **코드로 눌러볼 수 있다.**

```python
os.environ["QT_QPA_PLATFORM"] = "offscreen"
app = QtWidgets.QApplication([])
w = lightRun.LightApp()

w.ui.sliderRed.setValue(255)
w.ui.btnSend.click()
print({n: l.value for n, l in w.leds.items()})   # {'red': 1.0, ...}

w.show(); app.processEvents()
w.grab().save("preview.png")                      # 레이아웃 그림까지 저장
```

⚠️ **앱 코드가 `os.environ`으로 플랫폼을 덮어쓰면 import 이후에 다시 지정해야 한다.** 앱이 import 시점에 `QT_QPA_PLATFORM="xcb"`를 넣는다면, 셸에서 offscreen을 줘도 무시된다 → [[라즈베리파이-GUI-SSH-VNC-실행]]

offscreen 렌더는 **글자가 찍히지 않는 경우가 있다.** 배치·크기·색은 믿을 수 있지만 텍스트 확인은 `widget.text()`로 하는 편이 확실하다.

## 무엇을 걸러낼 수 있나

| 검증 가능 | 검증 불가 |
|---|---|
| 위젯 이름이 코드와 맞는지 | 실제 배선 |
| 시그널 연결(클릭·값 변경) | 핀 번호가 물리적으로 맞는지 |
| 값 매핑 (0~255 → 0.0~1.0) | 디스플레이 유무 |
| 레이아웃 배치 | 라이브러리 설치 상태 |

실제로 이 방식으로 사전 검증한 뒤 라즈베리파이에서 겪은 실패는 전부 하드웨어·환경 문제였고 코드 로직 문제는 없었다.
