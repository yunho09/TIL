# Git 스택 PR 재정렬과 force-with-lease 안전 푸시

스택 PR(브랜치 A ← B ← C ← … 순서로 각자 바로 아래 브랜치를 base로 삼는 구조)에서 브랜치 하나가 최신 상태로 안 올라가면, 그 위 브랜치들 전체의 diff·스크린샷이 실제 최종 머지 결과와 다른 코드를 보여주게 된다. 이 문제를 알아채는 법과, 여러 브랜치를 한 번에 강제 푸시할 때 다른 작업을 덮어쓰지 않는 법을 정리한다.

## 스택 어긋남을 알아채는 신호

코드 리뷰나 diff 확인 중 "이 커밋이 그 위 브랜치(PR)에 없다"는 게 확인되면, 그건 단순 누락이 아니라 **위쪽 PR들이 실제로는 그 커밋 이전 상태를 기준으로 보여지고 있다**는 뜻이다. 리뷰어가 확인한 화면·동작이 최종 머지 결과와 다를 수 있다는 신호이므로 우선순위 높게 다뤄야 한다.

판별은 각 브랜치가 바로 아래 브랜치를 조상으로 포함하는지 확인하면 된다(`git merge-base --is-ancestor <아래-브랜치> <위-브랜치>`). 리뷰 코멘트가 지목한 커밋이 몇 번째 브랜치부터 없는지 하나씩 대조하면 어긋난 구간을 정확히 찾을 수 있다.

## 해결 — 순차 rebase

어긋난 지점부터 위 방향으로 브랜치를 하나씩 rebase한다(각 브랜치를 새로 갱신된 바로 아래 브랜치 위로). 스택이 길면(10개 이상) 스크립트로 순서대로 자동화하는 게 안전하지만, **스크립트가 중단 후 재실행되면 이전 base를 잘못 잡을 수 있다** — 중단됐으면 마지막으로 정상 처리된 브랜치부터 정확한 base로 다시 시작해야 한다. 충돌은 스택 커밋 수에 비해 적게 나는 편이지만(겹치는 파일이 있으면), 나면 그 자리에서 바로 해결하고 계속 진행한다.

재정렬 후에는 스택 전체가 선형인지(각 브랜치가 바로 아래 브랜치를 정확히 포함하는지) 끝에서 끝까지 다시 확인한다.

## 안전한 강제 푸시 — 브랜치별 명시적 SHA lease

스택 재정렬은 필연적으로 이미 푸시된 브랜치들의 히스토리를 바꾸므로 강제 푸시가 필요하다. 다른 사람/세션이 같은 저장소에서 동시에 작업 중일 수 있으므로 단순 `git push -f`보다 **브랜치마다 "원격이 정확히 이 SHA를 가리킬 때만 덮어써라"는 lease를 명시**하는 편이 안전하다.

```bash
git push origin \
  --force-with-lease='refs/heads/<branch-A>:<origin이 가리키던 정확한 SHA>' 'refs/heads/<branch-A>:refs/heads/<branch-A>' \
  --force-with-lease='refs/heads/<branch-B>:<origin이 가리키던 정확한 SHA>' 'refs/heads/<branch-B>:refs/heads/<branch-B>'
  # ... 브랜치 수만큼 반복
```

- 재정렬 작업 시작 전에 각 브랜치의 origin SHA를 저장해둔다(백업 겸 lease 값으로 사용).
- push 직전에 `git fetch`로 원격이 세션 시작 시점과 여전히 같은지 재확인한다.
- lease가 걸린 브랜치 중 하나라도 그 사이 원격이 움직였으면 그 브랜치만 거부되고 나머지는 정상적으로 나간다 — 전부 실패하는 `git push -f`보다 피해 범위가 좁다.
- fast-forward가 되는 브랜치(재정렬로 아무 변화가 없던 브랜치)는 lease 없이 일반 push로 충분하다.

## Claude Code에서의 제약 — auto mode가 force-push를 차단

Claude Code의 auto 권한 모드는 `git push --force`류를 `[Git Destructive]`로 분류해 차단한다. 스크립트 파일로 감싸 실행해도, 명령을 그대로 노출해서 실행해도 동일하게 거부된다 — 이는 우회하면 안 되는 의도된 안전장치다. 대응:

1. 정확한 명령(브랜치별 `--force-with-lease` 전부 포함)을 사용자에게 그대로 넘기고 **직접 실행**하게 안내한다.
2. 안내할 때 `!` 접두사(Claude Code 채팅 전용 즉시실행 문법)를 쓸 건지, 순수 터미널 명령을 쓸 건지 명확히 구분한다 — 섞어서 안내하면 [[Claude-Code-느낌표-bash-접두사-채팅전용]]의 함정(`command not found`, zsh `event not found`)에 걸린다.
3. 앞으로 AI가 직접 push하게 하려면 `.claude/settings.json`에 `Bash(git push:*)` 허용 규칙을 추가하면 되지만, 이건 사용자가 선택할 일이지 AI가 먼저 우회를 시도할 일이 아니다.

## 되돌릴 안전망

재정렬 전 각 브랜치의 SHA를 파일로 저장해두면(`git rev-parse <branch>` 결과 모음), rebase가 잘못됐을 때 `git reset --hard <저장된 SHA>`로 즉시 원상복구할 수 있다. lease 값으로도 재사용되므로 재정렬 시작 시점에 한 번만 저장해두면 이중으로 쓸모 있다.
