# 제안서·발표 자료 협업·변환 함정 — HWP, 구글 문서/슬라이드, PPTX

HWP 양식을 채워 제출하면서 구글 문서·슬라이드로 팀 공동 편집하고 PPTX/PDF로 내보내는 과정에서 겪은 도구 함정 모음. 핵심은 **한글 프로그램이 없는 리눅스에서는 HWP 결과를 눈으로 확인할 수 없고**, 브라우저 자동화로 구글 문서를 고치는 건 포커스·클립보드 문제로 위험하다는 것.

## HWP 다루기 (한글 프로그램 없는 PC)
- 구글 문서는 `.hwp`를 열지 못한다. 공동 편집은 같은 내용을 `.docx`로 만들어 올리는 우회가 필요(LibreOffice로 HWP→docx 직접 변환하면 표지 정렬·굵은 제목·일정표 칸 너비가 깨져 내용 기준으로 docx를 새로 생성). 구글 문서를 `.hwp`로는 내보낼 수 없으므로, HWP 제출이 필요하면 내려받은 `.docx`를 한글에서 열어 "다른 이름으로 저장 → HWP".
- 구글 문서 쪽 수정은 `.hwp`·`.docx`에 자동 반영되지 않는다. 한쪽에서 직접 고친 뒤에는 **어느 파일이 최신본인지**가 쉽게 갈라진다 → 최종 제출 직전에 구글 문서/슬라이드에서 다시 내려받고 이전 파일은 별도 폴더로 치워 혼동을 막았다.
- HWP를 직접 만든 경우 한글에서 연 모습(줄 간격·쪽 넘김·색칠 칸)은 검증 불가 — 별도 해석 도구로 텍스트를 다시 읽고 이미지로 렌더링한 것까지만 확인이다.
- 쪽수 측정: Word 파일은 줄 간격이 넓어 한글보다 **약 1.6배** 길게 나온다. 한글 양식과 같은 글꼴·줄 간격(120%)·여백으로 따로 조판해 재야 기준 비교가 된다(그래도 실제 한글 값은 아님). 구글 문서는 맑은 고딕(나눔바른고딕보다 큼)·기본 여백·줄 간격 1.5·문단 여백·새 쪽 넘김 때문에 같은 내용이 더 길게 나온다(HWP 약 9쪽 ↔ 구글 문서 12~16쪽). 줄이려면 줄 간격 1.2, 여백 2cm 등.

## 브라우저 자동화로 구글 문서/슬라이드 고치기
- **자동화가 연 탭이 백그라운드(포커스 없음)면 입력이 엉뚱한 곳으로 간다.** 찾아 바꾸기(Ctrl+H) 입력칸에 친 글자가 문서 본문에 들어가 문서가 몇 줄만 남은 사고가 났다. 창이 작게 줄어든 경우도 클릭이 빗나갈 위험. 대응: 창 최대화·탭을 맨 앞에 띄운 걸 확인한 뒤 작업, 의심되면 입력하지 말고 사용자에게 Ctrl+H 방법을 안내. 복구는 버전 기록에서 직전 정상 버전으로.
- **클립보드 경유 붙여넣기 불안정**: 브라우저 안 JS로 클립보드에 쓴 내용이 1초 안에 다른 내용(이전 텍스트, 빈 값, 노션 링크, 원시 HTML 코드)으로 바뀌어 잘못 붙은 적이 반복됐다. 크롬 창이 화면 맨 앞이 아니면 브라우저 안 복사가 OS 클립보드에 전달되지 않는 것으로 추정. 안정적인 방법은 사용자가 직접 페이지에서 Ctrl+A/C → 구글 문서 Ctrl+A/V(맨 위에 딸려 온 제목 한 줄만 삭제). 붙이기 직전에 숨은 입력칸에 붙여 내용을 검증하는 방식도 썼지만 검증과 실제 붙이기 사이에 덮어써질 수 있었다.
- 잘못 붙은 내용이 **비밀번호 같은 문자열**이었던 경우: 구글 문서 **버전 기록은 특정 버전만 삭제할 수 없다**(편집자·소유자 모두). 완전히 없애려면 "사본 만들기"(버전 기록이 안 넘어감) → 원본 휴지통 비우기(링크가 바뀜) 또는 해당 비밀번호 교체. 클립보드에 남은 값은 아무 텍스트를 복사해 덮어쓴다.
- 문서 전체를 통째로 교체하면 그 사이 팀원이 고친 내용이 사라질 수 있다 → 교체 전 현재 내용을 백업하고(내보내기 텍스트), 다른 편집자 아바타가 보이면 주의.
- 슬라이드의 도형 위치는 입력 후 값이 반영 안 되는 경우가 있어 서식 옵션 → 위치에서 Tab으로 확정해야 했고, 크기 변경은 슬라이드를 바꿨다 돌아와야 보였다. 텍스트가 든 박스를 선택한 채 타이핑하면 교체가 아니라 덧붙여지고 글꼴이 달라지므로, 비우고 다시 입력한 뒤 서식 복사 도구로 맞춘다. 선 4개로 만든 테두리는 길이를 정밀 조정할 수 없어 지우는 편이 나았다. 팀원이 동시에 편집하면 에이전트가 하지 않은 변화(예: 배경색 변경)가 생길 수 있다.
- 문서 안 용어 일괄 정정(예: "팀장" 삭제)은 찾아 바꾸기가 가장 빠르다 — 바꾼 뒤 같은 단어를 다시 검색해 0건인지 확인.

## 멀티에이전트로 문서 작업할 때
- 에이전트들이 같은 브라우저·같은 클립보드를 공유하면 서로 방해한다(한 에이전트의 붙여넣기 중 다른 쪽이 복사/탭 조작). 완료 신호용 마커 파일(`PROPOSAL_DONE`)을 쓸 때, 수정 지시가 도중에 들어오면 마커를 지우고 최종 복사 후 다시 만들어야 다른 에이전트가 중간 버전을 가져가지 않는다.
- 검토 전용 에이전트(파일 수정 금지)로 "확정 사항과의 일치 / 섹션 간 일관성 / 근거 없는 주장 / 표현" 네 관점을 따로 돌린 뒤 반드시/권장/사소 단계로 나눠 반영하는 방식이 효과적이었다. 단, 에이전트가 "금지어"로 취급한 원문 표현(포스트잇에 있던 말)은 사용자 확인 없이 바꾸지 말 것.

## PPTX/PDF 내보내기
- Claude 아티팩트 덱을 PPTX로 받으려면 공유 → 내보내기 메뉴를 쓰지만, 자동화된 크롬에서는 다운로드가 기대한 폴더에 안 떨어질 수 있다 → 사용자가 직접 받거나, 슬라이드 HTML을 읽어 python-pptx 등으로 다시 만든다(Jua 폰트·그림자·화살표 커넥터는 근사치).
- **PPTX 폰트 깨짐**: Jua·Noto Sans KR은 대부분의 PC에 없어 다른 글꼴로 치환된다. 구글 슬라이드에서 받은 PPTX는 글꼴이 내장되지만 윈도우 PowerPoint에서만 제대로 보이고 한쇼·LibreOffice·키노트·일부 맥에서는 깨진다. 해결 순서: ① PDF로 제출/발표(글꼴 포함, 가장 안전) ② 맑은 고딕으로 바꾼 사본 PPTX(제목의 둥근 느낌은 사라짐) ③ 발표 PC에 폰트 설치.
- PDF로도 발표 가능: 크롬/엣지에서 F11 전체 화면, Acrobat Reader는 Ctrl+L 프레젠테이션 모드, 맥 미리보기는 슬라이드쇼. 단 전환 효과·발표자 노트는 없다.
- 보고서 PDF에서 뽑은 화면 사진은 처음부터 썸네일 크기(가로 175~234px)라 확대 불가 → 큰 화면이 필요하면 앱을 직접 실행해 캡처(1232×956 등, 5~6배). 앱에 내장된 목 데이터라 Gemini 실제 호출 결과가 아니고 애니메이션 효과는 사진에 안 나온다.
