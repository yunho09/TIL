# Notion MCP update_content — 빈칸(`___`)이 `***`로 깨지는 함정

Notion MCP로 페이지를 `update_content`로 고칠 때마다 페이지가 다시 직렬화되는데, 한 블록에 `___`가 여러 개 있으면 굵은 기울임(`***`)으로 해석돼 **다른 곳의 빈칸이 깨진다**. 포트폴리오 페이지처럼 "before → ___" 빈칸이 많은 문서에서 실제로 8~9곳이 깨졌다 (Claude 세션 관찰, 근본 원인은 미확인).

## 증상과 겪은 순서
- 표 한 곳만 고쳤는데 페이지 다른 곳의 `___`가 `***`로 바뀌어 Notion에서 굵은 기울임꼴로 보임.
- 깨진 블록만 부분 복구하면 `No matches found`로 실패하거나, 고칠 때마다 다른 빈칸이 다시 깨짐.

## 해결
- **같은 배치 안에서 `___`가 여러 개 든 블록 전부**를 `\_\_\_`로 이스케이프해 한 번에 넣는다.
- `old_str`은 **화면에 보이는 그대로**(정상이면 `___`, 이미 깨졌으면 `***`) 쓴다 — 저장된 표현과 다르면 매칭 실패.
- 수정 후 페이지를 다시 fetch해 빈칸이 남아 있는지 확인.
- 한글 오타(예: "셌다"가 "셈다"로 입력됨)도 이 도구로 쓰다 생겼으니 반영 후 다시 읽어 검증.
