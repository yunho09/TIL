# Claude Code 세션 기록으로 정정 지시 측정

Claude Code 세션 기록(jsonl)에서 "AI를 바로잡은 사용자 메시지"를 세어 하네스·규칙 개선 전후를 비교하는 방법과 함정. 기본 보관 30일이라 개선 전 기준값을 쓰려면 보관 기간부터 늘려야 하고, 센 방식이 다르면 사람끼리 수치를 합칠 수 없다.

## 기록 위치와 한계
- Claude 세션은 `~/.claude/projects/<작업폴더 경로를 -로 바꾼 이름>/*.jsonl`에 남는다(예: `-data-project-ToyVillage-Admin-FE`). Codex 기록은 별도이고 동료 기록은 그 사람 컴퓨터에만 있어 직접 못 본다.
- **`gitBranch` 필드는 대부분 `HEAD`로만 남아** 브랜치 추적에 못 쓴다 → tool_use 입력의 `git checkout`/`switch`/`gh pr create` 명령으로 추적. 작업 폴더 경로로 줄 수를 세면 worktree가 섞여 크게 부풀려진다(61,038줄 사례).
- **기본 보관 30일**. `~/.claude/settings.json`에 `"cleanupPeriodDays": 365`를 추가해 늘렸다(전역 설정이라 사용자 승인 후 변경, JSON 재검증). 측정 원본(분류 결과·스크립트)은 임시 폴더에 두면 날아가므로 노션 등 안 지워지는 곳에 남긴다. 팀 저장소에 커밋하지 않기로 했다(외주 저장소, 그리고 프롬프트 원문에 JWT가 섞여 있었음 — **프롬프트 원문은 저장소에 두지 않는다**).

## 측정 방법과 함정
- **키워드 선필터("아니", "다시", "규칙")는 누락이 크다.** 같은 세션을 키워드로 거르면 26건/917개였는데 프롬프트 980개를 전부 읽고 분류하니 하네스 원인 65건. 정정 표현 없이 지시한 경우가 빠지기 때문 → 전수 읽기로 재집계.
- **세는 기준을 먼저 고정한다**: 정정 지시 = 직전 AI 결과·행동을 바로잡는 메시지(새 요청 제외) / 하네스가 막았어야 할 것 = 규칙·검사·기준 파일이 하네스에 있었다면 안 생겼을 정정 / 원인별 분류 / 게이트 절차 프롬프트. 한 사람은 "하네스가 원인인 것만", 다른 사람은 "모든 정정 후 막을 수 있던 것"을 세서 100개당 2.8건 vs 13.7건처럼 5배가 났다 — 합치거나 비교하려면 같은 기준·스크립트로 다시 세야 한다.
- 메시지 수 기준이라 같은 일을 여러 번 말한 경우가 포함된다. 분류를 AI가 했는지 본인이 했는지도 비율 차이의 원인이 된다. 개인 환경 문제(포트·작업 폴더)·기능 버그·범위 논의는 하네스 대상에서 제외.
- 측정 결과와 적용: [[하네스-점검-결과와-개선-방향]]. 평균·중앙값 함정은 [[ToyVillage-Admin-FE/프로젝트-현황]]의 PR 지연 재계산 절 참고.
