# 위키 자동 캡처

이 vault(`~/문서/TIL`)의 LLM Wiki는 **Karpathy 모델**(원본을 매번 검색하는 RAG 대신, LLM이 마크다운 페이지를 직접 쓰고 계속 갱신)을 따른다. 처음엔 "위키에 넣어줘"라고 말해야 저장되는 수동 방식이었지만, 이후 Claude Code의 **SessionEnd 훅**으로 세션이 끝날 때마다 자동으로 위키에 반영되고 GitHub에 push되도록 확장했다.

## 왜 OMC 내장 wiki 스킬 대신 직접 구조를 만들었나

oh-my-claudecode에는 `/oh-my-claudecode:wiki` 스킬(`wiki_add/ingest/query/lint` 등)이 이미 있지만 이 vault에는 채택하지 않았다.

- OMC wiki의 저장소는 **`.omc/wiki/`에 고정**되고 기본적으로 git-ignore 대상이라, Obsidian의 그래프 뷰·백링크와 자연스럽게 섞이지 않는다.
- 카테고리가 `architecture/decision/debugging…` 식으로 **코드 프로젝트 지식**용으로 설계되어 개인 학습 노트 성격과 안 맞는다.
- Karpathy 모델의 핵심은 전용 툴이 아니라 **규칙(CLAUDE.md) + 평범한 마크다운 폴더**라서, 별도 플러그인 없이 Claude Code만으로 그대로 구현 가능하다.

그래서 `CLAUDE.md`(운영 규칙) + `raw/`(원본, 읽기 전용) + `wiki/`(페이지, index.md·log.md 포함) 구조를 vault 루트에 직접 만들었다. (자세한 페이지 작성 규칙·ingest/query/lint 워크플로는 이 vault의 `CLAUDE.md` 참고.)

## 자동 캡처 파이프라인

세션 종료(`exit`, 터미널 종료, `/clear` 포함) 시 다음이 순서대로 실행된다.

1. `~/.claude/hooks/wiki-capture.sh`(전역 훅 스크립트)가 해당 세션의 transcript에서 **대화 텍스트만 추출**(도구 호출/출력 제거).
2. 추출된 텍스트를 이 vault 경로에서 백그라운드로 `claude -p`(기본 모델 sonnet)에 넘겨, vault의 `CLAUDE.md` 규칙대로 "다시 쓸 가치 있는 지식만" ingest하게 한다. 남길 게 없으면 아무것도 안 씀.
3. ingest로 `wiki/`, `raw/`, `CLAUDE.md`에 변경이 생기면 자동으로 git commit + `git push`(`origin/main`).
4. vault 안에서 직접 작업한 세션(즉 이 캡처 스크립트 자신이나, 사용자가 vault 안에서 Claude Code를 돌린 경우)은 중복 저장을 막기 위해 **ingest 없이 push만** 수행.

훅은 `~/.claude/settings.json`(전역)의 SessionEnd 이벤트에 기존 훅(예: Clawd 펫 훅)과 나란히 등록되어 있다. 등록 전 백업은 `settings.json.bak-wiki`.

### 스킵 조건 (캡처를 건너뛰는 경우)
- 사용자 발화가 3회 미만인 짧은 세션
- 추출된 텍스트가 너무 작은 경우
- 캡처 프로세스 자신이 만든 세션(무한 재귀 방지)
- vault 안에서 직접 실행된 세션 (위 4번, push만 수행)

### 로그 위치
- 캡처 실행 자체의 로그: `~/.claude/wiki-capture.log`
- 실제로 뭘 저장했는지: `wiki/log.md` (예: `## YYYY-MM-DD HH:MM — ingest (Claude Code 세션 자동 캡처)`)

## 적용 범위와 한계

- **Claude Code CLI**, **Claude Desktop의 Code 탭** 모두 동작한다. 둘 다 `~/.claude/settings.json`을 읽고, transcript도 같은 위치(`~/.config/Claude/claude-code-sessions`)에 같은 형식으로 저장되기 때문.
- **Claude Desktop의 일반 채팅(Code 탭이 아닌 대화)은 동작하지 않는다.** 훅 시스템 자체가 없는 인터페이스라서. 그 대화를 남기려면 내용을 복사해 `raw/`에 넣고 수동으로 ingest해야 한다.
- **실시간이 아니라 세션 종료 시점에만** 반영된다. 세션을 오래 안 끝내면 그동안은 위키에 안 쌓인다 — 중간에 즉시 반영하고 싶으면 "지금까지 내용 위키에 저장해"라고 명시적으로 요청하면 된다.
- **세션을 resume해서 이어가는 경우**: 다시 종료할 때 transcript **전체**(이전+새 대화)를 다시 처리한다. 중복 페이지는 안 생기지만(기존 페이지는 새로 만들지 않고 갱신하는 규칙 때문) 매번 전체를 재처리하므로 토큰이 그만큼 더 든다. 같은 세션을 여러 번 껐다 켰다 하기보다, 긴 작업은 중간중간 `/clear`로 끊는 편이 캡처 비용 면에서 낫다.
- 캡처 대상 조건을 통과하는 세션마다 sonnet 실행 1회분 토큰 비용이 든다. 비용을 줄이려면 `wiki-capture.sh`의 모델 지정을 `haiku`로 바꿀 수 있다.
- 잡담 세션도 걸러지긴 하지만 완벽하지 않을 수 있어 노이즈가 쌓일 수 있다 — 가끔 "위키 린트"로 점검·정리 필요.
