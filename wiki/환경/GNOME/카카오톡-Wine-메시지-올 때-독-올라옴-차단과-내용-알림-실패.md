# 카카오톡(Wine) 메시지 올 때 독 올라옴 차단과 내용 알림 실패

Wine 카카오톡에 메시지가 오면 창이 '주의 요청'을 보내 GNOME이 "카카오톡이 준비되었습니다" 알림을 띄우고, 우분투 독이 그 창 때문에 올라온다. 독만 막는 작은 확장 `kakao-dock@yunho.local`로 해결했다. Discord처럼 "보낸 사람·내용" 알림을 띄우려던 시도는 카톡이 Wine에서 자체 팝업을 만들지 않아 접었다.

## 원인
- 메시지가 오면 카톡 창이 **demands attention(주의 요청)** 신호를 보낸다.
- GNOME이 이를 "준비됨" 알림으로 바꾸고, ubuntu-dock은 urgent 창이 생길 때마다 독을 띄우도록 설정돼 있다. → [[GNOME-알림-배너-위치-오른쪽-이동-확장]]의 "준비됨" 배너와 같은 경로.

## 결정과 최종 상태
- 사용자 결정: **'준비됨' 알림은 그대로 두고 독만 차단**.
- `kakao-dock@yunho.local`: 카톡 창에 한해 독의 urgent 처리를 막는 확장. 다음 로그인에도 자동 켜짐.
- 격리 테스트 셸에서 카톡 창은 '준비됨'만 뜨고 독 불변, 다른 앱은 원래대로 독 반응을 확인. 실제 메시지로는 아직 미확인(Claude 보충: 다음 메시지 때 확인 필요).
- 앞서 만든 "준비됨까지 차단+내용 알림" 확장(`kakao-notify@yunho.local`), 중계 스크립트, 실행기 변경은 모두 삭제하고 실행기를 원복.

## 내용 알림이 안 된 이유
- 시도한 방식: Wine 디버그 로그(`WINEDEBUG`로 stderr)에서 카톡의 오른쪽 아래 팝업 창에 그려지는 글자(DrawTextExW)를 읽어 GNOME 알림으로 중계.
- 실제로는 **카톡이 Wine에서 자체 알림 팝업 창을 아예 만들지 않아** 읽을 글자가 없었다. 설정(알림창 켜짐, 보낸 사람+메시지)이나 방 알림 문제가 아니었다.
- 추정 원인(미확정): 카톡이 2초마다 화면 왼쪽 위·오른쪽 아래 모서리의 창을 확인하는데(전체 화면 앱 감지 방식), Wine에서는 둘 다 Wine 데스크톱 창으로 나와 "전체 화면 앱 실행 중"으로 보고 깜빡이기만 함. 다른 가능성은 Wine이 카톡 창에 들어온 입력만 세서 '자리 비움'으로 판단. 메모장을 모서리에 두는 시험은 값이 안 바뀌어 판정 못 함.
- 이어서 하려면: Windows용 파이썬을 같은 Wine 환경에서 돌려 카톡이 보는 값을 직접 조회(내려받은 실행 파일 실행이라 자동 승인에서 막힘).

## 재활용할 수 있는 교훈
- **Wine 로그 중계 설계 함정** (코드 리뷰에서 나옴):
  - Wine의 stderr를 읽는 쪽이 사라지면 Wine 프로그램이 같이 실패한다 → 중계가 죽어도 `cat >/dev/null`로 대신 읽는 예비 리더 필요. Python의 `SIGPIPE`를 기본값으로 되돌리면 파이프가 닫힐 때 즉사하므로 두지 않는다.
  - 최상위 창의 parent가 explorer의 데스크톱 창(`#32769`)이라, parent를 끝까지 따라 올라가면 모든 창이 데스크톱으로 판정된다. `WS_CHILD`일 때만 parent를 따라간다.
  - Wine 트레이스의 좌표는 부호 없음(`%u`)이라 `CW_USEDEFAULT`가 약 2e9로 읽히고, 창 스타일은 생성 뒤 `SetWindowLong`으로 바뀌므로 생성 시점 값만 믿으면 안 된다.
  - 긴 문자열은 Wine 디버그 출력이 `"...`로 잘라 낸다(버퍼 300자).
- **gdbus 인자**: `-`로 시작하거나 `\`·따옴표가 든 문자열은 GVariant 문법으로 해석돼 사라지거나 바뀐다. 인자 앞에 `--`를 넣고 각 문자열을 `"…"`로 감싸 이스케이프한다.
- **GNOME 확장 주의**: 잠금 화면에서 확장이 꺼지면(`session-modes`에 `unlock-dialog` 없음) 차단이 풀리고, 잠금 해제 직후 독이 먼저 켜져 튀어나올 수 있다. 확장끼리 프로토타입 패치 순서(`notification-right`와의 의존)에 주의.
- 진단 로그에는 메시지 내용이 들어가므로 확인 후 지운다.
