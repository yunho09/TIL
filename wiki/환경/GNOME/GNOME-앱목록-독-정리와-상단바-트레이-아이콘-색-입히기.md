# GNOME 앱 목록·독 정리와 상단바 트레이 아이콘 색 입히기

GNOME 앱 목록(폴더 6개+낱개 3개)·독(파일 아이콘 하나)을 정리하고, 흰색/회색으로만 뜨는 상단바 트레이 아이콘(Claude·Discord·카카오톡)에 색을 입힌 작업의 결정과 근거. 업데이트로 원복되는 아이콘은 훅·타이머로 자동 복구하고, 확장은 격리 테스트 셸로 검증했다.

## 앱 목록·독 정리 결정
- 정리 전 **독·앱 폴더 설정을 파일로 백업**한 뒤 변경 (되돌리기 용).
- 독: 윈도우 드라이브·휴지통 아이콘을 독에서 빼고 "파일" 앱 하나만 고정 (드라이브·휴지통은 파일 앱 사이드바에서 접근).
- 앱 목록: 개발·인터넷·오피스·미디어·보조 프로그램·시스템 6개 폴더 + 폴더 밖 3개(설정, 터미널, 자주 쓰는 앱). 빈 이름 없는 폴더는 제거, "유틸리티"는 "보조 프로그램"에 합침.
- **겹치는 앱은 삭제하지 않고 목록에서만 숨김** (언제든 복구 가능): GNOME Terminal(Ptyxis와 중복), 개발 폴더와 실행 명령까지 같은 낱개 Figma 항목, 안 쓰는 Fcitx 4종(한글 입력은 ibus)·TeXInfo.
- 폴더를 다 짠 뒤 "보이는 앱이 전부 어느 폴더 안에 있는지" 검증.

## 트레이 아이콘 색 입히기
- **Claude 데스크톱**: 시스템 파일(앱 아이콘)을 교체해야 해서 관리자 암호 필요. 앱 업데이트 시 흰 아이콘으로 돌아가므로 **apt 훅으로 업데이트 후 자동 복구**하게 했고, 복사본에 업데이트를 시뮬레이션해 복구 동작을 검증. 앱을 재시작해야 반영.
- **Discord**: 윈도우판도 트레이 이미지가 흰색이라 색 버전이 따로 없음 → 리눅스 이미지의 **흰 부분을 파란색으로 재채색**(읽지 않음 빨간 점 유지). 앱이 업데이트하면 흰색으로 돌아가므로 **10분 주기 타이머**로 재적용. 트레이는 Discord가 아이콘을 다시 그릴 때(새 메시지·재시작) 반영. 실제 파일에 적용하기 전 복사본에서 시험. (Claude 보충: 백그라운드 타이머 설치는 자동 실행 권한 검사에 한 번 막혀, 먼저 1회성 재채색만 하고 이후 사용자 승인으로 설치)
- **카카오톡(Wine)**: 트레이 아이콘이 회색이라 작은 GNOME 확장(`tray-tint@yunho.local`)이 해당 아이콘만 노란 타일+갈색 말풍선 색으로 틴트. 창 이름 매칭으로 `explorer`·`kakaotalk.exe`만 고르고 무관한 explorer 아이콘은 건너뜀을 확인.
- **확장 검증법**: 실제 세션과 분리된 **테스트 GNOME Shell을 백그라운드로 띄워** 매칭·색을 화면으로 확인 (알림 배너 확장과 같은 방식, [[GNOME-알림-배너-위치-오른쪽-이동-확장]]). Wayland라 실환경 적용은 로그아웃/로그인(재부팅) 후이며, 실화면 확인은 아직 안 함.
- 상단바에서 클립보드·블루투스 아이콘 제거. "재부팅 필요" 순환 화살표 아이콘은 재부팅하면 사라짐.
