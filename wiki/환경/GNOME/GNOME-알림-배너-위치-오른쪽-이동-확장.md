# GNOME 알림 배너를 가운데 위에서 오른쪽 위로 옮기는 확장

GNOME Shell은 알림 배너 위치를 바꾸는 설정(gsettings)이 없어서, 셸 코드의 `bannerAlignment` 속성을 오른쪽으로 바꾸는 작은 확장 `notification-right@yunho.local`로 해결했다. 확장은 새로 켠 뒤 **재로그인**해야 적용되며, 테스트용 셸에서는 오른쪽 위 표시를 확인했지만 실제 세션 확인은 대기 중이다(미확정).

## 방법
- 알림 위치를 정하는 건 셸 내부의 `bannerAlignment`뿐이라 확장으로 이 값만 오른쪽으로 바꾼다. 내려오는 애니메이션과 마우스를 올렸을 때의 동작은 기본 그대로다.
- 현재 쓰는 **Wayland 세션은 확장을 셸 시작 시에만 읽으므로** 로그아웃 후 재로그인이 필요하다(같은 이유로 [[스와이프-직후-Alt+Tab-이전-데스크톱-목록]]의 `swipe-alttab-fix`도 같이 켜진다).

## 검증
- 실제 세션을 건드리지 않고 **격리된 테스트용 셸**을 따로 띄워 `notify-send`로 알림을 보내고 스크린샷으로 화면 오른쪽 위 끝에 뜨는 것을 확인했다.
- 재로그인 후 터미널에서 `notify-send 테스트`로 실화면 확인 예정.

## 2026-10-31 확장: 디자인·한 번 클릭·유리 효과
같은 확장에 위치 이동 외에 스타일과 클릭 동작 수정을 얹었다. 모두 격리 테스트 셸에서 `notify-send`+스크린샷으로 검증했다.

### 배치·디자인
- 배너를 **창 제목 표시줄 바로 아래**에 띄워 최대화 창의 X·최소화 버튼을 가리지 않게 했고, 배너 위쪽 빈 영역이 클릭을 가로채지 않게 했다.
- 크기 513×110 → **363×99**, 반투명 카드+얇은 테두리+그림자, X 버튼은 작은 원형. 라이트 모드는 밝은 카드로 따로 지정(두 스타일시트 모두 규칙 추가).
- 투명도 균형: 너무 투명하면 밝은 웹페이지 위에서 뒤 글씨가 비쳐 읽기 힘들고, 너무 어두운 회색은 어두운 창 위에서 카드가 구분이 안 됐다 → 카드 색 진하기를 55~62%에서 **35~42%**(hover 시에도 함께 낮춤)로 조정.
- **유리(블러) 효과**: 알림 뒤 화면을 복제해 블러를 깔고 그 위에 반투명 틴트+밝은 테두리를 얹는 `.frosted` 규칙. 블러가 없는 동안엔 회색 카드로 남겨 글자가 안 읽히는 일을 막는다.
  - 한계: GNOME 내장 블러는 둥근 모서리를 지원하지 않아 모서리 밖에 네모난 블러가 살짝 남는다(알록달록한 배경에서만 보임).
  - 시제품 함정: 복제 화면 크기가 0×0이면 유리 층이 안 그려진다 → 크기를 화면 크기로 명시. 크기·위치를 allocation 콜백 안에서 바꾸면 NaN이 나므로 피한다.
- **알림 목록(시계 팝업)**도 같은 유리 층+카드 스타일로 통일. 유리를 씌우면 달력 날짜마다 회색 원이 드러나서 투명하게 바꿨다(오늘 날짜의 주황 강조는 유지). 스타일 일괄 치환 시 `color:` 패턴이 `background-color:` 안에서도 걸려 라이트 `:active` 배경이 잘못 바뀐 사고가 있었다.
- 새 JS는 셸이 로그인 때만 읽으므로 유리·클릭 수정은 **재로그인 후 적용**된다.

### 두 번 눌러야 열리던 원인과 수정
- **원인**: 알림을 누르면 GNOME이 앱에 창을 올려도 된다는 활성화 토큰을 넘긴다. Claude 데스크톱·Discord 같은 앱은 이 토큰을 쓰지 않고 창을 올리려다 포커스 방지에 막히고, 그러면 GNOME이 "“…” 앱이 준비되었습니다" 알림을 하나 더 띄워 그걸 또 눌러야 열렸다.
- **수정**: 알림/액션을 클릭한 뒤 **3초 안에** 주의 요청(urgent)을 한 창을 바로 `Main.activateWindow()`로 올려 "준비됨" 배너를 생략한다. 확장을 끄면 원래 동작(준비됨 배너)으로 돌아오는 것도 확인했다.
- **리뷰 보완**(반영): 아무 창이나 올리면 3초 안에 터미널 벨·메신저가 끼어들어 엉뚱한 창으로 포커스가 갈 수 있으므로, ① 클릭한 알림의 앱과 같은 앱 창일 때만 올리고(앱을 모르면 올림) ② 앱이 스스로 올라와 포커스가 바뀌면 3초 대기를 즉시 해제한다. RTL 로케일용 margin 규칙도 추가.
- **미해결 관찰**: 알림을 눌렀는데 앱이 반응하지 않으면 가끔 쓰던 창의 키보드 포커스가 빠진다. 확장을 꺼도 5번 중 2번 발생(원래 GNOME 현상)이나 오른쪽 배치에서는 5번 중 5번으로 더 잦았다. 원인 미확인.

## 알림 목록 카드 겹침 수정 (2026-11-12)
- **증상**: 알림 목록(시계 팝업)에 같은 앱 알림이 쌓이면 카드들이 겹쳐 글씨가 뒤섞여 보임. 앱마다 알림이 하나뿐이면 재현되지 않아(스크린샷이 그런 경우) 격리 테스트 셸에서 같은 앱 알림 4개를 넣어서 재현했다.
- **원인**: GNOME은 같은 앱 알림을 하나로 접어 옛 카드들을 맨 위 카드 바로 뒤에 겹쳐 둔다(`NotificationMessageGroup`). 기본 테마는 카드가 불투명해 뒤 카드가 가려지지만, 위 "알림 목록 유리 스타일"로 투명하게 바꾸면서 뒤 카드 글씨가 비쳐 보였다.
- **수정**: 접힌 그룹의 뒤 카드를 **앞 카드 아래로 삐져나온 띠 영역만 그리도록 `set_clip`**. `_updateStackedMessagesFade` 래퍼 한 곳(추가·삭제·이동·펼침·접힘이 모두 지나는 길목)에 걸고, 카드/아이템의 `notify::allocation`에서 실제 배치 결과를 읽어 클립을 계산한다(레이아웃 계산을 복제하지 않음). 겹침이 없으면 클립을 제거해 펼친 그룹은 그대로 나온다. `disable()`에서 프로토타입 복원·클립 해제·시그널 해제.
- **검증**: 테스트 셸에서 접힘·펼치는 중·펼침·재접힘, 메뉴 연 채 새 알림 도착·삭제, 확장 껐다 켜기, 로그 오류 없음. 독립 리뷰는 막을 문제 없음.
- **리뷰 반영/판단**: 파괴된 뒤 콜백에서 `this._stackGroups` null 가드 추가, 주석 정정. "그룹 전체 재계산이 O(N²)" 지적은 앱당 알림이 최대 10개라 무시 가능해 보류. 테마 그림자가 큰 경우 클립에 잘릴 수 있다는 점은 미확인.
- **남은 흠**: 메뉴를 연 채 새 알림이 오면 새 카드가 커지며 들어오는 0.1초 동안 옛 카드가 잠깐 비어 보임.
- 재로그인 후 적용(실화면 확인 전).

## 같이 바꾼 데스크톱 설정 (2026-10-31)
- **독**: 드래그하다 화면 아래 끝만 스쳐도 독이 올라오던 것을 압력(밀어야 열림)을 요구하도록 바꿔 드래그 중 튀어나오지 않게 했다. 세기는 조절 가능.
- **한글 UI 글꼴**: 메뉴·창 글꼴을 `Pretendard 11`로 변경(이미 설치돼 있었음).
- **fontconfig 캐시 오염**: `Pretendard`를 찾는데 Font Awesome 파일이 매칭되는 이상이 있어 캐시를 재생성해 정상화했다.
- 팁: zsh에서는 변수가 단어로 분리되지 않아 반복 gsettings 조회가 실패하므로 bash로 돌린다.
