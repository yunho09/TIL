# OnlyOffice 한글 파일명 크래시 — fontconfig 캐시 손상

OnlyOffice가 pptx를 열자마자 꺼지는 증상의 원인은 파일이 아니라 **파일 이름에 한글이 있을 때** 탭 제목을 그리다 fontconfig에서 segfault가 나는 것이었다. 사용자 폰트 캐시(`~/.cache/fontconfig`)가 손상돼 있었고, 캐시를 새로 만들자 해결됐다.

## 증상
- pptx를 더블클릭하면 창이 뜨자마자 종료된다. 종료 코드는 **139(SIGSEGV)**.
- 파일 내용은 무관: 같은 파일을 영문 이름(`abc_def.pptx`)으로 바꾸면 열리고, 멀쩡한 파일도 `한글.pptx`로 바꾸면 죽는다.

## 진단 과정
- 영문/한글 이름으로 바꿔 가며 재현 → **한글 파일명이 트리거**임을 확인.
- 디버거 백트레이스: OnlyOffice가 **탭 제목에 한글 파일명을 그리는 지점**의 fontconfig 내부에서 segfault.
- 사용자 폰트 캐시가 손상된 것으로 판단(마지막 갱신 시점이 폰트 설치 무렵). 새 캐시를 임시로 만들어 보니 정상 → 캐시 손상 확정.

## 해결
```bash
mv ~/.cache/fontconfig ~/.cache/fontconfig.bak-YYYYMMDD   # 기존 캐시 백업
fc-cache -f                                               # 강제 재생성
```
- 원래 파일로 다시 실행해 창이 정상적으로 뜨는 것을 확인한 뒤 백업 폴더는 삭제.
- 이후 폰트를 설치/삭제하고 같은 증상이 재발하면 `fc-cache -f`만 한 번 돌리면 된다.

## 교훈
- "특정 이름의 파일만 앱이 죽는다"면 파일 내용보다 **이름(유니코드) 렌더링 경로 → 폰트 조회(fontconfig)** 를 의심해 볼 것. 영문/한글 이름 교차 테스트가 가장 빠른 분리 방법.
- 폰트 캐시는 삭제해도 안전한 파생 데이터라, 지우지 말고 옮겨 두었다가 정상 확인 후 지우면 된다.
- (Claude 보충) 손상 캐시가 어떤 경위로 생겼는지(폰트 설치 중 중단 등)는 확인되지 않았다.

## 재발 사례 — 실행 직후 크래시, 캐시가 다른 버전을 가리키는 심볼릭 링크 (2026-09-29)
파일명과 무관하게 **OnlyOffice를 켜자마자(1초 안에) 죽는** 형태로 재발했다. 원인은 같은 fontconfig 사용자 캐시였지만 손상 방식이 달랐다.
- `~/.cache/fontconfig` 안의 캐시 파일 123개가 시스템이 쓰는 형식(`cache-9`)이 아니라 **다른 버전 형식(`cache-12`)을 가리키는 심볼릭 링크**로 바뀌어 있었다(전날 11:48경). OnlyOffice가 첫 화면을 그리려고 이 캐시를 읽다가 `libfontconfig` 안에서 SIGSEGV. 누가 바꿨는지는 못 찾음(다른 프로그램/이전 작업이 캐시 버전을 억지로 맞추려 한 듯 — 추정).
- 진단: 크래시 덤프의 크래시 위치가 `libfontconfig`인지 확인, 캐시 디렉터리에서 `ls -l`로 심볼릭 링크 여부 확인.
- 해결: 그 링크들만 지우고 `fc-cache -f`로 재생성 → 12초 넘게 정상 유지 확인. 캐시는 파생 데이터라 지워도 손실 없음.
- 재현하려고 OnlyOffice를 강제로 띄우면 "timeout 예상치 않게 끝남" 류 알림이 남을 수 있는데 무해하다(계속 누르면 됨).
- 교훈: 앱이 **폰트/글자 렌더링 시점에** 죽고 백트레이스가 `libfontconfig`면 앱 설정보다 `~/.cache/fontconfig`부터 의심한다. 한글 파일명 조건이 없어도 발생할 수 있다.

## x2t 변환기 크래시 — 템플릿 미리보기 (2026-09-30)
- 증상: "예상치 않게 끝났습니다" 창이 떴는데 죽은 건 편집기 본체가 아니라 변환 보조 프로그램 **`x2t`**. 시작 화면용 내장 템플릿("Gift Certificate.dotx")의 **미리보기 썸네일을 백그라운드로 만드는 중**이라 사용자 문서·데이터와 무관.
- 원인: 앱 자체 라이브러리 `libdoctrenderer.so`의 NULL 포인터 접근(앱 내부 버그). 폰트 코드에서 죽은 게 아니므로 위 fontconfig 건과 별개. 같은 템플릿을 수동 변환하면 정상이라 재현되지 않는 일회성이었고, 버전 9.4.0(최신)이라 업데이트로 해결할 수도 없음.
- 대응: **계속**을 누르면 됨. 알림 창은 `~/.apport-ignore.xml`에 `x2t`를 등록해 숨길 수 있다(Ubuntu apport). 남은 `/var/crash/*x2t*.crash`는 삭제.
- 참고: 템플릿 미리보기 캐시(`templates_cache/200`)가 비어 있으면 시작 화면을 열 때마다 썸네일을 새로 만든다. 같은 크래시가 잦으면 캐시를 먼저 채우는 식으로 대응.
- 미적용 대안: `/opt/onlyoffice/desktopeditors/converter/x2t`를 재시도 래퍼(최대 3회)로 교체. `dpkg-divert --rename --divert …/x2t.real --add …/x2t`로 원본을 옮기면 업데이트에도 덮어써지지 않지만 pkexec 권한이 필요해 자동 모드에서 막혔고 실행되지 않음. 되돌리기는 래퍼 삭제 후 `dpkg-divert --rename --remove …/x2t`.
