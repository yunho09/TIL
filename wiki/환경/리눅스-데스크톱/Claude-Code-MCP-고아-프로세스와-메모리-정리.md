# Claude Code 세션이 남긴 MCP 고아 프로세스와 메모리 정리

램·스왑이 바닥났을 때 Claude Code 쪽에서 볼 곳: 오래 열어 둔 세션, 죽은 세션이 남긴 MCP 서버(고아 프로세스), 세션마다 따라 붙는 플러그인 MCP. 이 PC에서는 세션 종료 + 고아 정리 + Figma 종료로 쓸 수 있는 램이 3.0G→6.8G, 남은 스왑이 36MB→3.0G로 회복됐다. 앱별 점유 측정법은 [[리눅스-메모리-점유-앱별-진단-PSS]] 참고.

## 정리 순서와 효과

- **오래된 세션 종료**: 세션마다 MCP 서버가 딸려 있어 세션을 끄면 같이 내려간다. 효과는 예상보다 작았다(~0.7G) — 오래된 세션은 이미 반쯤 스왑에 밀려나 있어서 RAM 회수량이 적다.
- **고아 MCP 프로세스 정리**: 죽은 세션이 남긴 `gk mcp`(GitKraken) 21개 + figma-mcp-bridge 4개, 약 0.5~0.9G. 세션이 정상 종료되지 않으면 자식 MCP가 PID 1 밑에 남는다.
- 그다음은 사용자가 띄운 앱(Chrome, IDE, DB 클라이언트, Figma)이라 무엇을 닫을지 사용자가 골라야 한다.

## 함정: zsh에서 PID 목록 변수가 안 쪼개짐

`pids=$(pgrep ...)`로 담은 변수를 `kill $pids`에 넘기면 **zsh는 변수를 단어로 분리하지 않아** PID 전체가 한 인자로 들어가 아무것도 안 죽는다(에러도 눈에 안 띔). bash로 실행하거나 `${=pids}` / `pgrep ... | xargs kill`을 쓴다. 죽였는지는 `pgrep`로 다시 세어 확인.

## GitKraken MCP 플러그인이 계속 생기는 이유

- 직접 설치한 게 아니라 **claude.ai 계정에서 동기화돼 자동으로 붙는 플러그인**이다.
- GitKraken 계정을 거쳐 GitHub·GitLab·Jira의 커밋·브랜치·PR·이슈를 다루는 도구 묶음인데, `gh`·`git`으로 같은 일을 다 할 수 있어 꺼도 잃는 게 없다.
- 세션 하나당 프로세스 3개(npx → node → gk)를 띄워 세션이 많으면 합계 1.7G까지 갔다. GitKraken 데스크톱 앱·`gitkraken-hooks`와는 별개.
- 계정 동기화 플러그인이라 설정 파일을 직접 고치기보다 Claude Code에서 `/plugin` → **gitkraken** → Disable. 새로 여는 세션부터 적용되고 떠 있는 세션은 닫을 때 사라진다.

## Chrome 메모리 절약 모드 (chrome://settings/performance)

- 탭이 **꺼지는 게 아니라** 안 보는 탭의 페이지만 메모리에서 내려가고, 다시 누르면 새로고침된다(1~2초, 스크롤 위치는 대부분 복원). 보고 있는 탭·소리/영상 재생·다운로드·화면 공유 중인 탭은 건드리지 않는다.
- 새로고침이라 **쓰다 만 글은 날아갈 수 있다** → "항상 활성 상태로 유지할 사이트"에 노션, `localhost` 개발 서버 등을 넣어 둔다.
- **켜자마자 줄지 않는다**: 한동안 안 본 탭부터 하나씩 잠재워서 켠 직후엔 Chrome 8.9G→8.1G(0.8G)만 줄었고, 몇십 분에 걸쳐 더 줄어든다.

## 다시 늘어나는 것: 워크트리마다 vite 개발 서버

git 워크트리를 여러 개 두고 세션마다 작업하면 워크트리별로 vite 개발 서버가 하나씩 뜬다(각 ~650M, 3개면 ~2G). 다른 세션이 쓰는 중일 수 있으니 임의로 죽이지 말고, 작업이 끝나면 끄도록 한다.
