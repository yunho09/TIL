# 뚜껑 열고 잠금 풀면 화면이 검게 꺼지는 문제 (lid-grace × gsd-power 이중 Lock)

뚜껑을 덮었다 열고 잠금을 풀면 화면이 잠깐 보이다가 검게 꺼지고, 키를 다시 눌러야 켜지는 증상의 원인과 수정. 원인은 직접 만든 `lid-grace` 서비스와 GNOME 전원 관리(`gsd-power`)가 **동시에 Lock을 요청**해서 gsd-power가 25초간 멈추는 것이었다.

## 증상
- 뚜껑을 닫았다 열고 잠금 해제 → 화면이 보였다가 몇 초 뒤 검은 화면 → 키 입력 시 복귀.

## 원인 (D-Bus 모니터로 확인)
- 뚜껑을 닫으면 `lid-grace`가 화면을 **바로 잠근다**.
- 같은 순간 `gsd-power`도 잠그라고 요청한다. Claude Desktop 등이 **절전 방지(inhibit)** 를 걸어 둔 상태에서 이렇게 동작한다 (Claude 보충: 정확한 트리거 경로는 세션에서 단정하지 않음).
- 이미 잠긴 뒤 들어온 두 번째 Lock 요청에는 GNOME이 **응답을 주지 않고**, gsd-power는 응답을 기다리며 **25초 타임아웃** 동안 멈춘다.
- 그 사이 절전에 들어갔다가 깨어나면, 남은 시간이 지난 뒤 gsd-power가 밀려 있던 **"화면 끄기"** 를 실행 → 잠금을 푼 뒤에 화면이 꺼짐.
- 실측: gsd-power 정지 시간 정확히 25.00초, 화면 끄기 명령은 뚜껑 연 지 9초 뒤·잠금 해제 6초 뒤.

## 수정
- `~/.local/bin/lid-grace`를 변경: 뚜껑 닫으면 **화면만 바로 끄고, 잠금은 1.5초 뒤에** 수행. 그 시점에 이미 잠겨 있으면 **다시 잠그지 않아** gsd-power가 멈추지 않는다.
- 원본 백업: `~/.local/bin/lid-grace.bak-20261111`.
- 부작용: 닫고 1.5초 안에 다시 열면 잠금화면 없이 바로 바탕화면이 나온다.

## 검증 상태
- 수정 직후 사용자에게 재현 테스트(뚜껑 15초 넘게 닫기 → 열고 잠금 해제 후 30초간 입력 없이 관찰)를 요청한 단계였고, **결과는 세션에 기록되지 않음 (미확인)**.

## 교훈
- 이미 잠긴 세션에 중복 Lock을 보내면 호출자(gsd-power)가 응답 없이 블록될 수 있다 → 잠금 요청은 **현재 잠금 상태를 확인하고** 한 번만 보낸다.
- 원인 추적은 추측 대신 `dbus-monitor`로 누가 Lock/화면 끄기를 부르는지 한 번에 잡는 방식이 효과적이었다.
