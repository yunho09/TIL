# 카카오톡(Wine) — 스플래시 멈춤·한글 조합 네모·시작 직후 크래시

리눅스에서 Wine으로 돌리는 카카오톡이 자동 업데이트(26.8.2) 뒤 주황 스플래시에서 멈춘 문제는 Direct3D 렌더러를 Vulkan으로 바꿔 해결했다. 입력 중 한글이 네모로 보이던 건 카카오톡 언어를 한국어로 바꿔 해결했고, 시작 직후 간헐적 크래시는 원인 미확정이라 실행기에서 자동 재실행으로 우회했다.

## 1. 업데이트 후 스플래시에서 멈춤
- **증상**: 업데이트 직후 주황 스플래시 화면에서 수십 시간 멈춤(CPU 0.2%). 로그인·서버 연결은 정상이고 **화면만 안 그려짐**.
- **원인**: 새 버전이 창을 **Direct3D**로 그리는데 Wine 기본 경로(OpenGL)에선 안 그려짐.
- **해결**: 카카오톡 전용 Wine 설정에서 **Direct3D 렌더러를 Vulkan으로 변경**. 설정이 프리픽스에 저장돼 독/앱 목록 실행에도 유지.
- Direct3D를 아예 끄면 실행 자체가 안 됨(시도 후 원복).
- 다음 업데이트 뒤 또 멈추면 남은 수단: **DXVK** 설치, Wine 버전 교체.

## 2. 한글 조합 중 글자가 네모
- **증상**: 다 친 글자는 정상, **조합 중인 글자만 네모**.
- **원인**: 조합 중 글자는 카카오톡이 아니라 **Wine 입력기 창**이 그린다. 카카오톡 언어가 영어면 입력칸 글꼴이 **Arial**인데, 설치된 Arial(msttcorefonts)엔 **한글 글리프가 없음**. 완성 글자는 카카오톡이 한글 글꼴로 다시 그려 정상으로 보임.
- **해결**: 카카오톡 `pref.ini`의 언어를 `en`→`ko`로 변경(메뉴도 한국어화).
- **실패한 시도**: Wine 글꼴 대체(Arial→한글 글꼴)는 **진짜 Arial이 설치돼 있으면 Wine이 대체하지 않아** 무효.
- 진단법: Wine 추적 로그로 조합창이 쓰는 글꼴 확인(대화 내용은 출력하지 않도록 글꼴 정보만 필터).

## 3. 시작 3초 내 간헐적 크래시 (5~10회 중 1회)
- 처리되지 않은 예외(c0000409)로 시작 직후 강제 종료. 새로 만든 작업 하나에서 발생.
- **정확한 예외 원인은 미확인**: `KakaoTalk.exe`가 **Themida**로 보호돼 디스크에선 못 읽고, 실행 중 메모리 디버깅은 권한에서 막힘.
- **우회**: 실행기 `~/.local/bin/kakaotalk-wine`가 켠 지 1분 안에 프로세스가 사라지면 최대 5회 자동 재실행.
  - 종료 코드만 보지 않고 **프로세스 생존 여부**도 감시: 카카오톡이 스스로 새 프로세스를 띄우고 원래 프로세스를 정상 종료하는 경우가 있기 때문.
  - 단점: 켠 뒤 1분 안에 직접 종료하면 다시 뜸.
  - 크래시를 흉내(20초 후 강제 종료)해 약 3초 만에 재실행되는 것 확인.

## Wine 작업 시 함정
- `WINEPREFIX` 환경변수를 빠뜨리고 wine 명령을 쓰면 기본 프리픽스 `~/.wine`(약 920MB)이 새로 생긴다. 카카오톡 전용 프리픽스를 지정할 것.
