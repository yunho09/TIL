# 디스크 정리와 부팅 서비스 최적화 점검 (2026-10-15)

루트(/) 사용률 88%였던 PC에서 로그·캐시·안 쓰는 서비스를 정리해 여유 공간을 **13G → 18G**(사용률 83%)로 늘렸다. 무엇을 지웠고, 무엇을 일부러 남겼는지, 그리고 "부팅 30초 단축"이 과장이었던 이유를 기록한다.

## 적용한 것

- **systemd 저널**: 2.9G → 480M, 상한을 500M로 제한(journald 용량 제한 설정).
- **캐시**: npm·Homebrew 캐시, 옛 JetBrains 버전(2026.1) 설정/데이터 삭제.
- **옛 커널 설정 찌꺼기**: `rc` 상태(제거됐지만 설정 파일 남은) 패키지 22개 중 21개 purge. `grub-pc`는 `/etc/default/grub`을 건드릴 수 있어 **일부러 남김**.
- **notion-desktop snap** 삭제(크롬 노션 웹앱은 그대로). 단, 독(dock)의 노션 아이콘이 삭제한 snap의 `.desktop`을 가리키고 있을 수 있어 확인이 필요하다.
- **Docker 엔진**: 부팅 시 자동 시작을 끄고 **소켓 활성화**(docker 명령을 쓸 때 켜짐)로 전환 — 명령 실행으로 켜지는 것까지 확인.
- **ModemManager** 비활성화(모뎀 없는 PC).

## 일부러 남긴 것과 이유

- Docker Desktop VM 디스크 4.7G — 사용자 결정으로 유지.
- `~/.npm/_npx` 1.1G — 실행 중인 MCP 서버들이 npx 캐시에 들어 있어 지우면 안 됨.
- yarn berry 캐시 1.1G — 지우면 **PnP 방식 프로젝트가 깨질 수 있음**.
- CUPS 두 벌 — 등록된 프린터가 없어 급하지 않음.

## 정정: "네트워크 대기 때문에 부팅이 30초 느리다"는 과장

- `systemd-analyze`상 로그인 화면은 **부팅 약 3초 만에** 뜬다. 네트워크 대기(`NetworkManager-wait-online` 류)가 로그인을 늦추지 않았고, 늦춰지던 건 로그인 **이후 백그라운드에서 끝나는 부분**뿐이다.
- `cups-browsed`(프린터 자동 검색)도 같은 대기에 걸려 있어서 서비스 하나를 꺼도 체감은 크지 않을 수 있다. 실제 효과는 불필요 서비스 두 개(Docker 자동 시작, ModemManager)를 끈 정도. 재부팅 후 `systemd-analyze` / `systemd-analyze critical-chain`으로 확인해야 한다(미확인).
- 교훈: `blame` 순위나 "대기 N초"를 그대로 부팅 단축 효과로 말하지 말고, **크리티컬 체인에 실제로 걸려 있는지**부터 본다.

## 절전 복귀 직후 네트워크 미연결로 자동 동기화 실패

- DevLog 자동 동기화가 절전 복귀 직후 와이파이가 붙기 전에 실행돼 실패하고, 5분 뒤 재시도로 겨우 성공하고 있었다.
- 수정: 실행 전에 **네트워크 연결을 최대 60초 기다린 뒤** 실행(수동 1회 실행으로 성공 확인).
- 일반화: 절전 복귀 시점에 트리거되는 작업은 네트워크가 아직 없다 — 재시도 간격에 맡기지 말고 연결 대기를 넣는다. 복귀 지연 자체는 [[절전-복귀-지연-원인과-zram-도입]] 참고.

## 점검 결과 문제 없던 것

- 덮개를 열 때 화면이 켜지는 건 대부분 1초 안쪽.
- 덮은 뒤 잠들기까지 10초는 의도한 설정(금방 다시 열 경우 대비).
