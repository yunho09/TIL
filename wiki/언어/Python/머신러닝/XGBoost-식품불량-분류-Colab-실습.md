# XGBoost 식품불량 분류 Colab 실습

강의자료(머신러닝·인공지능) XGBoost 실습 코드 형식에 맞춰 식품 제조 공장 불량 분석(수행평가) 1~7번을 만들고 로컬과 Colab 양쪽에서 돌린 기록. 같은 코드가 두 환경에서 같은 결과(정확도 0.9960)를 냈고, Colab에서 기존 실습 노트북에 셀을 붙일 때 걸린 함정을 정리한다.

## 데이터와 결과 (수행평가 1~7번)
- 데이터 10,000행 × 8열: 입력 7개(temp, humidity, cook_time, pressure, moisture, vibration, speed) + `label`. PPT에 적힌 GitHub(heartcom/Linux-Program)에서 Colab으로 바로 받아오게 했고, 직접 업로드(`files.upload()`) 코드는 주석으로 남김.
- Train 8,000 / Test 2,000, `stratify`로 나눠 불량 비율이 둘 다 0.403.
- 정확도 0.9960, 정밀도 0.9963, 재현율 0.9938, F1 0.9950. Confusion Matrix: TN 1192, FP 3, FN 5, TP 800.
- 변수 중요도는 weight / gain / cover 세 가지로 비교. **gain** 기준으로는 humidity가 가장 큼.
- 모델 저장: `xgb_model.pkl` + `model_meta.json`(입력 7개 min/max). 실시간 추론 셀은 이 둘을 다시 불러와 1초마다 min~max 범위의 랜덤 입력 7개로 정상/불량을 판정하고, 최근 10건을 표로 보여주며 불량은 빨강으로 칠함(중지 전까지 계속 실행).

## 결정 경계와 과적합 확인
- 온도·습도 두 변수만으로 학습해 결정 경계를 그리면 온도 22~28℃, 습도 40~80% 구간이 빨간 박스로 갈라짐(강의자료 29번 슬라이드의 판정 기준).
- 과적합 확인은 Train/Test 정확도 차이로 판단. 이번엔 0.9999 vs 1.0000, 차이 0.0001 → 과적합 없음. 슬라이드의 0.9972 / 0.9975와 숫자가 다른 이유는 원본 `TH_quality_10000.csv`가 없어 판정 기준대로 데이터를 다시 만들었기 때문(경계가 더 깔끔). 결론은 같음.
- 원본 CSV는 GitHub에도 로컬에도 없었고, Colab 런타임에 올린 파일은 런타임이 바뀌면 사라진다.

## Colab 함정
- **"모두 실행" 금지**: 기존 실습 셀의 `files.upload()`가 파일 선택을 기다리며 멈춘다. 새 셀은 위에서부터 하나씩 실행.
- **시간이 UTC로 찍힘**: Colab 서버는 UTC라 실시간 추론 표의 시각이 한국 시간과 어긋남 → 한국 시간(KST)으로 변환해 출력.
- **한글 그래프**: 한글 폰트를 설정해야 Confusion Matrix·중요도 그래프 글자가 안 깨짐.
- 무한 루프 셀(실시간 추론)을 켜 두면 Colab 사용 시간이 닳으므로 캡처 후 ■로 중지. 다른 셀을 실행하려면 어차피 멈춰야 함.
- 같은 노트북에서 결정 경계·과적합 셀은 변수 이름을 `df_th`, `xgb_th`, `Xth_train`처럼 따로 써서 수행평가 1~7번 결과를 덮어쓰지 않게 함. 과적합 확인 셀은 모델을 학습하는 결정 경계 셀 아래에 있으므로 다시 돌릴 땐 결정 경계 셀부터.
- 브라우저 자동화로 Colab을 다룰 때 내장 브라우저는 구글 로그인에서 막혔고(비밀번호는 입력 불가), 이미 로그인된 사용자 Chrome(Claude in Chrome)으로는 진행됐다. 대안으로 `.ipynb`를 만들어 **파일 → 노트북 업로드**로 올리는 방법도 있음.

## 발표 대비 용어 (Claude 보충)
- `scale_pos_weight`: 클래스 불균형 보정 가중치, `stratify`: 분할 시 클래스 비율 유지, `gain`: 해당 변수로 분할할 때의 평균 손실 감소량.
