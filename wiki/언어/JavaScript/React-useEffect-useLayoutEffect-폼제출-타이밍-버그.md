# React `useEffect` vs `useLayoutEffect` — 폼 상태 최신값 반영 타이밍 버그

첨부파일을 제거한 직후 바로 저장하면 **이전 첨부 목록이 그대로 전송되는 버그**가 있었다. 원인은 파생 상태를 갱신하는 훅이 `useEffect`였기 때문이다.

## 원인

`useEffect`는 브라우저가 화면을 그린 **뒤(비동기)**에 실행된다. 사용자가 "제거" 조작 직후 아주 빠르게 "저장"을 누르면, 파생 상태를 갱신하는 `useEffect`가 아직 실행되기 전에 제출 핸들러가 먼저 돌아 옛 상태를 읽어가는 레이스 컨디션이 생긴다.

`useLayoutEffect`는 페인트 **전(동기)**에 실행되므로, 커밋 직후 상태 갱신이 항상 다음 이벤트 핸들러 실행 전에 끝나 있다는 보장이 생긴다.

## 해결

파생 상태 동기화 훅을 `useEffect`에서 `useLayoutEffect`로 교체해, 제출 시점에 항상 최신 상태가 반영되도록 고쳤다.

## 일반화

사용자 입력 직후 빠르게 제출이 가능한 폼(제거 → 즉시 저장 같은 패턴)에서, 파생 상태를 동기화하는 데 `useEffect`를 쓰면 레이스 컨디션이 생길 수 있다. 제출 로직이 "가장 최근 렌더 결과"에 항상 의존해야 하는 경우 `useLayoutEffect`가 더 안전한 선택이 될 수 있다(단, `useLayoutEffect`는 페인트를 막으므로 무거운 연산에는 부적합).
