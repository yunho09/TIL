# 쿠버네티스 워크로드 리소스 정리와 공식문서 대조 정정

Pod·Deployment·ReplicaSet·StatefulSet·DaemonSet·Service를 Notion k8s 페이지 하위에 정리하면서, 한국어 공식 문서만으로 채운 부분을 **영문 원본 문서와 대조해 고친 내용**을 남긴다. 한국어 문서는 "정보가 오래되었을 수 있다"는 안내가 붙어 있어 기본값·기능 게이트는 영문 기준으로 확인해야 한다.

## 조사 방법의 교훈
- **Service는 워크로드 문서에 없다.** "서비스, 로드밸런싱, 네트워킹" 쪽 문서를 따로 봐야 한다.
- `WebFetch`는 약 100,000자에서 잘리고 대부분이 내비게이션이라 문서 뒷부분이 안 읽힌다. 대신 GitHub `kubernetes/website` main 브랜치의 **raw 마크다운을 curl로 받아 grep**하면 정확하다 (`content/en/docs/...`). 기능 게이트 단계(Alpha/Beta/Stable)는 같은 레포의 feature-gates md 파일에서 확인했다.
- 일반 지식으로 채운 부분은 따로 표시하고 대조 전에는 사실로 단정하지 않는다.

## 대조로 정정된 내용
**StatefulSet**
- (틀림) "파드 관리 정책은 스케일링에만 적용"이라 썼으나, `Parallel` 정책에서 `maxUnavailable`이 1보다 크면 **롤링 업데이트도 그 수만큼 동시에 진행**된다(문서 용어 "bursting"). 이때 파드가 순서 없이 Ready가 될 수 있다.
- 업데이트 전략은 3가지: `RollingUpdate`, `OnDelete`, 그리고 `Recreate`(v1.37 **Alpha**, `StatefulSetRecreateStrategy` 게이트 필요, 기본 꺼짐).
- `maxUnavailable`: 기본 1, **0 불가**, 비율은 올림. `MaxUnavailableStatefulSet` 게이트는 v1.37부터 Beta+기본 켜짐, v1.35.4~v1.36은 Beta지만 기본 꺼짐.
- PVC 보존 정책(retention policy)은 v1.32부터 Stable.

**ReplicaSet / Deployment (autoscale)**
- ReplicaSet 문서 예시 `kubectl autoscale rs frontend --max=10 --min=3 --cpu=50%`, Deployment 문서는 `--cpu-percent=80%` — **두 문서의 표기가 서로 다르다.** 각 문서를 그대로 따랐다.
- HPA 예시 YAML의 `scaleTargetRef`에는 `apiVersion: apps/v1`이 필요하다.

## 문서와 일치한 핵심 사실
- **Deployment**: `maxSurge` 25% 올림, `maxUnavailable` 25% 내림, 둘 다 0 불가(replicas 10이면 최대 13·최소 8). `progressDeadlineSeconds` 600, `revisionHistoryLimit` 10(0이면 롤백 불가), `replicas` 기본 1, 셀렉터 변경 불가, **파드 템플릿이 바뀔 때만 롤아웃**.
- **Pod**: phase 5가지, `restartPolicy` 값과 기본값.
- **Service**: NodePort 범위 30000–32767, ExternalName은 CNAME 반환, 헤드리스 서비스, 서비스 환경변수는 서비스가 파드보다 먼저 있어야 주입, 포트가 여러 개면 이름 필수, `targetPort` 기본값, Endpoints API는 v1.33에서 deprecated.
- **DaemonSet**: 자동으로 붙는 톨러레이션 7개, 업데이트 기본값 `maxUnavailable` 1·`maxSurge` 0, 데몬 파드와 통신하는 방법 4가지.
- **ReplicaSet**: `--cascade=orphan` 동작, 레이블을 바꿔 파드를 격리하면 빠진 수만큼 자동 보충, 축소 시 삭제 대상 선택 순서 4단계, ReplicationController와의 차이(집합 기반 셀렉터 미지원).
- **StatefulSet**: PVC 이름 형식, `OrderedReady` 순서 규칙, `partition` 동작, 강제 롤백 절차, ordinals 시작 지정(v1.31 Stable).
